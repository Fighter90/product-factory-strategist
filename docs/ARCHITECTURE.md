# Архитектура агента

## 1. Принцип

LLM-среда (Claude Code / Cursor / Codex) — «мозг» и исполнитель: она выбирает следующее действие, ищет, читает,
пишет. Репозиторий даёт ей **правила** (AGENTS.md), **процедуры** (skills), **помощников** (subagents),
**знания** (knowledge/), **инструменты с гарантиями** (pfs CLI/MCP) и **события** (hooks). Всё, что должно быть
надёжным и проверяемым (учёт источников, типы утверждений, проверки, состояние, стоимость), вынесено из «памяти
модели» в детерминированный код и файлы.

```
                 ┌──────────────────── LLM-среда (Claude Code / Cursor / Codex) ─────────────────────┐
 Руководитель ⇄  │ AGENTS.md (правила, процесс) → skills (процедуры шагов) → subagents (роли, модели) │
   продукта      └───────┬───────────────────────────┬───────────────────────────┬───────────────────┘
                         │ CLI / MCP                 │ hooks (события)           │ WebSearch/WebFetch
                         ▼                           ▼                           ▼
            tools/pfs: state · sources · claims · check · impact · decisions · cost · kb · data · route · models · calc · export · docx
                         │
     ┌───────────────────┼─────────────────────────────┬─────────────────────────────┐
     ▼                   ▼                             ▼                             ▼
 knowledge/          config/                   projects/<slug>/                 docs/
 (методы, шаблоны,   (models, pricing,         sources/ claims.jsonl state.json  (описание)
  рубрика, INDEX)     quality_gate)            decisions.jsonl log.jsonl outputs/
```

## 2. Рабочий процесс

| Шаг | Вход | Действие | Выход | Ворота | Модель (config/models.json) |
|---|---|---|---|---|---|
| route | запрос | классификация по 6 сценариям | сценарий, карты, план моделей | уверенность ≥ medium или уточнение | fast (детерминированный код + субагент router при low) |
| intake | запрос | ≤3 вопроса, бриф, допущения | 00_brief.md | человек | deep |
| sources/research | бриф | план от вопросов, меняющих решение; поиск; выписка C### | 01_research_plan.md, sources/, claims.jsonl, analysis/ | каждый вопрос отвечен или назван пробел | balanced (researcher), fast (extract) |
| discovery | реестр | персоны, JTBD, альтернативы пользователя (карты discovery) | 02, раздел «Сегменты» | сегмент зафиксирован | balanced |

## 3. Работа с контекстом и знаниями

- **Раздельное хранение.** Инструкции (AGENTS.md, skills, agents) ≠ методические знания (knowledge/) ≠ материалы
  проекта (projects/*/sources) ≠ состояние (state.json, *.jsonl) ≠ результаты (outputs/).
- **Не грузить всё.** Агент ищет по базе (`pfs kb search` — BM25 по разделам карт с русским стеммингом) и читает 1–3
  карты; `route` сразу даёт список карт под сценарий. INDEX.md — навигация по шагам и курсам; связи карт `related`
  проверяются на битые ссылки.
- **Длинные источники.** Тексты лежат в sources/S###.md; в контекст попадают выписки (claims) и короткие цитаты.
  Объёмное чтение — субагенту researcher, его отчёт — ID утверждений.
- **Память между сеансами** = файлы проекта. Хук SessionStart подаёт агенту `status` + `decision due`.
  Прежний ответ агента не становится фактом: он хранится как `inference` с основаниями; при отзыве основания
  `pfs check` помечает все места, где на него ссылаются.
- **Исправление и отзыв.** `claim supersede` / `retract` сохраняют историю; `impact` — граф «источник → утверждение →
  вывод → строка документа → решение».
- **Вопросные блоки и карты шага.** `config/question_blocks.json` — библиотека блоков вопросов по шагам (`pfs questions <шаг|id>`);
  на каждом шаге агент обязан задать 1–3 вопроса из блока или отметить пропуск в журнале. Обязательные карты шага —
  `kb.STAGE_CARDS`, `pfs step` печатает их список.

## 4. Инструменты (pfs)

| Модуль | Назначение |
|---|---|
| core, project | пути, атомарная запись, шаги, вопросы человеку, сводка состояния |
| extract, sources | загрузка сайтов/PDF/DOCX/XLSX/CSV, защита от SSRF, дедупликация, детектор внедрённых инструкций, разрешённые домены |
| claims | реестр утверждений с правилами (факт ⇒ источник; синтетика ⇒ только гипотеза; вывод ⇒ основания), сила A–D |
| check | quality gate по config/quality_gate.json |
| impact | влияние изменений |
| decisions | решения, обязательства, пересмотр, устаревшие основания |
| cost | токены из транскриптов Claude Code (с дедупликацией по message.id, вкл. субагентов) × pricing.json |
| kb | поиск BM25, INDEX.md, проверка связей |
| data | профиль таблицы (типы, пропуски, дубли, единицы, пропущенные периоды), когорты, воронка по событиям/колонкам (`funnel`), описательная статистика с ДИ 95% (`stats`) |
| participate | гайды интервью и ИИ-респонденты (`interview guide/save`), медиа-источники с описанием «только видимое» (`media add`), UX-каркас из 10 эвристик (`ux scaffold`) |
| calc, xlsx | Excel-приложения к six-pager (юнит-экономика, модель роста, когорты, размер рынка): лист «Ввод» + формулы + кэш значений, параметры из `calcs.json`, без зависимостей |
| route, models | сценарий запроса; модель под задачу, эскалация, профили, синхронизация субагентов |
| export | REPORT.md и six-pager (FAQ-1…FAQ-6) с Excel-приложениями; HTML-дека 16:9 из six-pager (`--deck`) |
| docx | Markdown → DOCX конвертер на stdlib (pfs docx) |
| question_blocks | библиотека вопросных блоков шагов (config/question_blocks.json) |
| mcp_server | те же функции по MCP (stdio JSON-RPC, без зависимостей) |

## 5. Хуки

| Событие | Скрипт | Что делает |
|---|---|---|
| SessionStart | session_start.py | состояние проекта и «что решать сейчас» — продолжение в новом чате |
| PreToolUse(WebFetch) | pre_web.py | блокирует домены вне allowed_sources проекта |
| PostToolUse | post_tool.py | журнал действий; поиск фраз-инструкций в ответах WebFetch/WebSearch; автопроверка документа после записи |
| Stop | stop.py | стоимость сессии (идемпотентно) и сообщение пользователю |

Хуки никогда не роняют сессию: исключения пишутся в `.claude/hooks/hook_errors.log`.

## 6. Устойчивость к сбоям

- Атомарная запись всех файлов состояния (tmp + rename).
- Идемпотентность: повторное добавление источника (по URL или SHA-256), утверждения (по тексту), отметки шага и учёта
  стоимости сессии не создаёт дублей — после сбоя можно безопасно повторить команду.
- Сетевые ошибки и недоступные сайты — явная ошибка с подсказкой (`--text-file`), а не тихий пропуск.
- Журнал log.jsonl показывает, что уже сделано, — агент не повторяет выполненные шаги.

## 7. Переносимость

Всё состояние — в обычных файлах (JSON/JSONL/Markdown) внутри репозитория. Проект переносится копированием папки
или `git clone` и продолжается в любой среде, которая читает AGENTS.md: Claude Code (CLAUDE.md, skills, agents, hooks),
Cursor (.cursor/rules + MCP), Codex/OpenCode/Copilot (AGENTS.md). Модели меняются профилем `pfs models use <профиль>`.
