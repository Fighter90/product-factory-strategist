# Руководство пользователя — Стратег Фабрики продуктов

> Для руководителя продукта, который использует агента для продуктовых решений.
> Сопровождающая документация: [SUPPORT_RU.md](SUPPORT_RU.md). Для администратора: [ADMIN_GUIDE_RU.md](ADMIN_GUIDE_RU.md).

## 1. Что такое агент

Стратег Фабрики продуктов — CLI-агент для руководителя цифрового продукта.
Вы формулируете продуктовый вопрос («Почему падает конверсия?», «Выводить ли тарифную сетку?»),
агент проводит вас по 12-шаговому процессу: от уточнения задачи до готового документа
для комитета (six-pager) с доказательной базой.

Ключевые свойства:

- **Проверяемость.** Каждое существенное утверждение имеет источник ([S###]) и тег утверждения ([C###]);
  числовые кросс-чеки ловят расхождения с источником.
- **12 шагов.** Фиксированный процесс: intake → sources → research → discovery → situation →
  options → choice → strategy → validation → review → decision → monitoring.
- **Паузы только на решениях.** Агент останавливается на intake, choice, decision и finish;
  между ними идёт без лишних вопросов.
- **Два языка.** RU по умолчанию; EN-проекты создаются с `--lang en`.
- **Без отправки данных наружу.** Реестры и документы — в папке проекта; реестры правятся только через `pfs`.

## 2. Установка (5 минут)

```bash
git clone https://github.com/Fighter90/product-factory-strategist-agent.git
cd product-factory-strategist-agent
bash scripts/install.sh
```

Скрипт клонирует три репозитория (агент, база знаний `knowledge/`, сайт), ставит `pfs`
глобально и запускает самопроверку (`pfs doctor`). Подробнее: [INSTALL.md](INSTALL.md).

Проверка окружения:

```bash
pfs doctor   # PATH, python, pdftotext/pypdf, TLS-цепочка, число карт в базе, активный проект
```

## 3. Первый запуск

```bash
pfs new "Название проекта" "Ваш продуктовый запрос дословно"
```

Пример: `pfs new "Контрагент: вывод тарифной сетки" "Пробная версия не конвертируется в оплату (2%). Стоит ли вводить тарифную сетку?"`

Агент создаст проект в `projects/<slug>/`, спросит уточнения (шаг intake) и дальше поведёт
по шагам. Ориентироваться помогает:

```bash
pfs status   # где остановились, что дальше
pfs next     # «что решать сейчас»: шаг, обязательства, пересмотры
```

## 4. 12 шагов процесса — что делать на каждом

### Шаг 1 · intake — уточнение запроса
Ответьте на вопросы агента: решение, цель, получатель, ограничения, данные.
Результат: `00_brief.md`.

### Шаг 2 · sources — сбор материалов
```bash
pfs source add <файл.md|pdf|csv> --origin public   # ваши материалы
pfs source add https://example.com/report          # веб-страница (скачивается, дедуп по URL)
pfs source fetch https://blocked.example.com --title "…"  # недоступный URL: ретраи и фолбэки
pfs source list                                    # реестр источников S###
```
Правило: данные, не полученные из внешних источников, честно помечаются как гипотезы.
Запрещённые домены настраиваются в `quality_gate.json`.

### Шаг 3 · research — исследование
Регистрируйте утверждения с силой доказательства:

```bash
pfs claim add "Утверждение" --kind fact --source S001 --grade B --quote "дословная цитата"
pfs claim add "Гипотеза" --kind hypothesis --source S001
pfs claim add "Вывод" --kind inference --from C001,C002
```

Гейт следит за цитатами: числа из цитаты должны быть в тексте источника.
Если цитата не сошлась — `pfs claim fix-source --id C001 --source S002` (с перепроверкой).

### Шаг 4 · discovery — пользователи и альтернативы
Персоны, JTBD, конкуренты. Карты шага подскажут методики (`pfs step` печатает их).

### Шаг 5 · situation — картина ситуации
`02_situation.md`: что известно, чего не знаем (таблица пробелов), противоречия,
вопросы, которые могут изменить решение.

### Шаг 6 · options — варианты
`03_options.md`: минимум три содержательно разных варианта, включая «оставить как есть»
и «закрыть направление». У каждого варианта — раздел «Возражения» с контр-аргументами.

### Шаг 7 · choice — выбор руководителя
Агент показывает сравнение и рекомендацию, пауза `pfs ask` → вы отвечаете `pfs answer "B"`.

### Шаг 8 · strategy — стратегии
`04_product_strategy.md` (аудитория, выбранное направление, экономика, роадмап-этапы)
и `05_comms_strategy.md` (аудитория, барьер, сообщение, таблица «обещание → подтверждение»).

### Шаг 9 · validation — план проверки
`06_validation_plan.md`: ожидаемое изменение, база сравнения, срок, контрметрики,
KPI двух плоскостей (бизнес/продукт) — явная таблица.

### Шаг 10 · review — контроль качества
```bash
pfs check --strict      # блокирующие ошибки останавливают
pfs review lock         # зафиксировать вердикт после ревизии
```

### Шаг 11 · decision — решение
```bash
pfs decision add --title "…" --decision "…" --owner PM --grounds C001,C003 \
  --review "2027-02-01" --trigger "метрика < X" --commit "что | кто | когда"
pfs decision due      # что решать сейчас
```

### Шаг 12 · monitoring — по запросу
Отдельный режим: `pfs decision due`, `pfs next`. Автоматически не запускается.

## 5. Финальный пакет: six-pager

Двухшаговый воркфлоу:

```bash
pfs export --six-pager    # шаг 1: пакет данных + каркас FAQ-1…6 со слотами
pfs check --six-pager     # шаг 2: линтер документа комитета; цикл «править → 0 ошибок»
pfs finish                # финальный пакет: 4 Excel + REPORT + six-pager RU/EN + DOCX + дека
```

Линтер проверяет: структуру эталона, объём ≤ 3500 слов, остатки шаблона, пустые таблицы,
служебные ID без расшифровки, арифметику (вклад 100%, метрики совпадают), сноски,
язык (EN без кириллицы). Six-pager не пересобирается поверх написанного текста.

## 7. Частые вопросы пользователя

| Симптом | Действие |
|---|---|
| «Задача 'X' не описана в models.json» | `pfs models` — список доступных задач; в доки шпаргалке используйте реальные задачи (`judge`) |
| Число без ссылки на C###/S### | добавьте тег утверждения или пометку «продуктовое допущение» |
| Линтер: «KPI/CAC без расшифровки» | расшифруйте аббревиатуру при первом упоминании |
| «document not written yet» | рабочий документ ещё не создан — заполните или уберите ссылку |
| finish отклоняет пакет | `pfs check --strict` покажет список: исправьте и повторите |
