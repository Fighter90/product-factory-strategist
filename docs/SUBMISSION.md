# Стратег Фабрики продуктов — описание работы

> Документ для жюри. Конвертируется в PDF: `pandoc docs/SUBMISSION.md -o submission.pdf` (или «Печать → PDF» из GitHub).
> Скриншоты для PDF: вывод команд из раздела 7 и файлы `projects/демо/outputs/*` (скриншоты: SIX_PAGER.pdf, rose_screen.jpg).

## 1. Что это и как запустить

Репозиторий-агент для руководителя цифрового продукта: превращает размытый запрос и разнородные материалы в проверяемую
картину ситуации, ≥3 содержательно разных варианта (вкл. «оставить как есть» и «закрыть») и согласованные продуктовую и
коммуникационную стратегии с планом проверки; после решения — сопровождение (основания, обязательства, пересмотр).

Запуск: Python 3.9+ без пакетов → `python3 -m tools.pfs doctor` → открыть папку в Claude Code и написать задачу.
Подробно — [README](../README.md).

## 2. Архитектура

См. [ARCHITECTURE.md](ARCHITECTURE.md). Кратко:

- **Процесс:** route → intake ⏸ → sources → research → discovery → situation → options (+red team) → choice ⏸ → strategy →
  validation → review → decision ⏸ → monitoring. ⏸ — решает человек; остальное агент ведёт сам и отмечает шаги в state.json.
- **Инструменты:** CLI `pfs` (stdlib Python): состояние и продолжение, реестр источников (загрузка сайтов/PDF/DOCX/XLSX/CSV,
  дедупликация, детектор внедрённых инструкций, разрешённые домены, защита от SSRF), реестр утверждений с правилами,
  quality gate, анализ влияния, решения, стоимость по транскриптам, поиск по базе знаний, профиль данных и когорты,
  маршрутизация сценариев и моделей. Те же функции — по MCP (`.mcp.json`).
- **Контекст и знания:** инструкции (AGENTS.md, skills, agents) / методические знания (knowledge/, 80 карт RU + EN-индекс и EN-зеркала в methods_en/) / настройки
  (config/) / материалы проекта (projects/*/sources) / состояние (state.json, *.jsonl) / результаты (outputs/) — раздельно.
  Агент не грузит базу целиком: `pfs route` даёт список карт, `pfs kb search` — разделы карт (BM25).
- **Хуки:** SessionStart (контекст проекта при новом чате), PreToolUse/WebFetch (разрешённые домены),
  PostToolUse (журнал, детектор инструкций в веб-ответах, автопроверка документа), Stop (стоимость).

## 6. Демо-проект: ROSE — время, ошибки, помощь человека

**Задача (реальный продукт, открытые данные):** «Создать стратегию развития ROSE — закрытый клуб ужинов на шестерых в
Москве (3+3, подбор по манере речи, никаких фото до ужина, тайные розы, контакты при взаимности) — и стратегию выхода
на рынок премиум-знакомств». Продукт: [rosedate.ru](https://rosedate.ru/). Исходные материалы — 4 PDF продукта и
кликабельный прототип, зарегистрированы источниками [S009–S012].
Результат: [REPORT.md](../projects/демо/outputs/REPORT.md), [SIX_PAGER.md](../projects/демо/outputs/SIX_PAGER.md)
(**PDF/DOCX** — в том же каталоге), Excel-модель — 4 книги в `outputs/attachments/`.

**Как шла работа (по журналу `log.jsonl`, 96 записей):** route → сценарий growth → intake (3 вопроса руководителю:
направление · ось выручка/ARPU · ограничения «маржа + бренд») → 12 источников: сайт-прототип (JS — текст сохранён
вручную), Forbes/RB/ВЦИОМ/Коммерсантъ, 2 ИИ-респондента (origin=synthetic), бриф и выбор руководителя →
24 утверждения с типами и силой A–D → ситуация с честными пробелами → **5 вариантов A–E, включая «оставить как есть»
и «закрыть направление»** → red team субагент: 15 возражений + 5 скрытых допущений, встроены порогами → выбор
руководителя: **вариант B «глубина Москвы»** (S008) → обе стратегии с таблицей «обещание → подтверждение» → план
проверки 90 дней с порогами продолжить/изменить/остановить → **evidence-review: check --strict 100/100** →
числа пересчитаны программно (LTV 41 250 ₽, LTV/CAC 3,44 — сходятся с текстом и Excel) → решение D001 с основаниями
и датой пересмотра → monitoring открыт.

| Показатель | Значение |
|---|---|
| Реальное время сквозного прогона | ≈ 18 минут (12 шагов) |
| Источники / утверждения | 13 источников (S001–S013, из них 3 синтетических/модельных); 24 утверждения, 18 активных — история замен сохранена |
| Варианты и red team | 5 вариантов; 15 возражений + 5 скрытых допущений |
| Excel | 4 книги, 180 живых формул; пересчёт при открытии |
| Качество | check --strict 100/100; числа текста ↔ Excel сверены программно |
| Модели | профиль задаётся в `config/models.json` (Claude Opus/Sonnet/Haiku); прогон выполнен в среде OpenCode — учёт времени по журналу, стоимость учитывается Stop-хуком в Claude Code |
| Помощь человека | 3 обязательные паузы: подтверждение брифа, выбор варианта B, утверждение решения D001 |
| Ошибки и сбои (честно) | Forbes отдал 0 знаков (JS) → текст сохранён вручную (`--text-file`); сдвиг нумерации источников → 5 `claim supersede`; случайное замещение живого факта → **чекер поймал**, факт восстановлен (C024); знание об этих ошибках — часть прозрачности агента |

**Экономика стола** (допущения [C017], модель в Excel): 6 × 16 500 = 99 000 ₽ выручки; переменные ~45%; вклад 54 450 ₽; LTV участника ≈ 41 250 ₽; LTV/CAC ≈ 3,4; брейк-евен ≈ 8 столов/мес.

**Сравнение с исходным способом:** все числа отчёта снабжены тегами источников и проверены `check --strict`
(у обычного чата с ИИ проверяемых чисел — 0%); полный пакет «исследование → варианты → стратегии → план → решение»
— за один прогон 18 минут.
