> Документ для жюри. Конвертируется в PDF: `pandoc docs/SUBMISSION.md -o submission.pdf` (или «Печать → PDF» из GitHub).
> Скриншоты для PDF: вывод команд из раздела 7 и файлы `projects/демо/outputs/*` (six-pager PDF: SIX_PAGER_RU.pdf,
> SIX_PAGER_EN.pdf; скриншоты продукта: `projects/демо/outputs/img/`, `site/assets/`).

## 1. Что это и как запустить

Репозиторий-агент для руководителя цифрового продукта: превращает размытый запрос и разнородные материалы в проверяемую
картину ситуации, ≥3 содержательно разных варианта (вкл. «оставить как есть» и «закрыть») и согласованные продуктовую и
коммуникационную стратегии с планом проверки; после решения — сопровождение (основания, обязательства, пересмотр).

Запуск: Python 3.9+ без пакетов → `python3 -m tools.pfs doctor` → открыть папку в Claude Code и написать задачу.
Подробно — [README](../README.md).

## 2. Архитектура

См. [ARCHITECTURE.md](ARCHITECTURE.md). Кратко:

- **Процесс:** route → intake ⏸ → sources → research → discovery → situation → options (+red team) → choice ⏸ → strategy →
  validation → review → decision ⏸ → monitoring. ⏸ — решает человек; остальное агент ведёт сам и отмечает шаги в state.json.
- **Инструменты:** CLI `pfs` (stdlib Python): состояние и продолжение, реестр источников (загрузка сайтов/PDF/DOCX/XLSX/CSV,
  дедупликация, детектор внедрённых инструкций, разрешённые домены, защита от SSRF), реестр утверждений с правилами,
  quality gate, анализ влияния, решения, стоимость по транскриптам, поиск по базе знаний, профиль данных и когорты,
  маршрутизация сценариев и моделей. Те же функции — по MCP (`.mcp.json`).
- **Контекст и знания:** инструкции (AGENTS.md, skills, agents) / методические знания (knowledge/, 89 карт RU + 89 EN-зеркал — полная двуязычная база в methods_en/ + INDEX_EN.md) / настройки
  (config/) / материалы проекта (projects/*/sources) / состояние (state.json, *.jsonl) / результаты (outputs/) — раздельно.
  Агент не грузит базу целиком: `pfs route` даёт список карт, `pfs kb search` — разделы карт (BM25).
- **Хуки:** SessionStart (контекст проекта при новом чате), PreToolUse/WebFetch (разрешённые домены),
  PostToolUse (журнал, детектор инструкций в веб-ответах, автопроверка документа), Stop (стоимость).

## 6. Демо-проект: CVStart — 12 шагов, синтетика, помощь человека

**Задача:** «Разработать коммерческую версию cvstart.org и стратегию вывода на рынок на весь мир». Продукт:
[cvstart.org](https://cvstart.org/) ([github.com/Fighter90/career-ops-ui](https://github.com/Fighter90/career-ops-ui)) —
открытый (MIT) AI-конструктор резюме и поиска вакансий: скан ~129 джоб-бордов, AI-скоринг 0.0–5.0, CV Studio,
PDF/DOCX, cover letters, трекер, карта вакансий; 100% локально; 18 LLM-провайдеров BYOK; 19 языков; ~7 602
автотеста; монетизации нет. Ось сравнения — платящие подписчики и ARR; ограничения: MIT-core остаётся бесплатным,
соло-разработчик, сохранить доверие локального режима.
Результат: [REPORT.md](../projects/демо/outputs/REPORT.md), six-pager на двух языках —
[SIX_PAGER_RU](../projects/демо/outputs/SIX_PAGER_RU.md) и [SIX_PAGER_EN](../projects/демо/outputs/SIX_PAGER_EN.md),
каждый в трёх форматах (MD/PDF/DOCX — детальный текст комитета: выводы, обоснования, расчёты; без скриншотов), Excel-модель — 4 книги в `outputs/attachments/`.

**Как шла работа (12 шагов, по журналу `log.jsonl`):** route → сценарий вывода на рынок → intake (≤3 вопроса
руководителю: коммерциализация + GTM · ось платящие/ARR · ограничения «MIT-core, соло, локальный режим») →
10 источников (S001–S011): сайт и README продукта, рынок resume builders ($1,2–2,4 млрд — диапазон, агрегаторы
расходятся ×2), AI-сегмент CAGR 13,1%, конкуренты (Zety, resume.io, Novoresume, Kickresume, Enhancv, Teal, Rezi —
$8–40/мес с автопродлениями, языки EN+5), онлайн-рекрутинг $37,97 млрд (2025), ATS у 98% F500 → 20 утверждений
с типами и силой A–D (12 фактов, 4 гипотезы, 4 допущения) → дискавери: 2 ИИ-персоны (Sarah 32, software engineer,
EN-сегмент; Markus 35, PM, Берлин) — origin=synthetic, только гипотезы → ситуация с честными пробелами
(внутренних метрик hosted-версии нет — её ещё не существует) → **5 вариантов A–E, включая «оставить как есть»
и «закрыть коммерческую ветку»** → red team субагент: 15 возражений + 5 скрытых допущений (20 ударов), встроены
порогами → выбор руководителя: **вариант B — hosted freemium SaaS** (Free BYOK / Pro $12 / Unlimited $29;
opt-in облако при локальном MIT-core; честный прайсинг без автопродлений; волны локалей EN → DE/ES/PT-BR → JA/ZH) →
обе стратегии с таблицей «обещание → подтверждение» → план проверки 90 дней (продолжить ≥40 платящих /
изменить 20–40 / остановить <20 при activation <35%; контр-метрики: звёзды GitHub, GDPR-жалобы, NPS ≥30,
инференс free ≤$200/мес) → **review: check --strict 100/100** → решение D001 (бета в 3 EN-гео к 2026-12-15;
пересмотр 2027-02-10; основания C019/C013/C014/C016/C005/C006) → monitoring открыт.

| Показатель | Значение |
|---|---|
| Источники / утверждения | 10 источников (S001–S011, из них 3 синтетических/модельных); 20 утверждений C001–C020 — история реестра сохраняется |
| Варианты и red team | 5 вариантов; 20 ударов red team (15 возражений + 5 скрытых допущений) |
| Excel | 4 книги на формулах; пересчёт при открытии |
| Качество | check --strict 100/100 |
| Помощь человека | 3 обязательные паузы: подтверждение брифа, выбор варианта B, утверждение решения D001 |
| Синтетика — честно | персоны (S009–S010) и воронка (S008) помечены origin=synthetic: гипотезы и метод, не доказательство спроса — чекер факты на них не пускает |

**Экономика hosted-версии** [C016]: ARPU $29 → контрибуция $21,75; LTV ≈ $271,88; LTV/CAC ≈ 4,5;
брейк-евен ≈ 69 платящих. Синтетическая воронка [S008] (метод, не прогноз): к нед. 12 — 53 платящих,
MRR $1 537; воспроизводится скриптом `analysis/gen_synthetic.py` → `analysis/synthetic_funnel.csv`.

**Сравнение с исходным способом:** все числа отчёта снабжены тегами источников и проверены `check --strict`
(100/100); полный пакет «исследование → варианты → стратегии → план → решение» собирается одним сквозным
прогоном агента.
