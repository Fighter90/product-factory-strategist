# Стратег Фабрики продуктов — описание работы

> Документ для жюри. Конвертируется в PDF: `pandoc docs/SUBMISSION.md -o submission.pdf` (или «Печать → PDF» из GitHub).
> Скриншоты для PDF: вывод команд из раздела 7 и файлы `projects/связь-для-близких-и-собственных-устройств/outputs/*`
> (six-pager: SIX_PAGER.docx, SIX_PAGER_EN.docx; макет продукта: `sources/raw/wireframe-kabinet.png`).

## 1. Что это и как запустить

Репозиторий-агент для руководителя цифрового продукта: превращает размытый запрос и разнородные материалы в проверяемую
картину ситуации, ≥3 содержательно разных варианта (вкл. «оставить как есть» и «закрыть») и согласованные продуктовую и
коммуникационную стратегии с планом проверки; после решения — сопровождение (основания, обязательства, пересмотр).

Запуск: Python 3.9+ без пакетов → `python3 -m tools.pfs doctor` → открыть папку в Claude Code и написать задачу.
Подробно — [README](../README.md).

## 2. Архитектура

См. [ARCHITECTURE.md](ARCHITECTURE.md). Кратко:

- **Процесс:** route → intake ⏸ → sources → research → discovery → situation → options (+red team) → choice ⏸ → strategy →
  validation → review → decision ⏸ → monitoring. ⏸ — решает человек; остальное агент ведёт сам и отмечает шаги в state.json.
- **Инструменты:** CLI `pfs` (stdlib Python): состояние и продолжение, реестр источников (загрузка сайтов/PDF/DOCX/XLSX/CSV,
  дедупликация, детектор внедрённых инструкций, разрешённые домены, защита от SSRF), реестр утверждений с правилами,
  quality gate, анализ влияния, решения, стоимость по транскриптам, поиск по базе знаний, профиль данных и когорты,
  маршрутизация сценариев и моделей. Те же функции — по MCP (`.mcp.json`).
- **Контекст и знания:** инструкции (AGENTS.md, skills, agents) / методические знания (knowledge/, 111 карт RU + 111 EN-зеркал — полная двуязычная база в methods_en/ + INDEX_EN.md) / настройки
  (config/) / материалы проекта (projects/*/sources) / состояние (state.json, *.jsonl) / результаты (outputs/) — раздельно.
  Агент не грузит базу целиком: `pfs route` даёт список карт, `pfs kb search` — разделы карт (BM25).
- **Хуки:** SessionStart (контекст проекта при новом чате), PreToolUse/WebFetch (разрешённые домены),
  PostToolUse (журнал, детектор инструкций в веб-ответах, автопроверка документа), Stop (стоимость).

## 6. Демо-проект: «Связь для близких» — 12 шагов, синтетика, помощь человека

**Задача (бриф заказчика, учебный рынок мобильного оператора):** «Ваша команда отвечает за услуги вымышленного
мобильного оператора. Одни клиенты помогают близким со связью. Другие обслуживают несколько собственных номеров.
Решите, кому помочь в первую очередь, что именно изменить и почему оператору стоит вложить в это деньги».
Оси: валовая прибыль планового года ≥285 млн (база «без изменений» — 279 [C002]); ограничения из-за исчерпания
12% → 9% (−3 п.п.) [C013]. По брифу ответ даётся **одной запиской из пяти частей** — это
[BRIEF_RESPONSE.md](../projects/связь-для-близких-и-собственных-устройств/outputs/BRIEF_RESPONSE.md):
расчёты рядом с решениями, все числа с тегами источников.
Результат: [REPORT.md](../projects/связь-для-близких-и-собственных-устройств/outputs/REPORT.md) (MD/DOCX/PDF),
six-pager на двух языках — [SIX_PAGER](../projects/связь-для-близких-и-собственных-устройств/outputs/SIX_PAGER.md) и
[SIX_PAGER_EN](../projects/связь-для-близких-и-собственных-устройств/outputs/SIX_PAGER_EN.md) (каждый в MD/DOCX —
детальный текст комитета: выводы, обоснования, расчёты), Excel-модель — 4 книги на формулах в `outputs/attachments/`,
дека — `outputs/presentations/deck.html`. Карта пакета за 60 секунд —
[DEMO_README.md](../projects/связь-для-близких-и-собственных-устройств/DEMO_README.md).

**Как шла работа (12 шагов, по журналу `log.jsonl`):** route → бригада карт и план моделей → intake (бриф от
руководителя, решение Q1 «выделять ли людей и деньги на пилот», Q2 «расширять ли охват») → 4 источника
(S001 бриф, S002–S003 ИИ-респонденты — организатор и владелец роутера, S004 макет кабинета) → план исследования
от 7 вопросов, которые могут изменить решение → дискавери: сегменты С1–С3 → ситуация: что известно [C001–C010],
чего не знаем (частоты причин — допущения [C011,C012]), противоречие «данные есть — предупреждений нет» →
**5 вариантов A–E, включая «оставить как есть» и «закрыть услугу»** → red team субагент: 15 возражений + 5 скрытых
допущений (20 ударов), встроены порогами [C021–C026] → выбор руководителя: **B — «Предупреждение до перебоя»**
(предупреждение организатору при низком остатке участника и предстоящем платеже; гранулярные согласия) →
обе стратегии с таблицами «обещание → чем подтверждено» → план проверки: pre-registration, A/B 600 семейных групп
(набор 6 недель + наблюдение 14 дней, ITT), порог расширения −3 п.п., стоп-метрики (precision ≥80%, темп набора,
повторные списания) → **review: `check --strict` 0 ошибок** → решение D001 утверждено руководителем (пилот к концу
Q1; расширение планового года — только при эффекте ≥−3 п.п.; пересмотр 2027-04-30; 4 обязательства) →
мониторинг: `pfs decision due`.

| Показатель | Значение |
|---|---|
| Источники / утверждения | 4 источника (S001–S004; 2 из них — ИИ-респонденты); 26 активных утверждений C001–C027 (10 факт · 8 допущение · 4 гипотеза · 4 вывода), история реестра сохраняется (C018 замещена) |
| Варианты и red team | 5 вариантов A–E; 20 ударов red team (15 возражений + 5 скрытых допущений) |
| Excel | 4 книги на формулах; пересчёт при открытии |
| Качество | `check --strict`: 0 ошибок; six-pager RU/EN — 0 ошибок линтера |
| Помощь человека | 3 обязательные паузы: бриф, выбор варианта B, утверждение решения D001 |
| Синтетика — честно | ИИ-респонденты (S002–S003) помечены origin=synthetic: гипотезы, не доказательство спроса — чекер факты на них не пускает |

**Экономика демо** [C003]: разрыв до цели 6 млн = **12 000 доп. оплаченных месяцев × 500 ₽**; целевой сценар
5 500 номеров × 3 мес − 1,5 млн расходов = **+6,75 млн → 285,8 млн (цель достигнута)**; сдержанный 283,5,
неблагоприятный 280,5, «ноль» 277,5, «минус» с оттоком 275,5 [C003,C021]. Расчёт воспроизводим:
`analysis/economics.py` → `economics_out.txt`.

**Сравнение с исходным способом:** все числа отчёта снабжены тегами источников и проверены `check --strict`
(0 ошибок); полный пакет «исследование → варианты → стратегии → план → решение» собирается одним сквозным
прогоном агента.

## 8. Время и расходы

**Установка:** одна команда `bash scripts/install.sh` — 3 репозитория, CLI `pfs` глобально,
самопроверка `pfs doctor`; ~5 минут без ручных настроек (подтверждено независимым QA-прогоном
на чистой Linux-машине).

**Контрольный CLI-прогон QUICKSTART** (12 шагов + решение + финишная сборка, без LLM):
~3 секунды на полный цикл; 0 токенов, $0.00 — вся механика (реестры, гейты, линтер комитета,
Excel, экспорт, журналы) работает на stdlib Python. RU- и EN-циклы прогоняются одинаково
(EN: `pfs new --lang en`).

**Полный цикл с агентом (LLM):** время и стоимость зависят от среды исполнения, выбранных
моделей (`pfs models`, профили fast/balanced/deep, режим `--economy`) и тарифов провайдера.
В журнале демо-прогона зафиксирована только CLI-часть ($0.00, 0 минут) — стоимость
LLM-сессий окружением разработки не передавалась в `pfs cost`; механизмы учёта
(`pfs cost`, `pfs log --usd`, `--human-minutes`) работают и покрыты тестами.

**Участие человека:** три обязательные паузы — бриф (intake), выбор варианта (choice),
утверждение решения (decision); между ними агент ведёт шаги сам. Режим `PFS_AUTOPILOT=1`
проходит паузы без человека (QA/CI-режим).

**Известные ошибки цикла разработки** — найдены и исправлены в процессе (полная история:
`CHANGELOG.md` и задачи PRO-46…PRO-93 в Linear): кросс-чек арифметики ловил расхождения
с `calcs.json` (доля вместо процента), линтер комитета требовал расшифровки терминов и
сносок, `pfs finish` отказался собирать пакет при одной ошибке линтера — гейты работают
как детекторы, а не формальности.

## 9. Ограничения заявленных возможностей

1. **Живой LLM-цикл** не воспроизводился независимой проверкой вне среды разработки:
   работа агента-«мозга» подтверждается артефактами демо-прогона (документы 00–07,
   six-pager RU/EN, REPORT, Excel, дека) и файлами инструкций, а не повторным прогоном.
2. **Живые внешние MCP-серверы** (`linear`, `producthunt`, `lovable`, `rea`) требуют
   OAuth-авторизации или ключей в `.env` и подключаются опционально; без них агент
   работает на CLI-механике и встроенном MCP-сервере `pfs-strategist`.
3. **pypdf** — опциональный компонент: без него загрузка PDF-источников деградирует
   (текст не извлекается, остаётся выписка вручную через `--text-file`).
4. **Стоимость и время LLM-части** зависят от среды, моделей и тарифов провайдера —
   цифры такого рода в материалах не приводятся; фиксируется только CLI-часть.
5. **SSL-ремедиация** зависит от способа установки (uv tool → `uv tool install --with certifi`;
   venv/system → `pip install certifi`, на macOS — «Install Certificates.command»):
   подсказка подстраивается автоматически (PRO-82), TLS-проверка не отключается.
6. **Косметика локализации:** подписи листов Excel-приложений остаются в RU-написании
   при EN-проекте; кириллица в цитатах русскоязычных источников EN-документа легитимна
   (источник цитируется дословно).
