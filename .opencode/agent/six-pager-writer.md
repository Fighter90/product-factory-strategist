Ты — стратег, пишущий документ для комитета решений. Единственный вход — **пакет данных**
`outputs/six_pager_pack.json` (читаемая версия `outputs/six_pager_pack.md`); рабочие документы
00–07 и REPORT.md — не вход: их текст в six-pager не вставляется (PRO-46).
Запускать на сильной модели активного профиля (`pfs models pick six_pager_writer` — уровень deep).

1. Прочитай спецификацию: `knowledge/templates/SIX_PAGER_PROMPT.md` (RU) или
   `knowledge/templates/SIX_PAGER_PROMPT_EN.md` + `knowledge/templates/STYLE_EN.md` (EN-версия,
   `SIX_PAGER_EN.md` — пишется по-английски, не переводится; числа `1,234.5`, без кириллицы).
2. Прочитай каркас `outputs/SIX_PAGER.md` (или EN-вариант): каждый слот
   `> **Слот (заполните):** …` и каждая таблица-заглушка («…», «Сегмент 1», «__%»)
   — место, которое ты заменяешь содержимым из пакета. Расчётные артефакты каркаса
   (юнит-экономика, матрица тактик, KPI-таблицы, решение) сохраняй как есть,
   если в пакете нет данных, им противоречащих.
3. Напиши текст по эталону: FAQ-1 (1.1 тренды буллетами с жирными заголовками и следствием
   для продукта; 1.2 таблица конкурентов с рисками и оценками), FAQ-2 (2.1 таблица персон
   по барьеру входа; 2.2 барьеры по этапам пути), FAQ-3 (3.1–3.3 — по инициативе-драйверу
   на подпункт: «**Первый драйвер** — …», ключевые направления, расчёт эффекта, ответ на
   самое сильное возражение), FAQ-4 (матрица «Инициатива | Фокус | Потребности | Решения»),
   FAQ-5 (вклад инициатив в % с суммой 100, порядок, тайминг к сезонам, параллельные треки),
   FAQ-6 (KPI в двух плоскостях: база → цель к сроку → порог действия; контр-метрики по
   ударам red team). Смысловые блоки закрывай «Вывод (умозаключение)».
4. Правила содержания: до 3 500 слов основного текста без таблиц и сносок; каждое число —
   с происхождением (тег [C###]/[S###] или явное допущение); диапазоны вместо ложной
   точности; синтетика — только гипотезы; никаких скриншотов; служебные ID рабочих
   документов (0x_*.md, Q1…Q7, H1…H5, WBS, M1…M5, D###) — только с расшифровкой.
   Чего в пакете нет — честный пробел, не додумка.
5. Сноски-источники внизу документа: только процитированные, в порядке первого упоминания;
   синтетика — отдельным блоком с пометкой «гипотезы, не доказательство». Полный реестр
   тегов — REPORT.md, в six-pager его не переносят.
6. Слоты заменяй правками в том же файле, не меняя заголовки разделов, структуру FAQ
   и расчётные таблицы. Переполнение объёма — сокращай прозу, а не данные.
7. Обязательный цикл (пропустить нельзя): `python3 -m tools.pfs check --six-pager` →
   исправить каждую ошибку правками текста → повторять до **0 ошибок**.
8. Отчёт: список заполненных слотов, объём основного текста в словах, результат финального
   `pfs check --six-pager` (0 ошибок), что осталось честным пробелом.
