# 06 · Дизайн A/B-пилота «Предупреждение до перебоя» [C013]

> Соответствует требованиям брифа к пробному запуску [S001] и pre-registration [06, C025].

## Дизайн эксперимента

| Элемент | Решение | Основание |
|---|---|---|
| Единица рандомизации | Семейная группа (вся семье один вариант обслуживания) | Участники делят пакет — действие одного меняет остаток другого [S001] |
| Группы | A — предупреждения; B — обычное обслуживание | Требование случайного распределения [S001] |
| Размер | 600 групп (300×300) | Пример мощности из брифа: 600 групп, 6 недель набора, ~100/нед [C027,C012] |
| Владельцы нескольких номеров | Отдельный малый контур, распределение по владельцам | Та же причина соприкосновения остатков [S001]; вторая очередь [C016] |
| Условия включения | Тариф поддерживает передачу пакета; свободный остаток; согласия выданы (3 типа [C022]) | «Кого включать» [S001] |
| Первый подходящий случай | Первое событие «остаток ~20% / платёж через 3 дня» после включения в пилот | Одинаково регистрируется в обеих группах [S001] |
| Начало наблюдения | Момент подходящего события; обе группы — одинаково долго | «Что считать» [S001] |
| Учёт участников | ITT: все включённые, включая не открывших сообщение [S001] | Исключает смещение «готовых помочь» [S001] |
| Рандомизация | Детерминированный хеш по ID группы; кластеры = семьи; регистрация протокола до старта | Pre-registration [C025]; спилловер — замер опросом контрольных групп [C025] |

## Метрики

- **Первичная (пилот):** дополнительные оплаченные месяцы на группу (ITT) [C025] — прямая связь с 500 руб./мес [C003].
- **Клиентский результат:** доля подходящих номеров, где в 7 дней после случая низкого остатка интернет ограничили из-за исчерпания — цель −3 п.п. (12%→9%) [C013,S001].
- **Реакции на предупреждение:** перевод ГБ / оплата / ничего — раздельно [C023].
- **Инкрементальность платежей:** даты платежей против контроля, окно 90 дней; сдвиги >30% → эффект обнуляется [C021].
- **Вторичные:** активация 14 дней [C007]; обращения «за что списали» [C019,H3]; время на задачу «помочь близкому» (тест удобства) [S001].
- **Стоп-метрики:** отзывы согласий >15% [C022]; отключения опции >10%/4 нед; ложные срабатывания >20%; повторные списания ≥1 (06).

## Порог и интерпретация (записаны до данных)

- Эффект ≥ −3 п.п. при ложных срабатываниях <20% и повторных списаниях = 0 → **расширение** [06].
- Эффект −1…−3 п.п. → диапазон совместим и с пользой, и с нулем → **продлить наблюдение**, дата пересмотра [S001].
- Эффект ≈0 или контр-метрики выше порогов → **остановка/изменение**, разбор с владельцем системы [S001].
- Улучшение на одном тарифе → повторная проверка на новых клиентах этого тарифа; при расширении сохранить группу сравнения «первый подходящий случай» [S001].

## Оплата и смета

- Прямые расходы пилота: разработка ~2 из 3 чел.-мес Q2 [C010]; специалист проверки — 1 чел.-мес (решение руководителя [S001]); поддержка — смета до старта (удар red team №5 [03]).
- Стоимость разработки считается отдельно: поквартальное сопоставление доп. прибыли после прямых расходов с вложениями; пока цена неизвестна — предельная сумма вложений, возвращаемая за плановый год [S001].

## Просьба к руководителю (решение Q1)

Профинансировать проверку **одной причины** («исчерпание доли участника» — допущение о доминирующей причине [C011]) на **одном типе тарифов** (с передачей пакета): 600 групп, 2 чел.-мес разработки, 0,5 ставки аналитика, решение по специалисту проверки. Руководство в конце Q2 увидит: эффект по клиентскому результату, инкрементальные оплаченные месяцы, контр-метрики — и выберет: расширять / дорабатывать / наблюдать / остановить [S001,C002].
