# Фреймворки роста: AARRR, HEART, Flywheel, Growth Loops, Growth Model Canvas

## Когда применять
«Как продукт будет расти?», «какой фреймворк выбрать — воронку или петлю?», «спроектировать петлю роста / виральный цикл», «какие метрики мерить на каждом этапе». Выбор модели роста — индивидуальный рецепт; главное, чтобы сходилась математика.

## Суть
**Линейная воронка (AARRR, HEART):** требует постоянного наполнения «сверху» внешними вложениями в привлечение; на каждом этапе пользователи необратимо уходят.
**Петля роста (Flywheel, Growth Loop):** замкнутый цикл, где результат цикла (привлечённый пользователь, созданный контент) становится причиной привлечения новых в следующем цикле — рост «изнутри».

| Тип продукта | Рекомендуемый фреймворк (не жёсткое правило) |
|---|---|
| E-commerce | AARRR |
| SaaS | воронка пути + HEART |
| Игры | Growth Loop |
| Соцсети | Growth Loop + HEART |
| Медиа | Growth Loop + HEART |
Факторы выбора: стадия продукта, бизнес-цели, рынок, тип продукта.

### AARRR (Pirate Metrics), 6 этапов в версии скилла
| Этап | Суть | Каналы | Метрики |
|---|---|---|---|
| Awareness | люди узнают | SEO, SEM, content, affiliate, PR, соцсети, рассылки, ASO | visits, reach, CTR, CPC, CPM, bounce, engagement |
| Acquisition | посетители идентифицированы | блог, white papers, чат-виджеты, лендинги, вебинары, ретаргетинг, квизы | подписки, загрузки, Cost per Lead, trial signups |
| Activation | первый отличный опыт (Aha-момент) | UX, туториалы, поддержка, онбординг, drip | core feature usage, onboarding success, CAC |
| Retention | возвращаются | email, пуши, доп. функции, lifetime-маркетинг | churn, DAU, MAU, returning customers |
| Revenue | поведение генерирует доход | UX, sales, checkout | CLV, conversion, upsell/cross-sell, средний чек, CLV/CAC |
| Referral | приводят новых | реферальные механики, шеринг, рейтинги, вирусные кампании | invites, shares, viral coefficient, NPS |
Недостатки: постоянное наполнение верха (дорого, ограниченная масштабируемость), необратимый отток, нет петель обратной связи.

### HEART (Google) — фреймворк качества UX
Для каждого измерения: Goal → Signals → Metrics.
- Happiness — рейтинг в сторах, in-app опрос, Customer Effort Score.
- Engagement — DAU, действия на пользователя, число сохранённых/избранных.
- Adoption — download rate, Time to Value, onboarding completion.
- Retention — 30-/90-дневный retention, MAU, churn/uninstall.
- Task Success — время выполнения задачи, search success rate, error rate.

### Flywheel (маховик): Activate → Adopt → Adore → Advocate
| Этап | Сегмент | Стратегия | Метрика |
|---|---|---|---|
| Activate | оценивающий | простой путь к Aha-моменту, убрать барьеры | sign-up rate |
| Adopt | новичок | формирование привычки, обучение новым функциям | retention rate |
| Adore | постоянный пользователь | улучшать опыт, предвосхищать потребности | NPS |
| Advocate | чемпион | побуждать рекомендовать (запускает новый цикл) | referrals invited |
Пример (вертикаль «работа» классифайда объявлений): положительные петли — больше резюме → больше откликов → больше работодателей → больше вакансий → больше соискателей; отрицательная (контроль) — меньше соискателей → больше мошенников.

### Growth Loop: проектирование
Универсальный цикл: рост продукта → больше и лучше ресурсов (люди и капитал) → решение новых значимых проблем → рост продукта.
- **Observe:** реальный сценарий поведения; мотивация — to look good / to feel good / to help others / to get / to bond / to convince.
- **Design:** что мотивирует и как отразить в продукте; какое действие ожидаем и как его упростить; какой результат получит пользователь и как усилить.
- **Iterate:** шаги петли для отслеживания и метрики каждого шага.
Пример: врачи делятся медконтентом → продукт помогает найти подтверждающие данные → контент с фото и регалиями автора виден другим → они создают свой → метрики: прочитано/отмечено, поделились, пришли по ссылке, регистрации с UTM.

### Growth Model Canvas
Целевая аудитория (персона) · Value Proposition · North Star Metric · WOW Moment · Product DNA (клиенты нуждаются и «подсажены») · 6 этапов Awareness…Referral с метриками.

## Процедура
1. Описать продукт, стадию, цель роста, рынок; определить NSM ([[M-product-metrics]]).
2. По таблице выбрать 1–2 кандидата; обосновать письменно, почему не выбраны остальные.
3. **Проверить математику выбранной модели:**
   - воронка: `Результат = Вход × CR1 × CR2 × …`, экономика канала — `LTV > CAC`, payback ([[M-unit-economics]]);
   - петля (стандартная формула, не из скилла): коэффициент петли `K = i × c` (приглашений/созданного контента на пользователя × конверсия приглашённых в новых пользователей); при `K < 1` и постоянном внешнем притоке P итог на стационаре `P / (1 − K)`; при `K ≥ 1` рост самоподдерживающийся, на практике ограничен насыщением; важны время цикла и качество новых пользователей.
4. Спроектировать петлю по Observe → Design → Iterate; записать: триггер → действие → результат → вход следующего цикла; утечки и негативные петли.
5. Назначить метрику каждому шагу и способ измерения (события, UTM).
6. Заполнить Growth Model Canvas; связать с трекшн-моделью: петля — драйвер виральности, воронка — драйвер привлечения/активации/удержания ([[M-traction-model]]).
7. Контрольные метрики на каждый этап + контр-метрики здоровья.

## Шаблон / чек-лист
Петля:
| Шаг | Что делает пользователь | Мотивация | Результат | Метрика шага | Конверсия |
|---|---|---|---|---|---|
| 1 | | | | | |
| … | | | | | |
| Выход цикла → вход следующего | | | | K, время цикла | |
Артефакт выхода: выбор и обоснование; воронка или петля с метриками; каналы по этапам; Growth Loop; Canvas; контрольные метрики.

## Типичные ошибки
- Копировать фреймворк «как у лидера рынка», не проверив математику.
- Принять HEART (качество UX) за модель привлечения, а AARRR — за модель качества.
- Рисовать петлю без измеримых шагов и конверсий.
- Игнорировать отрицательные петли (мошенники, абьюзеры, спам).
- Оптимизировать Referral при слабом Activation/Retention.
- Опираться на «вирусность» без расчёта K и времени цикла.

## Вопросы, которые могут изменить решение
- Откуда сегодня идёт >70% новых пользователей (канал) и масштабируется ли он ([[M-pmf-scaling]])?
- Есть ли в продукте естественный результат использования, видимый другим (контент, приглашение)?
- Удерживается ли часть пользователей (кривая выходит на плато)? Если нет, петля усилит утечку.
- Какова стоимость единицы внешнего притока P в воронке?
- Что является Aha-моментом и сколько пользователей до него доходит?
