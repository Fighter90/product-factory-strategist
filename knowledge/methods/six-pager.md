# Six-pager

## Когда применять
Когда рекомендацию защищают перед комитетом/руководством: нужен компактный (≈6 смысловых страниц)
документ в фиксированной структуре, где каждый раздел отвечает на известный вопрос, а цифры считаются
в Excel-приложениях, а не «в воздухе». В агенте собирается командой `pfs export --six-pager`.

## Суть
Шесть FAQ-разделов, каждый — ответ на вопрос принимающего решение. Six-pager **пишется по эталону**
(`knowledge/templates/six_pager.md`, промпт `SIX_PAGER_PROMPT.md`), а не склеивается вставкой из
документов 02/03/04/06: документы — источники фактов и чисел, текст каждого раздела пишется заново
под вопрос читателя (PRO-46).

| Раздел | Вопрос читателя | Чем наполняется (источники фактов) |
|---|---|---|
| FAQ-1 | Что происходит на рынке, кто конкуренты, в чём вызов? | факты и противоречия из `02_situation.md`, таблица конкурентов «преимущество → риск для нас» |
| FAQ-2 | Кто пользователи, какие у них боли по этапам пути? | сегменты/персоны из ситуации и исследования |
| FAQ-3 | Какие инициативы предлагаем и почему именно они? | варианты и возражения из `03_options.md`, рекомендация |
| FAQ-4 | Из чего конкретно состоит каждая инициатива? | тактики: Focus → Needs & desires → Solutions |
| FAQ-5 | Как реализуем и как поймём, что получилось? | план проверки из `06_validation_plan.md`, вклад инициатив |
| FAQ-6 | По каким метрикам меряем успех? | бизнес- и продуктовые метрики с формулами (04, карта метрик) |

Правила структуры: вклад инициатив в результат суммируется в 100%; каждая инициатива имеет сильные
возражения; «оставить как есть» и «закрыть направление» присутствуют как полноценные альтернативы;
таблица конкурентов «преимущество → риск для нас»; тактики привязаны к потребностям, а не к фичам.

## Процедура (агент)
1. Проверить готовность источников: `02_situation.md`, `03_options.md`, `04_product_strategy.md`,
   `06_validation_plan.md`. Чего-то нет — сначала доделать шаг; six-pager без источников фактов не пишется.
2. Собрать параметры из реестра утверждений в `projects/<slug>/calcs.json` (каждое значение → C###).
3. Фоновым субагентом: `pfs calc all` → `outputs/attachments/*.xlsx` (юнит-экономика, модель роста,
   когорты, размер рынка; лист «Ввод» с редактируемыми параметрами, расчёты на формулах).
4. `pfs export --six-pager` → `outputs/SIX_PAGER.md`: разделы пишутся по эталону
   (`knowledge/templates/SIX_PAGER_PROMPT.md`), каждый FAQ отвечает на свой вопрос, а не пересказывает документ.
5. `pfs check` без новых ошибок; показать руководителю список приложений и что в них редактировать.

## Шаблон / чек-лист
См. `knowledge/templates/six_pager.md`. Чек-лист качества:
- [ ] каждый раздел отвечает на «свой» вопрос, а не пересказывает соседний;
- [ ] числа только с [C###]/[S###]; значения в тексте совпадают с Excel;
- [ ] у каждой инициативы — возражения и вклад в результат (сумма = 100%);
- [ ] метрики с формулами, единицами, периодом и целевым значением;
- [ ] план проверки: база сравнения, срок, контрметрики, критерии продолжить/изменить/остановить.

## Типичные ошибки
- «Красивый текст без расчётов»: цифры без модели и источника — читатель не может их проверить.
- Тактики без потребностей: список фич вместо «боль → механика → ожидаемый эффект».
- Переполненный FAQ-1: история рынка вместо ответа «что это меняет для решения».
- Метрики без базы сравнения и срока — «вырастим лояльность» не проверяемо.
- Excel с «мёртвыми» числами вместо формул: допущение нельзя пощупать.

## Вопросы, которые могут изменить решение
- Какой вклад каждой инициативы в целевую метрику и на чём он основан?
- Что должно случиться, чтобы мы отказались от инициативы (критерий остановки)?
- Какая цифра в модели самая хрупкая и что её подтвердит дешевле всего?
