# Оценка объёма рынка (PAM / TAM / SAM / SOM)

## Когда применять
Вопросы руководителя продукта: «насколько велик потенциал?», «стоит ли входить в сегмент / инвестировать?», «хватит ли рынка под цели трекшн-модели?». Карта даёт воспроизводимый расчёт рыночной воронки и «проверку сверху» (модель роста не может обещать больше, чем SOM).

## Суть
**Объём рынка** — количественная оценка реальных или потенциальных продаж (деньги, люди или единицы продукта), полученная расчётом из данных, а не предположением.

| Уровень | Что это | Горизонт | Роль |
|---|---|---|---|
| PAM (Potential Available Market) | теоретический максимум без ограничений; в расчётах не используется | — | опциональный «потолок» |
| TAM (Total Addressable Market) | весь рынок при покрытии всех сегментов без гео/технологических ограничений | сверхцель, порядка 10 лет | главный показатель для венчурных инвесторов |
| SAM (Serviceable Available Market) | часть TAM, реально обслуживаемая с учётом бизнес-модели, гео, технологий, конкурентов | 3–5 лет | долгосрочная цель |
| SOM (Serviceable Obtainable Market) | часть SAM, достижимая в ближайшей перспективе по росту, цене, ресурсам | 1–3 года | самая консервативная метрика, её ждут в бизнес-плане |

**Единицы рынка** — считать в том, что ближе к бизнес-модели, и показывать пересчёт в остальные:
| Единица | Когда | Пример |
|---|---|---|
| Люди | аудитория, маркетинг | 15 млн потенциальных пользователей |
| Деньги | инвестрешения, оценка бизнеса | 2,5 млрд руб./год |
| Единицы продукта | производство, логистика | 50 млн заказов/год |

По модели: подписка = пользователи × ARPU; e-commerce = заказы × средний чек; маркетплейс = сделки × комиссия (или GMV × take rate); B2B SaaS = компании × стоимость лицензии.

**Два способа оценки**
- Top-down: мир → регион → страна → город → сегмент; быстро, менее точно.
- Bottom-up: единицы (пользователи/компании) × средняя цена/частота; точнее, требует данных.
- Считать обоими и сравнить. Правило скилла: расхождение более чем в 3 раза — искать ошибку (определения, единицы, период, географию).

**Top-down формулы по уровням воронки** (как в расчётных таблицах курса):
- `PAM = потенциальные пользователи × ARPU` (глобальный потолок).
- `TAM = население региона × % целевой аудитории × % готовности платить × ARPU`.
- `SAM = TAM × % доступный по бизнес-модели × (1 − % занятый недоступными конкурентами) × Adoption rate`.
- `SOM = SAM × целевая доля рынка` или `SOM = текущая база × (1 + коэффициент роста)^период`.
- Альтернативная «физическая» формула (аренда, отели, парковки): `Объём рынка = количество единиц (объектов) × загрузка × период × цена за единицу`.
- В деньгах и в людях уровни определяются словами через сегменты, например: PAM — весь рынок туризма (проживание + транспорт + питание + досуг); TAM — сегмент «проживание» целиком, включая офлайн; SAM — только те же сегменты в онлайн-канале (OTA); SOM — расчётный GMV продукта: `SOM = бронированные ночи × средний чек`, пользователи = `ночи / длительность поездки / частота поездок в год`.

**Расчёт всегда показывают вместе с динамикой рынка**: CAGR базового рынка и прогноз доли канала (например, доля онлайн-канала растёт с X% до Y% к горизонту) — «рынок вырастет в N раз, а онлайн-канал заберёт большую часть роста» это отдельный аргумент за/против входа, а не только текущий объём.

**Два способа SOM**
| Ситуация | Подход |
|---|---|
| Цифровой масштабируемый продукт | через конверсии (воронка привлечения) |
| Физический товар, ручное производство | через производственные ограничения |
| Сервис с ограниченным capacity | через производственные ограничения |
| Маркетплейс | конверсии + supply-ограничения (берётся меньшее) |

## Процедура
1. **Паспорт исследования:** продукт/компания, цель («потенциал рынка для X в сегменте Y»), дата, гео, горизонт, основная единица.
2. **Границы рынка.** Письменно определить, что входит в категорию, а что нет («рынок AI» = софт? сервисы? чипы?). Без определения цифры из разных источников несопоставимы (см. [[M-source-criticism]]).
3. **Top-down:** `Рынок_сегмента = Рынок_верхнего_уровня × Доля_гео × Доля_сегмента` (единицы и год одинаковы на всех шагах). Для каждой цифры — источник, год, класс достоверности.
4. **Bottom-up:**
   - B2C: `TAM = N_сегмента × Доступ(%) × Частота (раз/год) × Средний_чек (руб./раз)` → руб./год.
   - B2B: `TAM = N_компаний_сегмента × Стоимость_контракта (руб./год)`; число ЛПР и цикл продажи нужны для SOM.
5. **SAM** = TAM × последовательные ограничения (гео, канал, платформа, ценовой сегмент, юридическое). Каждый множитель выписать отдельной строкой с источником.
6. **SOM через конверсии:** `Скачивания/лиды × CR1 × CR2 × … = активные покупатели`; `SOM = активные × Средний_чек × Частота (раз/год)`.
7. **SOM через ограничения:** `SOM = Мощность_ед./день × Рабочих_дней × Цена`.
8. **Сверка и sanity-checks:**
   - `TAM ≥ SAM ≥ SOM`; ориентир скилла: TAM в 5–10 раз больше SAM — если отношение близко к 1, вероятно, перепутаны TAM и SAM.
   - Произведение конверсий ≤ 1; число активных покупателей ≤ SAM в людях.
   - Расхождение top-down и bottom-up ≤ 3 раз; иначе пересмотреть определения.
   - Единицы: руб./год ≠ руб./мес; пользователи ≠ заказы.
   - Трекшн-модель не превышает SOM ([[M-traction-model]]).
9. **Три сценария** (пессимистичный/базовый/оптимистичный) для самых неопределённых множителей.
10. **Визуализация первой:** концентрические круги PAM→TAM→SAM→SOM или waterfall (как TAM сужается до SOM); затем таблицы с логикой расчёта.

### Примеры из скилла (цифры иллюстративные)
- Приложение одежды: 50 000 скачиваний/год × 40% регистрация × 10% первый заказ × 50% повторный = 1 000 активных; × 3 000 руб. × 4 раза/год = **12 млн руб./год**.
- Сумки ручной работы: 2 мастера × 1 шт./день × 365 дн. × 15 000 руб. = **10,95 млн руб./год** (проверь реальные рабочие дни: 365 — упрощение примера).
- Top-down (traction-modeling): рынок фармацевтики РФ ~3 трлн руб. → Москва+МО 21% × диабет 2,3% ≈ 15 млрд руб. (SAM) → SOM: лидер 10% от SAM = 1,5 млрд руб. — потолок реалистичной цели. Цифры без источника, взяты как демонстрация логики.

## Шаблон / чек-лист
**Формат расчётного файла (как в практике курса)** — один лист, две части:
1. Паспорт исследования: продукт, цель исследования (для какого решения считается), дата, перечень источников, **итоги исследования** — абзац-вывод: какая доля рынка у продукта по сегментам, растёт ли рынок (CAGR), растёт ли доля канала, и что это значит для решения «инвестировать / нет».
2. Таблица воронки (каждый уровень — строка):
| Этап | Логика расчёта (словами, через сегменты и срезы) | Объём в деньгах | Объём в пользователях | Источники (для каждой цифры) |
|---|---|---|---|---|
| PAM (опц.) | | | | |
| TAM | | | | |
| SAM | | | | |
| SOM | | | | |

Проверка снизу вверх: SOM считается от данных продукта или ближайшего конкурента (события × конверсии × чек), затем сравнивается с SAM — получается расчётная доля рынка; она должна быть правдоподобной (не «22% у игрока, которого никто не знает») и согласованной с мощностями. В «пользователях» уровень может быть `n/a`, если источник считает транзакции (путешествия), а не уникальных людей — это фиксируется явно, а не замалчивается.

| Этап | Логика расчёта | Деньги | Пользователи/единицы | Источник (год, класс A–D) |
|---|---|---|---|---|
| PAM (опц.) | | | | |
| TAM top-down | | | | |
| TAM bottom-up | | | | |
| SAM | | | | |

Параметры B2C: население сегмента; проникновение интернета/доступ; частота покупок; средний чек; конверсии по воронке (бенчмарки через [[M-benchmarking]] или собственные данные).
Параметры B2B: число компаний сегмента; число ЛПР; стоимость контракта; цикл продажи; win rate.

Ориентиры инвесторов из скилла (**без источника — класс D, проверять перед использованием**):
| Параметр | Россия, Series A | Международный, Series A |
|---|---|---|
| Инвестиция | $1M–$5M | $5M–$20M |
| TAM | $100M–$1B | от $1B |
| SAM | $50M–$200M | $200M–$1B |
| Выручка/MRR | $10K–$50K/мес | $50K–$200K/мес |

Чек-лист выхода: паспорт; визуализация; таблицы TAM (оба метода), SAM, SOM; сравнение с порогами; выводы; все числа со ссылкой на источник прямо в тексте.

## Типичные ошибки
- Путать TAM и SAM; отдавать «TAM» как цель на 1–3 года.
- SAM без учёта реального ландшафта конкурентов и ограничений канала.
- Завышенный SOM: взять долю рынка «хотя бы 1%» вместо расчёта по конверсиям/мощности.
- Источники старше 2–3 лет; цифры без ссылки; разные определения рынка в числителе и знаменателе.
- Считать только в деньгах, не показав людей и единицы продукта.
- Начинать с таблиц вместо визуализации.
- Статичный «стоп-кадр»: объём на сегодня без CAGR рынка и прогноза доли канала — решение о входе зависит от будущего рынка, а не только текущего.
- Доля рынка как входной параметр модели (см. [[M-traction-model]]): доля — результат, а не вход.

## Вопросы, которые могут изменить решение
- Какова единица, которая ограничивает бизнес: спрос (воронка) или мощность (capacity)?
- Создаёт ли продукт новую категорию (нет рыночной статистики → только bottom-up и аналоги)?
- Какие сегменты недоступны по гео/регуляторике/платформе?
- Какой горизонт нужен решению: 1–3 года (SOM) или 3–5 лет (SAM)?
- Какие множители дают >50% неопределённости результата (в сценарии они первые)?
