# Dual-Track Agile: дискавери и поставка — два трека одной команды

## Когда применять
Команда работает по спринтам, но дискавери случается «когда-нибудь», бэкенд — «свалка идей», и спринты строятся из непроверенных фич.

## Суть
- **Discovery Track**: ответы «что строить» — интервью, прототипы, тесты ценности/юзабилити. **Delivery Track**: проверенные идеи превращаются в работающий продукт. Треки параллельны, ONE team (не «отдел исследований»).
- **Прогресс по критерию готовности**: идея попадает в поставку только после проверки ценности/юзабилити/осуществимости (definition of ready — проверенная, не «придуманная»).
- **Каденция**: в каждом спринте часть ёмкости — на дискавери-активности (интервью, тесты, прототипы), часть — на поставку проверенного.
- **Артефакты**: дерево возможностей, карта допущений, prototипы, эксперименты с критериями — всё короткоживущее и обновляемое.
- **Антипаттерн**: «спринт исследований» раз в квартал; «дискавери делает аналитик, поставка — разработка» (разрывает обучение).

## Как делать
1. Заложить в каждый спринт долю дискавери-ёмкости (обычно 20–30% для продуктовых команд).
2. Вести пайплайн идей: дерево возможностей → допущения → тесты → «готово к поставке».
3. Definition of ready = проверены ценность, юзабилити, осуществимость, бизнес-риск.
4. Ретро по обоим трекам: не только «что поставили», но и «что узнали».

## Подводные камни
- Дискавери без поставки = бесконечные исследования; поставка без дискавери = конвейер непроверенных фич.
- «Готово» без проверенных допущений — бэклог фикшна.
- Разные команды на треках — теряется «one team».
