# Эталон six-pager: структура и «хорошо и плохо»

## Когда применять
Перед сборкой или проверкой six-pager: нужна точка отсчёта «как выглядит правильный документ для комитета» —
по разделам, а не «в среднем». Карта — конспект структуры эталона и типовых ошибок каждого FAQ; полный эталонный
кейс не копируется, текст всегда пишется заново под конкретное решение (PRO-46, PRO-60).

## Суть
Эталон — это фиксированная структура из шапки, шести FAQ-разделов и таблицы приложений, где каждый раздел
отвечает на один вопрос принимающего решение и имеет свой «эталонный уровень» качества.

| Раздел | Эталонный уровень («хорошо») | Анти-эталон («плохо») |
|---|---|---|
| Шапка | запрос дословно, решение, получатель, дата и шаг процесса | шапка с «темой» вместо решения («апдейт по продукту») |
| FAQ-1 Анализ состояния | 3–5 фактов рынка с [C###]/[S###], таблица конкурентов «игрок → преимущество → риск для нас», вывод «что это меняет для решения» | история рынка на страницу, конкуренты «вообще», выводы без чисел |
| FAQ-2 Пользователи | 2–4 сегмента с болями по этапам пути и «что сдерживает», целевой фокус с цифрой перевода | персоны «все пользователи 18–65», боли без этапа пути |
| FAQ-3 Инициативы | ≥3 содержательно разных варианта, включая «оставить как есть» и «закрыть», сильные возражения, вклад в результат (сумма 100%) | одна «любимая» инициатива, возражения «нет ресурсов», вклад «примерно половина» |
| FAQ-4 Тактики | таблица Focus → Needs & desires → Solutions, каждая тактика привязана к потребности и ожидаемому эффекту | список фич без потребностей, «сделаем приложение» |
| FAQ-5 План и проверка | владельцы и команды по инициативам, сезонность, карточка проверки: база сравнения, срок, контрметрики, критерии | план «начнём в январе», проверка «посмотрим метрики» |
| FAQ-6 Метрики | бизнес- и продуктовые метрики с формулами, единицами, периодом, целевым значением и A/B-планом | «вырастим удержание и лояльность» без формул и целей |
| Приложения | Excel с листом «Ввод»: параметры редактируемые, расчёты на формулах | «мёртвые» числа в ячейках, допущение не пощупать |

Смысловые правила эталона: числа только с тегами [C###]/[S###] и в сверке с Excel; каждая инициатива имеет
возражения и измеримый вклад; возражение — сильное (может убить инициативу), а не формальное; раздел не
пересказывает соседний; объём ≈6 смысловых страниц, один экран — одна мысль.

## Процедура
1. Открыть шаблон `knowledge/templates/six_pager.md` и промпт `SIX_PAGER_PROMPT.md` — структура и правила уже там.
2. Для каждого FAQ сверить черновик с колонкой «хорошо» таблицы выше: отвечает ли раздел на свой вопрос.
3. Пройти колонку «плохо» как чек-лист антипаттернов: нашли — переписать раздел, а не «подшлифовать».
4. Сверить числа текста с Excel-приложениями и реестром утверждений (каждое значение → C###).
5. Прочитать документ глазами члена комитета: может ли он возразить по каждому разделу — и есть ли ответ в тексте.

## Шаблон / чек-лист
- [ ] шапка: запрос дословно, решение, получатель, дата;
- [ ] FAQ-1: факты с [C###]/[S###] + таблица конкурентов + вывод для решения;
- [ ] FAQ-2: сегменты с болями по этапам пути + целевой фокус с цифрой;
- [ ] FAQ-3: ≥3 варианта, включая «оставить как есть» и «закрыть», возражения, вклад = 100%;
- [ ] FAQ-4: тактики через Focus → Needs & desires → Solutions;
- [ ] FAQ-5: владельцы, сезонность, карточка проверки (база, срок, контрметрики, критерии);
- [ ] FAQ-6: метрики с формулами, единицами, периодом, целями;
- [ ] приложения: лист «Ввод», расчёты на формулах, числа совпадают с текстом.

## Типичные ошибки
- «Сборка» документа вставкой кусков 02/03/04/06: текст не отвечает на вопросы комитета, а пересказывает шаги процесса (PRO-46).
- FAQ-1 как «история рынка»: красиво, но не меняет решение.
- Возражения для галочки: «может не хватить ресурсов» не убивает инициативу и не требует ответа.
- Вклад инициатив «в сумме 130%»: доли не нормированы, приоритизация невозможна.
- Метрики без базы сравнения и срока — проверить их нельзя.
- Excel без формул: допущения не редактируются, доверие к цифрам падает.

## Вопросы, которые могут изменить решение
- Какой FAQ-раздел у нас сейчас weakest и что его усилит дешевле всего?
- Какое возражение комитета мы не смогли бы снять сегодняшним текстом?
- Какая цифра документа самая хрупкая и где её подтверждение в приложениях?
