# Эталон six-pager: как устроен документ комитета

## Когда применять
Когда six-pager собирается или проверяется: перед написанием раздела — чтобы знать эталонную структуру
«как должно быть»; после написания — как чек-лист против типовых отклонений. Карта — конспект структуры
эталона `knowledge/templates/SIX_PAGER_PROMPT.md` с разбором «хорошо/плохо»; сам эталон — канонический
промпт, его текст не дублируется здесь.

## Суть: скелет документа
Шесть FAQ-разделов, каждый отвечает на вопрос читателя-комитета; внутри — нумерованные подпункты 1.1, 2.1…,
обязательные таблицы и «Вывод (умозаключение)» отдельной строкой в конце каждого смыслового блока.

| FAQ | Вопрос читателя | Обязательные элементы по эталону |
|---|---|---|
| FAQ-1 Анализ текущего состояния | Что происходит на рынке, кто конкуренты, в чём вызов? | 1.1 обзор рынка: динамика диапазонами, буллет-прогноз по годам, 5–7 трендов, у каждого — «что это значит для продукта»; 1.2 таблица конкурентов: преимущества / механики роста / риски (Высокий–Низкий); «чего не хватает никому» = окно стратегии |
| FAQ-2 User Persona | Кто целевая аудитория и какие барьеры? | 2.1 таблица сегментов с фиксированными строками («Кто они?», «Что используют сегодня?», «С какими трудностями?»), сегментация по барьеру входа, не по профессии; 2.2 барьеры по этапам пути (привлечение → выбор → оплата → постоплатный опыт) + «что сдерживает от старта» |
| FAQ-3 Стратегические инициативы | Что предлагаем и почему именно это? | вводная: из каких вариантов выбрано (отсылка к red team); 3–4 инициативы-драйвера с конструкцией «Первый/Второй драйвер — …», «Ключевые направления», расчёт эффекта (формула → подстановка → результат) |
| FAQ-4 Тактики | Из чего конкретно состоит каждая инициатива? | матрица «Инициатива | Фокус | Потребности и ожидания пользователя | Решения (тактики)»: на инициативу 2–4 строки; тактики исполняемые, не лозунги |
| FAQ-5 План реализации | Как реализуем и в каком порядке? | вклад инициатив в результат в % (сумма 100%) с обоснованием весов; приоритеты тактик (высокий → базовый); тайминг к сезонам рынка; параллельные треки; решение D### с триггером стопа |
| FAQ-6 Метрики успеха | По чему меряем успех? | KPI в двух плоскостях: бизнес (выручка/MRR, платящие, конверсия, LTV/CAC) и продукт (активация, time-to-value, churn, CSAT/NPS); каждый KPI: база → цель к сроку → порог действия; контр-метрики по ударам red team |

## «Хорошо и плохо» на каждом FAQ

| FAQ | Хорошо | Плохо |
|---|---|---|
| FAQ-1 | тренд ведёт к следствию-возможности: «ATS-гейт стал стандартом → для нас это барьер входа, значит…»; конкуренты в таблице с оценкой риска; окно стратегии названо | история рынка на три страницы; тренды без «что это значит для нас»; конкуренты списком без рисков и без вывода |
| FAQ-2 | сегменты по барьеру входа («не знает, что так можно» vs «знает, но боится оплаты»); для каждого барьера — чем снимается продуктом | портреты «домохозяйка 35 лет»; сегменты по профессии/возрасту; барьеры без связи с механиками продукта |
| FAQ-3 | драйвер с расчётом: «конверсия 2,0→2,6% × трафик × ARPU = +X [C016]»; явная отсылка «вариант B отвергнут, потому что…» | «мы улучшим удержание» без формулы; инициативы без альтернатив и возражений; эффект «в воздухе» |
| FAQ-4 | тактика: «тариф Старт за 199 ₽: посадочная с калькулятором экономии, оплата картой и СБП» | тактика-лозунг: «развитие бренда», «улучшение UX»; матрица без потребностей |
| FAQ-5 | вклад: «тарифная лестница 45%, потому что закрывает два барьера из 2.2 и даёт X ₽ [C020]»; тайминг к сезону | вклад «примерно поровну»; план без дат и без решения D###; 100% не сходится |
| FAQ-6 | «конверсия в оплату: база 1,8% → цель 2,4% к 01.06 → порог действия 2,0%» | «вырастим выручку и лояльность»; KPI без базы и срока; нет контр-метрик |

## Типовые ошибки
- Склейка вместо письма: в FAQ-1 вставлен текст `02_situation.md` без перехода к эталонным подпунктам 1.1/1.2
  — документ не отвечает на вопросы комитета в их порядке.
- Числа без происхождения: «рынок 120 млрд» без [S###]/диапазона — читатель не может проверить.
- Вывод не отделён: смешаны данные, обоснование и вывод — комитет спорит с абзацем, а не со строкой
  «следовательно…».
- Скриншоты и картинки вместо таблиц — запрещены эталоном: доказательная форма комитета — таблицы и формулы.
- Вклад инициатив не сходится в 100% или веса без обоснования.
- Метрики без порога действия: не записано, при каком значении меняем план.
- RU и EN расходятся: перевод сделан «по смыслу раздела», цифры не совпадают — версия EN теряет доверие.

## Процедура (агент)
1. Перед написанием: прочитать эталон `knowledge/templates/SIX_PAGER_PROMPT.md` и эту карту; список
   обязательных элементов каждого FAQ — из таблицы «Суть».
2. Данные брать из 02/03/04/06 и реестра утверждений (каждое число → C###/S###), но писать разделы заново
   по скелету эталона, а не вставлять документы.
3. Каждый смысловой блок закрывать строкой «Вывод (умозаключение)» со словами «следовательно / это означает».
4. После сборки: пройти «Чек-лист самопроверки» эталона и таблицу «Хорошо/плохо» выше по каждому FAQ.
5. `pfs check --strict` — 0 ошибок; RU и EN версии синхронны (полный перевод, одинаковые цифры).

## Вопросы, которые могут изменить решение
- Какой FAQ самый слабый в текущем черновике — где комитет задаст вопрос, на который нет строки «следовательно»?
- Какая таблица отсутствует (конкуренты, сегменты, матрица тактик) и что она изменит в споре?
- Какое число без тега происхождения самое уязвимое и чем его подтвердить дешевле всего?
