# Базовая статистика для продуктовых решений

## Когда применять
Нужно оценить, случайна ли неделя «успеха», насколько можно доверять среднему, какой диапазон эффекта обещать бизнесу и чем рискуют решения «масштабировать / не масштабировать». Это фундамент под [[M-ab-testing]] и чтение любых метрик.

## Суть

### Зачем статистика продукту
Один удачный результат (например, 23 продажи за неделю при точке безубыточности 20) может быть чистой случайностью: при истинном среднем 20 вероятность такой недели ≈ треть всех недель, а при среднем 19 такая «удачная» неделя случается примерно в 27% случаев. Статистика переводит интуицию «повезло/не повезло» в управляемый риск: она не даёт гарантий, а даёт вероятности и позволяет заранее договориться, каким риском готовы жить.

### Описательные статистики: среднее, медиана, перцентили
- **Среднее** — сумма значений / число наблюдений; чувствительно к выбросам (один крупный чек сдвигает «средний чек»). Стабильно при больших n благодаря ЦПТ: среднее большой выборки распределено почти нормально, даже если сами значения — нет.
- **Медиана** — значение, делящее выборку пополам; устойчива к выбросам и тяжёлым хвостам; лучше описывает «типичного» пользователя (медианное время сессии, медианный чек).
- **Перцентиль pN** — значение, ниже которого лежит N% наблюдений. p90/p95/p99 времени ответа — стандарт для SLA: среднее может быть в норме при ужасных хвостах. Для медиан и перцентилей обычный t-test по «сырым» значениям не работает — используют бутстрэп-распределение квантиля.
- Правило: для денег и времени рядом со средним всегда смотреть медиану/перцентили; расхождение — признак асимметрии.

### Разброс: дисперсия и стандартное отклонение
- **Дисперсия σ²** — средний квадрат отклонений от среднего; **σ** — корень из неё, в тех же единицах, что метрика. Для доли (конверсии) σ² = p·(1−p), где p — baseline-конверсия.
- Разброс определяет «коридор нормальных значений» метрики и требуемую выборку: чем больше σ, тем шире ДИ и дольше любой тест. Снизить дисперсию можно линеаризацией ratio-метрик, стратификацией, CUPED ([[M-ab-testing]]).

### Распределения
- **Нормальное («колокол»)** вокруг истинного среднего: большинство значений рядом с центром, редкие отклонения по краям. Отсюда опасность «одного успеха»: значение из правого хвоста — нормальное событие, а не закономерность.
- Продуктовые метрики часто **асимметричны с тяжёлым правым хвостом** (чеки, время сессии, время ответа): среднее > медианы, отдельные выбросы доминируют. Тогда: лог-трансформация, сравнение по медианам/перцентилям, непараметрические критерии.
- Бинарные исходы (купил/не купил) при больших n дают нормальное распределение доли — это позволяет считать ДИ и выборку по формулам с p(1−p).

### Гипотезы и p-value
- **H₀** («эффекта нет», статус-кво) и **H₁** («эффект есть») формулируются до анализа. По умолчанию считаем H₀ верной, пока данные не дают оснований отвергнуть её.
- **p-value** — вероятность получить наблюдаемую или более экстремальную разницу, если на самом деле эффекта нет (H₀ верна). Малое p-value ≠ большой эффект: оно говорит о силе доказательства против H₀, а не о размере и не о вероятности успеха.
- Правило решения: p < α → отвергаем H₀ (эффект значим); p ≥ α → оснований отвергать нет (это не «эффект отсутствует», а «мы его не доказали»).

### Доверительный интервал (ДИ)
Диапазон, который с заданной вероятностью (обычно 95%) «накрывает» истинное значение. Для среднего:
```
ДИ = x̄ ± z · σ / √n
где x̄ — среднее по выборке; z — квантиль нормального распределения
(1,96 для 95%, ≈2,58 для 99%); σ — стандартное отклонение; n — размер выборки.
```
Ориентиры z-квантилей двусторонних интервалов: 90% → z ≈ 1,64; 95% → 1,96; 99% → 2,58. Для долей вместо σ/√n подставляют √(p·(1−p)/n).
Мини-пример: выборка {15, 17, 19}, σ=5, n=3 → x̄=17, ДИ = 17 ± 1,96·5/√3 ≈ 17 ± 5,66 = [11,3; 22,7].
- Ширину ДИ увеличивают: больший разброс σ, более строгий уровень z; уменьшают: большая выборка n. Среднее только сдвигает интервал, на ширину не влияет.
- Для эффекта A/B (разницы групп) интервал строится вокруг разницы; сравнение эффектов по сегментам удобно рисовать лесным графиком: точка = оценка эффекта, линия = 95% CI, вертикальная линия 0.
- Практика: **если нижняя граница ДИ ниже точки окупаемости (или ДИ накрывает 0) — устойчивого успеха нет**, даже если среднее выглядит хорошо. Решение по ДИ, а не по точке.
- Связь с p-value: 95% ДИ не включает 0 ⇔ p < 0,05. p-value отвечает «насколько сильны доказательства против H₀», ДИ — «в каком диапазоне может лежать реальный эффект». Бизнесу показывать оба.

### Два шаблона трактовки результата (для коммуникации)
- «Рост +6%, p-value = 0,10, 95% ДИ [−1%; +13%]» → ДИ накрывает ноль: реальный эффект может быть и отрицательным; оснований для масштабирования нет, возможен повторный тест с большей мощностью.
- «Платящие +10%, p-value = 0,04, 95% ДИ [+3%; +17%]» → значимо; даже худшая граница ДИ (+3%) выше бизнес-порога → масштабируем, отдельно проверив сегменты, где эффект не подтвердился (возможен баг или малая выборка сегмента).

### Ошибки I и II рода, α, β, мощность
- **Ошибка I рода (α, false positive):** «увидели» эффект, которого нет → масштабировали случайность. Стоимости: потраченные ресурсы, репутация, откат.
- **Ошибка II рода (β, false negative):** пропустили реальный эффект → недополученный рост, «похоронили» хорошую фичу.
- **α** — допустимая доля ложных тревог, фиксируется до теста: 5% — стандарт; 1% — когда цена ложного релиза высока (платежи, безопасность); до 10% — для MVP и «улучшалок», где важнее не пропустить.
- **β** — вероятность пропуска; обычно ≤ 0,2. **Мощность (power) = 1 − β** — вероятность поймать эффект, если он есть; стандарт ≥ 0,8.
- Баланс зависит от контекста: где пропуск дороже ложной тревоги (безопасность, критичные фичи) — жёстче β и выше мощность; где дорог откат/риск (платёжные фичи) — жёстче α. Выбор α/β — бизнес-решение, проговорённое до теста.
- Поднять мощность: больше выборка, дольше тест, ниже дисперсия (агрегация, линеаризация, CUPED), чувствительнее proxy-метрика.

### Практические ориентиры по объёму данных
- Точность оценки среднего растёт как √n: чтобы сузить ДИ вдвое, нужно вчетверо больше данных; при n ≈ 100 наблюдениях видны только крупные эффекты (порядка десятков процентов), мелкие сдвиги «тонут» в шуме.
- Выборка не лечит смещение: если данные собраны нерепрезентативно (отзываются только лояльные или недовольные), рост n не исправит вывод.
- Минимум серии наблюдений: любые выводы по одной неделе/одному запуску предваряются вопросом «как часто такое случается случайно».
- Асимметрия — повод сменить главную статистику: если среднее заметно выше медианы, headline-цифрой для «типичного пользователя» берут медиану, а среднее оставляют для суммарных эффектов (выручки).

### Корреляция ≠ причинность
- Совместное движение метрик (или связь в узле дерева метрик) может быть: совпадением, общей причиной (сезон, трафик), обратной причинностью (не «создавшие проект удерживаются лучше», а «удерживающиеся создают проекты»), смещением выборки.
- Причинность доказывается экспериментом ([[M-ab-testing]]) или квази-экспериментом (Diff-in-Diff, matching, синтетический контроль). Регрессия с контролем факторов показывает «корреляцию с поправкой», но не доказывает причинность.
- Правило для дерева метрик: стрелка «влияет» — либо доказанный A/B, либо гипотеза с планом проверки; коэффициенты связей измеряются, а не предполагаются.

### Коммуникация с бизнесом
- Говорить диапазонами: «с 95% уверенностью эффект лежит в [X; Y]», а не «выросло ровно на 7%».
- Всегда называть: уровень значимости, ширину ДИ, мощность, ограничения («значимо только на Android», «мощности не хватило — нужен ретест»).
- Анти-паттерны: «докручивание» теста до красивого результата; продажа значимого, но крошечного эффекта; обещание гарантий вместо вероятностей; игнор серых результатов.

## Процедура
1. Сформулировать H₀/H₁ и критерий решения (какой результат считаем успехом) до анализа.
2. Выбрать описательные статистики под природу метрики (среднее + медиана/перцентили для асимметричных).
3. Оценить разброс и «коридор нормальных значений» на истории 3–6 месяцев: текущее отклонение внутри коридора — не повод для разбора.
4. Посчитать ДИ (и p-value, если есть сравнение); проверить, пересекает ли ДИ 0 или бизнес-порог.
5. Для тестов: зафиксировать α/β/MDE, посчитать выборку ([[M-ab-testing]]); проверить, что мощность достаточна.
6. Сформулировать вывод в терминах риска: какой тип ошибки возможен, что мы теряем в каждом сценарии решения.
7. Проверить альтернативные объяснения (сезон, структура базы, внешние события) до причинной трактовки корреляции.

## Типичные ошибки
- Решение по одной точке/неделе без разброса и коридора нормы.
- Среднее без медианы на асимметричной метрике; p90 игнорируется при SLA-вопросе.
- «p маленький → эффект большой»; «p большой → эффекта точно нет» (вместо «не доказали»).
- ДИ накрывает порог окупаемости, но решение принято по среднему.
- α выбирается постфактум «чтобы прокрасилось»; продление теста ради значимости.
- Корреляция в отчёте превращается в «поэтому сделаем X» без проверки причинности.
- Сравнение долей с разными знаменателями/окнами; п.п. путают с %.
- «Докручивание» выборки после результата (выбор более удачного окна/сегмента постфактум) — тот же p-hacking, что и продление теста.

## Вопросы, которые могут изменить решение
- Какова вероятность увидеть такой результат при верной H₀, и какую мощность имеет сравнение?
- Внутри ли коридора нормальных значений текущее отклонение и нет ли сезонного совпадения?
- Какова цена ошибки I рода vs II рода для этого конкретного решения?
- Нижняя граница ДИ выше точки безубыточности/порога качества?
- Чем объясняется связь, кроме предполагаемой причины, и как её проверить дешевле эксперимента?
