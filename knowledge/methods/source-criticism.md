# Критика источников и аналитических отчётов

## Когда применять
Любая внешняя цифра, прогноз или тезис идёт в вывод, модель или рекомендацию: отчёт консалтинга/вендора/госструктуры, бенчмарк, размер рынка, тренд, ответ LLM, слова пользователя о своих метриках. Правило: **отчёт — гипотеза, а не факт**, пока не проверен и не триангулирован.

## Суть
### Шкала достоверности (Evidence grade)
| Класс | Критерий | Confidence | Как использовать |
|---|---|---|---|
| **A** | Первичный источник или данные проекта с раскрытой методикой; подтверждён минимум 2 независимыми источниками (триангуляция); возраст в допуске; сопоставим по сегменту, периоду, определению | High | Опора решения |
| **B** | Авторитетный вторичный источник с методологией (Tier-1 консалтинг, регулятор, отчёт с раскрытой методикой); подтверждён частично или есть оговорки по сопоставимости | Medium | Опора с диапазоном и оговоркой |
| **C** | Единственный источник, пересказ, нет методологии, интерес спонсора, возраст на границе допуска, экспертная оценка без проверки | Low | Только гипотеза/ориентир; обязательны sensitivity и план проверки |
| **D** | Не проверяется или есть red flags (нет первоисточника/определений, «internal analysis», слишком точные или ровные цифры без интервала), либо допущение агента без источника | Very low | Не основание для решения; только явно помеченное допущение |

**Правило слабого звена:** класс вывода не выше класса самого слабого критичного входа. Если решение чувствительно к входу класса C/D — сначала проверка или сбор данных.

### Типы источников и главный риск
| Тип | Плюсы | Что проверить в первую очередь |
|---|---|---|
| Государственные/международные (OECD, UNCTAD, Росстат, институты статистики) | нейтральность, описанная методология, сопоставимость стран | лаг данных (6–12 мес.), политическая оптика |
| Отчёты IT-компаний | сигналы раньше всех (телеметрия) | нет методологии; продуктовые изменения создают «тренд»; интерес в благоприятной трактовке |
| Консалтинг (McKinsey, BCG, Deloitte, PwC) | Tier-1 раскрывает метод | слой интерпретаций; скрытый заказчик/спонсор; нишевый консалтинг слабее |
| Соло-аналитики | личное видение | cherry-picking, конфликт интересов |
| Банковский ресёрч, регуляторы (SEC, ECB, ЦБ РФ) | сделки/регуляторная база | финансовая оптика |
| Публичная отчётность (10-K, квартальные) | финансово проверена | может скрывать неудобное; определения метрик свои |
| VC/инвест-отчёты | быстрые сигналы рынка | узкий фокус на венчуре, интерес фонда |

## Процедура
Проверка в пяти уровнях (для каждого отчёта/источника):
1. **Цель.** Зачем анализируем (выбор сегмента, прогноз рынка, проверка гипотезы), для кого вывод, горизонт, география.
2. **Тип и автор.** Определить тип по таблице и интерес автора; поднять на первый план соответствующие проверки.
3. **Source integrity:** автор и компетенции; единичный или серийный отчёт; спонсор и бенефициар; конфликт интересов (вендорская принадлежность, партнёрства).
4. **Method integrity:** определения терминов («пользователь», «активный», «рынок AI»); тип данных — опрос (смещение выборки, социальная желательность), статмодель (допущения, экстраполяция), транзакции/телеметрия (неполнота), desk research (вторичные источники), смешанный (лучше всего); выборка (география, отрасли, роли респондентов, веса, период сбора); показатели Accuracy/Credibility/Timeliness/Coherence.
5. **Claim integrity:** выбрать 3–7 ключевых тезисов/цифр; подтвердить вторым независимым источником; sanity-checks:
   - доли ≤ 100%, части суммируются в целое;
   - валюта и год совпадают;
   - порядок величины (рынок $5 млрд против $5 трлн);
   - подразумеваемый рост: `CAGR = (V_конец / V_начало)^(1/n) − 1` — реалистичен ли;
   - «отчёт 2026» ≠ «данные 2026»: проверить дату сбора.
6. **Присвоить класс A–D** по шкале; сопоставить с возрастом: быстро меняющиеся величины (CAC, CPI, retention) — не старше 24 месяцев; стабильные (маржа, долгосрочный LTV) — 3–5 лет; рыночные данные для market-sizing — не старше 2–3 лет (правила скиллов).
7. **Триангуляция:** минимум 2–3 независимых источника разных типов (госстатистика + отчёт + первичные данные); для бенчмарков — 3, разброс более 30% требует осторожности. Зависимые источники (пересказы одного отчёта) считаются за один.
8. **Зафиксировать происхождение** (ниже) и принять решение по классу.
9. **Передать вывод** с оговорками: что подтверждено, что гипотеза, что надо проверить.

### Red flags и green flags
| Red flags | Green flags |
|---|---|
| нет определения рынка/категории | раздел Methodology/Appendix |
| цифры без ссылки на первоисточник | словарь терминов |
| слишком точный прогноз («+14,7%») без доверительного интервала | раздел Limitations |
| вендорский отчёт под видом независимого | история обновлений с описанием правок |
| нет географии и профиля респондентов | описаны взвешивание и очистка данных |
| «internal analysis» как единственный источник | для прогнозов — сценарии, диапазоны, драйверы |
| обновления без указания смены методологии | раскрыто спонсорство |
Дополнительно: narrative fallacy (выводы сшиты под одну историю, нет сценариев и неопределённости); sponsor bias; терминологическая неопределённость; ровные числа.

Когнитивные ловушки аналитика: confirmation bias, overconfidence, survivorship bias, authority bias (вера гуру); anchoring и curse of knowledge при ревью собственной работы.

## Шаблон / чек-лист
**Паспорт источника:** автор · тип · серия (единичный/серийный) · спонсор · год публикации · дата сбора данных · география · определение ключевых терминов.

**Запись о происхождении (Evidence Log) — одна строка на утверждение:**
| Поле | Что записать |
|---|---|
| ID | E-001… |
| Утверждение | значение, единица, период, сегмент/география, определение |
| Источник | издатель, название, год, страница/раздел, URL; первичный или вторичный |
| Метод и спонсор | как получено, кто финансировал |
| Даты | публикации · сбора данных · когда прочитано нами |
| Триангуляция | ID подтверждающих записей или «нет» |
| Класс A–D и Confidence | + почему |
| Использование | где в выводе/модели; чувствительность результата |
| Следующая проверка | что и кто сделает до решения |
Особые случаи: **расчёт агента** — записывать формулу, входы с их ID и класс по правилу слабого звена; **слова пользователя о метриках** — «данные пользователя», класс по тому, можно ли проверить (выгрузка, дашборд); **ответ LLM без источника** — класс D; ссылку не придумывать, указать, что нужен поиск.

В тексте вывода: ссылка ставится прямо на число (гиперссылка или ID записи), а не списком в конце; рядом — год и класс.

Таблица ключевых тезисов отчёта: тезис · статус (подтверждён/нет) · подтверждение · класс · примечание.
Чек-лист: источник проверен · метод понятен · ключевые цифры триангулированы · нет явного конфликта интересов · ограничения раскрыты · определения совпадают с нашими.

## Типичные ошибки
- Брать цифру из заголовка отчёта и не смотреть методологию.
- Сравнивать цифры из разных отчётов с разными определениями рынка.
- Считать три пересказа одного отчёта тремя источниками.
- Не проверять дату сбора, путая её с датой публикации.
- Брать вендорский отчёт как нейтральный и точные прогнозы без интервала.
- Записать допущение в модель без пометки, что это допущение.
- Оставить вывод класса A при входах класса C.

## Вопросы, которые могут изменить решение
- Чувствителен ли итоговый вывод к этой цифре? Если нет — не тратить время на углубление.
- Кто выиграет, если это число верно (спонсор, вендор, автор)?
- Есть ли первичные данные у нас или у пользователя, которые заменят вторичный источник?
- Совпадает ли определение метрики/рынка в источнике с нашим?
- Сколько независимых подтверждений достижимо по времени и бюджету?
