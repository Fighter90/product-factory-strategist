# Ценообразование тарифной лестницы

## Когда применять
Когда у продукта больше одного тарифа или планируется ввести тарифы: раскладка «Free → Base → Pro → Enterprise»,
выбор value metric, расчёт ARPU-микса, проверка того, что freemium сходится, и решение о годовых планах.
Карта — мост между [[M-monetization]] (выбор модели) и [[M-unit-economics]] (проверка сходимости).

## Суть
Тарифная лестница — это не «несколько цен», а механизм распределения базы по цене: **ARPU = Σ(цена тарифа × доля
тарифа в базе)**. Отсюда три следствия.

1. **ARPU всегда взвешенный.** Средний по тарифам без весов — ложь: база из 90% Free и 10% Pro не даёт
   «среднего между 0 и 1000». Считайте ARPU по фактическому миксу и следите за его дрейфом по когортам.
2. **Шаг лестницы покупают ценностью, а не фичами.** Каждый следующий тариф оправдан качественным скачком:
   лимиты снимают реальную боль масштаба (объём, места, автоматизация, поддержка). Правило больших шагов:
   цена ×2–3 за заметно новую ценность; мелкие шаги по 10–15% учат клиента выбирать самый дешёвый тариф.
3. **Value metric — то, за что платят.** Метрика должна расти с ценностью клиента (места, пользователи,
   сделки, объём данных), предсказуемо для покупателя и легко измерима. Ошибка в value metric ломает лестницу:
   клиенты платят не за то, что им дорого.

**Freemium-конверсия.** Free-тариф — канал привлечения, а не благотворительность: его себестоимость несут все.
Плата за вход сходится, только если `CR_free→paid` выдерживает нагрузку: `CAC_платящего = CAC_привлечения /
CR_free→paid` (привлечение за 300 при конверсии 5% → платящий стоит 6000). Минимальная доля платящих,
при которой freemium живёт: `доля_платящих_min ≈ стоимость_обслуживания_юзера / ARPPU`. Проверяйте её на
ретро-когортах до того, как масштабировать привлечение.

**Годовые планы.** Годовая подписка — это предоплата: снижает churn в первые 12 месяцев, ускоряет cash-flow,
но продаётся со скидкой (типично 15–20%, то есть «2 месяца в подарок»). Влияние на экономику двоякое:
LTV на пользователя растёт (низкий ранний churn), ARPU в месяц падает (скидка), а дисконт каннибализирует
месячный план — часть базы, которая и так осталась бы, платит меньше. Годовой план выгоден, когда
`скидка < экономия на churn + стоимость капитала`; проверяется A/B-тестом цены и сравнением retention
годовых и месячных когорт.

## Процедура (агент)
1. Собрать фактический микс: доли тарифов, ARPPU по тарифам, CR free→paid по когортам — каждое число
   с источником и датой (`pfs claim add --kind fact`).
2. Посчитать ARPU-микс и CAC платящего; сравнить payback платящего с целевым горизонтом.
3. Проверить value metric: за что реально платят лучшие клиенты; растёт ли счётчик с их ценностью.
4. Спроектировать шаги лестницы: на каждый переход «что болит на предыдущем тарифе → что покупают на следующем».
5. Модель в [[M-traction-model]]: три сценария микса (пессимистичный / базовый / оптимистичный по конверсии
   и доле годовых) — см. [[M-scenario-modeling]].
6. Проверить каннибализацию: кто на новом тарифе был бы платящим на старом ([[M-cannibalization]]).
7. План проверки: A/B цены и годовой скидки, метрики — CR free→paid, ARPU, payback, churn по тарифам.

## Шаблон / чек-лист
- [ ] ARPU посчитан взвешенно, по когортам, а не как среднее по прайс-листу;
- [ ] у каждого перехода лестницы названа боль предыдущего тарифа и купленная ценность;
- [ ] value metric один, предсказуемый, растёт с ценностью клиента;
- [ ] CAC платящего = CAC / CR free→paid, и он окупается в целевой горизонт;
- [ ] доля годовых планов и размер скидки — гипотеза с A/B-планом, а не «так у конкурентов»;
- [ ] каннибализация годовым планом месячного оценена в модели.

## Типичные ошибки
- «Средний ARPU по тарифам»: усреднение прайс-листа вместо взвешивания по базе.
- CAC без конверсии: привлечение стоит 300, платящий — 6000; сравнение LTV с первым числом.
- Лестница из флажков: «Pro отличается поддержкой» — не скачок ценности, а повод остаться на Base.
- Годовая скидка как акция без расчёта: каннибализация месячного плана съедает выигрыш в churn.
- Слишком много тарифов: выбор утомляет, ARPU-микс неуправляем; 3–4 ступени — потолок для self-serve.

## Вопросы, которые могут изменить решение
- Какая доля базы вообще готова платить (размер «платящего ядра»)?
- Не съест ли годовой план месячный без выигрыша в retention?
- Какой value metric переживёт рост продукта на 2 года вперёд?
