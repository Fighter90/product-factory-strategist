# Анализ трендов и сценарное планирование

## Когда применять
«Куда движется рынок?», «что будет через 3–5 лет?», «хайп это или тренд?», «какие сценарии заложить в стратегию и модель роста?». Метод даёт отличать сигналы от хайпа и превращать будущее в набор проверяемых сценариев с сигналами и действиями.

## Суть
| Понятие | Определение |
|---|---|
| Сигнал | ранний индикатор, аномалия, «зерно» тренда |
| Хайп | всплеск интереса без гарантии устойчивости (NFT, метавселенная) |
| Тренд | устойчивая последовательность с чётким направлением |
| Инсайт | влияние тренда на ваш продукт |
| Мегатренд / драйвер | фундаментальная сила, движущая множество трендов (цифровизация, демография, климат) |
| Образ будущего | представление о будущем при развитии трендов |
Типы по PESTLE: политические, экономические, социальные, технологические, юридические, экологические ([[M-external-environment]]).

**Три горизонта стратегии (McKinsey):** Run — 1–3 года (текущая прибыль, эффективность); Change — 2–5 лет (будущая прибыль, адаптация); Disrupt — 3–10 лет (прорыв, новые рынки).

**Когда не прогнозировать:** результат не влияет на решение; цена ошибки меньше цены промедления; скорость изменений выше скорости планирования; пространство решений слишком сложно (больше 3 переменных).

### Шесть методов + дополнение
| Метод | Суть | Когда выбирать |
|---|---|---|
| Horizon scanning | поиск сигналов: научные статьи, стартапы, патенты, новости | рано увидеть тренды, пополнять карту трендов |
| Delphi | анонимные раунды опроса экспертов (обычно 2–3), результаты показываются между раундами → консенсус | мало данных, нужна экспертная оценка параметра |
| Scenario planning | 2–4 образа будущего с собственной логикой («что может быть», не «что будет») | высокая неопределённость, стратегия на 3–10 лет |
| Diffusion models | скорость внедрения: Bass, Logistic, Gompertz; S-кривая «старт → ускорение → плато» | прогноз принятия технологии/продукта |
| Backcasting | от желаемого будущего к настоящему («если в 2030 мы лидеры, что делаем сейчас?») | есть чёткая цель, нужен путь (пример Amazon — future press release) |
| Prediction markets / crowd forecasting | торговля исходами, коллективная оценка (Metaculus, PredictIt) | сверка собственных вероятностей |
| System dynamics | задержки и петли обратной связи (Forrester) | сложные системы с запаздыванием |

## Процедура
### A. Сценарный анализ, простой метод (10 шагов)
1. Уточнить тренд, рынок, горизонт.
2. Выразить в измеримой величине (%, млн, индекс).
3. Baseline: текущее состояние и траектория стабильности.
4. Сценарий ускорения (благоприятные условия).
5. Сценарий отката/остановки (неблагоприятные).
6. Драйверы/триггеры каждого сценария.
7. Сигналы: что наблюдать, чтобы понять, какой сценарий идёт.
8. Адаптация продукта и стратегии.
9. Разделить действия: **no-regret moves** (при любом исходе) и **option bets** (ставки на исход).
10. Оценить текущую готовность продукта.

### B. Матрица 2×2
1. Выбрать два тренда — наиболее влияющих и наименее связанных между собой.
2. Оси — крайние значения (High/Low) для каждого.
3. Четыре квадранта = четыре образа будущего; дать каждому имя и 3–5 признаков.
4. Далее шаги 6–10 простого метода для каждого квадранта (кратко).

### C. Отличить тренд от хайпа (на основе определений скилла)
Собрать сигналы в журнале (источник, дата, класс достоверности по [[M-source-criticism]]) → кластеризовать → проверить: есть ли несколько независимых сигналов в разных источниках и периодах, видно ли направление и реальное принятие (деньги, поведение, регуляция), а не только упоминания. Нет — оставить как сигнал/хайп под наблюдением. Тренд → записать инсайт для продукта.

### D. Delphi (практическая схема)
Сформулировать конкретный измеримый вопрос → подобрать разнородных экспертов → раунд 1: анонимные оценки и обоснования → сводка (медиана, разброс, аргументы) → раунд 2 с учётом сводки → при необходимости раунд 3 → зафиксировать итоговый диапазон и несогласных. Результат — диапазон для допущения модели, класс не выше B.

### E. Backcasting
Описать желаемое состояние на дату измеримо → определить необходимые условия и способности на промежуточных этапах → сравнить с текущим → список разрывов и первых шагов → привязать к roadmap и рискам.

### F. Интеграция с моделью и стратегией
Сценарии → три сценария трекшн-модели (pessimistic/base/optimistic) и внешние факторы эффектов ([[M-traction-model]]); сигналы → триггеры пересмотра roadmap; no-regret → в ближайший квартал; option bets → малые ставки с критерием остановки ([[M-risks]]). Диффузия (стандартная логистическая форма, не из скилла): `N(t) = K / (1 + e^{−r(t−t0)})`, где K — потолок насыщения, r — скорость, t0 — точка перегиба; параметры брать из аналогов с классом достоверности.

### Критерии качества сценариев
| Критерий | Смысл |
|---|---|
| Plausibility | правдоподобен, опирается на факты |
| Internal consistency | нет внутренних противоречий |
| Distinctiveness | сценарии реально различаются |
| Decision relevance | влияют на решения |
| Traceability | прослеживаются до драйверов и сигналов |
| Testability | есть наблюдаемые проверяемые сигналы |

## Шаблон / чек-лист
Паспорт: тренд · горизонт · рынок · измеримая величина · источники.
Карта трендов: сигнал | хайп | тренд | мегатренд.
Сценарии:
| Сценарий | Допущения/драйверы | Измеримая величина (значение, год) | Сигналы-индикаторы | Действия no-regret | Option bets | Вероятность/класс достоверности |
|---|---|---|---|---|---|---|
Таблица сигналов: сигнал · источник · дата · что означает · порог реакции.
Дисциплина: прогнозировать регулярно малыми порциями (ежемесячно), приоритизировать значимые тренды, документировать гипотезы и проверять через 3–6 месяцев, проводить ретроспективы прогнозов.

## Типичные ошибки
- Принять хайп за тренд по числу упоминаний.
- Единственный «прогноз» вместо набора сценариев; сценарии, отличающиеся только оптимизмом.
- Слишком длинный горизонт (за 10 лет слишком много неизвестного) без промежуточных сигналов.
- Confirmation bias, overconfidence, survivorship bias, вера авторитету; игнорирование чёрных лебедей.
- Сценарии без привязки к решениям («картинки будущего»).
- Нет сигналов и дат пересмотра.

## Вопросы, которые могут изменить решение
- Какое решение изменится, если сценарий A, а не B? Если никакое — прогноз не нужен.
- Какие два фактора определяют исход сильнее всего и насколько они независимы?
- Что нам дешевле: подстроиться под сценарий или повлиять на него?
- Какие сигналы мы сможем реально отслеживать и кто отвечает?
- Какой горизонт нужен: Run, Change или Disrupt?
