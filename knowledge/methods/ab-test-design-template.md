# Шаблон дизайна A/B-теста

## Когда применять
Перед запуском любого A/B-теста, когда нужно превратить размытую идею «давайте попробуем» в проверяемый документ с метриками, порогами решений и расчётом выборки. Шаблон — это договор команды с собой: все решения о порогах, длительности и действиях фиксируются **до** старта, чтобы после набора данных не подгонять критерии под результат. Методологическая база (статистика, критерии, ловушки) — в карте `M-ab-testing`; этот шаблон — рабочий скелет конкретного эксперимента, который заполняется по секциям сверху вниз и живёт одним документом.

## Как пользоваться шаблоном
Заполняйте секции по порядку: Бизнес → Метрики → Механизм решений → Реализация → Проверка гипотез. Секция «Результаты» заполняется только после набора данных — заранее в неё пишут лишь структуру. Правило зрелости: если какой-то раздел не получается заполнить без «потом уточним» — эксперимент запускать рано. Квадратные скобки — места для подстановки; текст в скобках — подсказка, что и в каком виде писать. Готовый документ ревьюят аналитик + продакт: аналитик проверяет статистику (MDE, выборка, критерии), продакт — бизнес-логику и цену ошибки.

## Связь с процессом pfs
Шаблон — основной артефакт шага `validation` (пфс-шаг 9): секция «Бизнес» вырастает из гипотез шага `options`, метрики — из `M-success-metrics`, расчёт выборки — из `M-quant-methods`, а секция «Выводы» фиксируется в `pfs validation` и журнале решений (`pfs decision add`). Для неклассических случаев (сетевые эффекты, офлайн, «уже выкатили») — альтернативы в `M-ab-testing`, раздел «когда классика невозможна».
