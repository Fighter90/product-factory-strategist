# AI в исследованиях

## Когда применять
Когда нужно ускорить рутину исследования (транскрипция, первичное кодирование, черновики гайдов и гипотез, поиск по базе интервью),
но сохранить качество выводов. Главный вывод занятия: ответы ИИ нужно проверять собственными данными, иначе это красивый текст.
Курс ставит AI после тем про дизайн сессий и хранение данных намеренно: без базового понимания метода нельзя оценить качество вывода модели.

## Суть
LLM показывают три способности «интеллекта»: видеть паттерны, предсказывать, строить модели — но без фактов в окне контекста
они дополняют пробелы правдоподобной выдумкой. Поэтому ключевая практика — **context engineering**: подавать модели исходные данные и
ограничивать её ими.

- **Базовый промпт:** `[Роль] + [Задача] + [Контекст/детали] + [Формат/ограничения]`. Семь правил: ясность и краткость; роль; контекст
  (цель, ограничения, аудитория); формат результата; пошаговые инструкции для сложных задач; примеры; разделители и структура.
- **Reasoning-модели:** «думают» шаги внутри, ходят во внешние источники, показывают, на что опирались. Промпт для них короче и точнее,
  длинные ролевые инструкции и «сначала сделай то, потом это» могут мешать. Преимущество: по цепочке рассуждений и источникам видно причину ошибки
  и можно убрать неподходящий источник или поправить запрос.
- **Три слоя контекста:** System (роль и правила, читается первой), Session (задача и уточнения), Extended (выдержки из базы интервью, тикетов, метрик).
- **RAG (retrieval-augmented generation):** искать релевантные куски → передавать их в промпт → генерировать ответ по ним. Пример
  параметров из занятия: чанки около 800 токенов, эмбеддинги, порог сходства ~0,75, топ-5 кусков; чанк >2000 токенов обрезается; без
  метаданных поиск тянет нерелевантное; сканы-PDF без текстового слоя дают пустоту. «Контекст дороже токенов»: лучше час почистить данные.
- **Ассистент:** модель + системный промпт + база знаний (+ инструменты). Для анализа конкретных интервью веб-доступ лучше отключать (иначе «выбросы»);
  для обзора рынка — включать. Внутренние данные компании во внешние сервисы не загружать без разрешения службы безопасности.

## Процедура

### 1. Решить, что делегировать
| Задача | Делегировать ИИ? | Условие |
|---|---|---|
| Расшифровка аудио/видео | Да | Выборочная сверка с записью, имена и термины проверять |
| Первичное кодирование открытых ответов | Да, с закрытым списком тегов | Запретить новые теги; «нет подходящего тега» — допустимый ответ; сверка части ответов человеком |
| Суммаризация интервью | Да | Каждый тезис с цитатой и тайм-кодом/ссылкой на файл |
| Черновик гайда интервью/теста, гипотез, исследовательских вопросов | Да | Исследователь правит; проверка на наводящие вопросы |
| Преобразование размытого запроса («улучшим онбординг») в исследовательские вопросы и гипотезы | Да как черновик | Команда проверяет полноту: покрыты ли все «где ломается — почему» |
| Поиск закономерностей в корпусе | Да как помощь | Утверждение подтверждено минимум в N цитатах, проверено вручную |
| Кластеризация идей/стикеров | Да | Человек утверждает группы |
| Обзор рынка, конкурентов | Да с веб-доступом | Ссылки на источники, проверка ключевых фактов ([[M-source-criticism]]) |
| Формулировка итогового инсайта и рекомендации | Нет — только черновик | Решение и ответственность у человека |
| Оценка распространённости, спроса, готовности платить, размера сегмента | **Нет** | Только данные реальных респондентов и статистика |
| Роль респондента (синтетические пользователи) | Только по [[M-synthetic-respondents]] | Метка, не как доказательство |
| Оценка эмоций «из текста» как факта | Осторожно | Эмоция — гипотеза, пока нет видео/голоса/наблюдения |
| Работа с персональными данными | Только во внутреннем контуре | Согласие, анонимизация |

### 2. Выбрать модель и режим
Короткая точная задача → reasoning-модель, простой промпт. Для сравнения качества — одну задачу на reasoning-модели и ту же на обычной LLM, сравнить (учебный приём курса: два кейса — «низкая вовлечённость новой фичи» и «размытый онбординг» — решаются на разных моделях, чтобы увидеть разницу в планировании исследования). Включать/выключать веб-доступ осознанно; проверять лимиты контекста (токены, размер файла) в справке сервиса — надёжный приём: спросить лимиты у самой модели или посмотреть официальную таблицу. В конструкторах ассистентов различать UI-обёртку (быстро собрать и поделиться) и программный доступ через API (версионирование, логи, контроль) — второй нужен, когда ассистент часть процесса, а не разовая игрушка.

### 3. Собрать контекст
Подготовить исходники: чистые тексты (не сканы), метаданные (дата, сегмент, метод, респондент без ПДн). Разбить крупные файлы на части.
Минимум три разнородных источника для ассистента (интервью, тикеты, аналитика). Системный промпт: роль, запрет выходить за CONTEXT,
формат ответа, требование цитат с названием файла.

### 4. Запросить с форматом доказательности
Требовать: тезис → дословная цитата → файл/позиция → уровень уверенности; «если данных недостаточно — так и скажи»; отдельно «факт из источника»
и «интерпретация модели».

### 5. Проверить (валидация — обязательна)
1. Каждая цитата существует в исходнике (поиск по тексту).
2. Выборочная перепроверка человеком (ориентир карты: 10–20% тезисов, больше для критичных выводов).
3. Повторный прогон другой формулировкой/моделью; расхождения разобрать.
4. Для кодирования — двойное кодирование части ответов и сравнение (доля совпадений).
5. Посмотреть «рассуждение» и список источников; найти и убрать нерелевантный источник.
6. Выводы, которые модель сформулировала без цитаты, — понизить до гипотез.

### 6. Сохранить результат с происхождением
В базу знаний ([[M-ux-backlog]]) записывать, что получено с участием ИИ: модель, дата, версия промпта, исходные файлы, кто проверил.

## Шаблон / чек-лист

**Шаблон промпта для тегирования (из занятия, адаптация):**
```
### ЗАДАЧА
Протегируй открытый ответ, выбрав теги ТОЛЬКО из списка. Если ничего не подходит — "нет подходящих тегов".
### КОНТЕКСТ
Ты — ассистент по анализу обратной связи. Опирайся только на текст ответа.
### СТРУКТУРА ОТВЕТА
Таблица: ответ | тег | краткое обоснование (цитата из ответа)
### СПИСОК ТЕГОВ
["интерфейс","баги","цена","скидка"]
```

**Категории инструментов (из списка курса; названия — примеры на момент составления, проверять актуальность и доступность в регионе):**
универсальные чат-LLM (ChatGPT, Claude, Gemini, Qwen, DeepSeek, GigaChat, YandexGPT); LLM с веб-поиском и источниками (Perplexity); генерация и
правка изображений; «чат с таблицами/данными» (CSV/Excel); презентации; схемы и майндкарты (Napkin, Mermaid, draw.io, Markmap); видео-аватары;
no-code автоматизации (n8n, Activepieces); IDE с ИИ; транскрибаторы (Fireflies, tl;dv, российские сервисы); конструкторы ассистентов с базой
знаний (GPTs, Gems, Dify, NotebookLM, Spaces). Ассистент = системный промпт + (опционально) база знаний + (опционально) инструменты.

**Чек-лист «можно ли использовать вывод ИИ»:** есть ссылки на исходники; цитаты сверены; не содержит оценок распространённости без данных;
расхождения при повторном прогоне объяснены; пометка «с участием ИИ» сохранена; ПДн не вышли за контур.

## Типичные ошибки
| Ошибка | Последствие | Исправление |
|---|---|---|
| Принимать вывод без источников | Выдумка в отчёте | Требовать цитаты и сверять |
| Загрузить 50 страниц в окно | Дорого и обрезается | Чанкование, поиск по базе |
| Чанки слишком большие, нет метаданных | Теряются факты, шум | Нарезка, теги, метаданные |
| Индексировать сканы | Пустой текст | Распознавание текста заранее |
| Веб-доступ включён для анализа своих интервью | «Выбросы» из внешнего мира | Отключить |
| Длинные ролевые промпты для reasoning-моделей | Хуже результат | Коротко и конкретно |
| Открытые теги вместо закрытого списка | Невозможно агрегировать | Закрытый список |
| ИИ как «респондент» без метки | Подмена доказательств | См. [[M-synthetic-respondents]] |
| Внутренние данные во внешнем сервисе | Утечка | Внутренний контур или анонимизация |
| Выдавать вывод модели за результат исследования | Потеря ответственности | Человек подписывает вывод |

## Вопросы, которые могут изменить решение
- Какие данные (интервью, тикеты, метрики) есть и можно ли их передавать модели? Если нет — только черновики и шаблоны.
- Что должно считаться доказательством в итоговом документе? Если только данные респондентов — ИИ ограничен вспомогательной ролью.
- Какова цена ошибки в выводе (маркетинговая гипотеза или инвестиционное решение)? От неё зависит доля ручной проверки.
- Нужен ли воспроизводимый процесс (версия промпта, модель, дата) для аудита?
- Какие инструменты разрешены в организации?
