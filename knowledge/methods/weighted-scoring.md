# Взвешенный скоринг: веса, шкалы, фильтры

## Когда применять
Когда нужно сравнить содержательно разные варианты (инициативы, решения, рынки) по нескольким критериям
и получить прозрачное основание для выбора. Скоринг — инструмент **структурирования спора**, а не «объективная
истина»: полезен до выбора руководителем ([[M-decision-daci]] — решение всё равно за человеком).

## Суть
Взвешенный скоринг = фильтры (дисквалификация) + критерии с весами + шкалы + числа из расчётов,
которые сходятся с базой знаний (PRO-51).

Порядок применения:
1. **Фильтры до скоринга:** жёсткие условия отсева («нет владельца», «противоречит стратегии», «юнит-экономика
   отрицательна при реалистичном миксе», «нельзя проверить за квартал»). Вариант, проваливший фильтр, не
   участвует в скоринге — так таблица не разбухает и слабые варианты не «дотягивают» весами.
2. **Критерии:** 4–6, каждое — вопрос, на который вариант отвечает числом или экспертной оценкой с классом
   достоверности. Типовые: вклад в целевую метрику (из модели [[M-traction-model]]), цена/ресурсы, время до
   эффекта, риск (обратимость), уверенность в гипотезе.
3. **Веса:** сумма 100%; веса назначает принимающий решение (не автор расчёта) до проставления оценок —
   это снимает «подгонку весов под любимца».
4. **Шкалы:** единая шкала для всех вариантов (1–5 или 1–10); у шкалы — якоря («5 = +5% к NSM по базовому
   сценарию с классом A–B»); оценки с обоснованием, не «просто число».
5. **Расчёт:** `Score = Σ(оценка × вес)`; рядом — обязательно сырые оценки по критериям: решение не по сумме,
   а по профилю (вариант может проигрывать в сумме, но выигрывать по критически важному критерию).

Связь с расчётами (PRO-51): критерии «вклад в метрику» и «окупаемость» заполняются из проверенных расчётов
([[M-unit-economics]], [[M-traction-model]]): ARPU — средневзвешенный по миксу тарифов, CAC ≠ 0, эффекты —
с учётом каннибализации и эластичности. Число в скоринге противоречит базе знаний — скоринг недействителен,
чинить расчёт, а не таблицу.

## Процедура
1. Сформулировать вопрос сравнения: «что выбираем и что значит "лучше"» — критерии из целевой метрики.
2. Прогнать варианты через фильтры; дисквалифицированные — с причиной, они остаются в документе как рассмотренные.
3. Назначить веса (принимающий решение, до оценок); сумма весов = 100%.
4. Заполнить оценки с якорями и обоснованиями; числа — только из расчётов, сходящихся с базой ([[M-model-validation]]).
5. Посчитать суммы; построить профиль топ-2 вариантов: где сильны, где слабы.
6. Показать таблицу руководителю вместе с сильными возражениями ([[M-solution-design]]); выбор — за человеком.
7. Записать выбор в решение: основания (критерии, оценки, C###), условия пересмотра ([[M-decision-daci]]).

## Типичные ошибки
- Веса «подбираются» после оценок так, чтобы выиграл любимый вариант.
- Скоринг без фильтров: 10 вариантов по 8 критериям — таблица ради таблицы.
- Оценки без якорей: «риск 3» у одного означает «средний», у другого «высокий».
- Числа критериев из воздуха: «вклад в выручку 4» вместо значения из модели ([[M-traction-model]]).
- Решение по сумме баллов при противоречивом профиле: вариант критически слаб по главному критерию.
- Скоринг как замена спора: таблица должна структурировать возражения, а не заменить их.

## Вопросы, которые могут изменить решение
- Какой критерий реально решающий, и не растворён ли он в весах?
- Какая оценка в таблице самая шаткая — и что её подтвердит дешевле всего?
- Изменит ли порядок вариантов снятие одного критерия (проверка устойчивости)?
- Какие два варианта стоит объединить или проверить совместно?
