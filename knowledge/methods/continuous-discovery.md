# Continuous Discovery: дискавери каждую неделю, а не проектом

## Когда применять
Команда уже работает спринтами и не может позволить себе «месяц дискавери». Нужен непрерывный поток контактов с пользователями и прозрачная карта «риск → возможность → решение».

## Суть
- **Опорное дерево возможностей (Opportunity Solution Tree)**: цель продукта наверху → ветви возможностей (потребности/боли пользователей, не фичи!) → под каждой — решения → под каждым решением — эксперименты-проверки. Одно явление может появиться в дереве многократно — это нормально.
- **Каденция касаний**: еженедельный контакт с пользователями (интервью-сниппеты по 20–30 минут, не «проекты» по 6 недель). Правило Torres: «кто-то из команды говорит с пользователем каждую неделю».
- **Три параллельных риска** проверяются одновременно: ценность (нужно ли), юзабилити (понятно ли), осуществимость/бизнес (можно ли и выгодно ли).
- **Interview snippets** — короткие структурированные записи фактов из разговора (цитата + контекст), накапливаются в базу, а не умирают в папке записей.
- **Мини-канвас решения** перед работой: главный риск, самое опасное допущение, минимальный тест.

## Как делать
1. Сформулировать цель продукта на квартал (метрика + границы).
2. Построить/обновить дерево возможностей: интервью → формулировки возможностей от лица пользователя («нужен способ…»).
3. Вести каденцию касаний; каждый раз — один нюанс исследования (боли, цена, контекст использования).
4. Для приоритетной возможности — 3+ альтернативных решения иstorytelling-таблица допущений.
5. Выбрать самое опасное допущение → минимальный тест → результат в дерево.

## Подводные камни
- Дерево из фич вместо возможностей — теряется смысл.
- Касания «когда будет время» — дискавери умирает; каденция фиксируется в календаре.
- Тест ради теста: тест должен бить по самому опасному допущению.
