# Удержание платных подписок и win-back

## Когда применять
Когда платящие оттекают: не продлевают подписку, отключают автосписание, уходят после промо-периода.
Цель — управлять «тремя утечками» платящей базы: добровольный churn, невольный churn (платежи) и «спящие»
ушедшие, которых можно вернуть (win-back). Сценарий retention встречается в демо-задаче МегаФона — карта
описывает общую методику без закрытых данных.

## Суть
Удержание платящих — это работа с кривой выживания когорты по причинам оттока, где каждая причина имеет
свой инструмент:

| Причина оттока | Как выглядит | Инструмент |
|---|---|---|
| Не получил ценность | отмена в первые 1–2 периода | onboarding до «первого результата», триггерные письма/пуши по использованию |
| Не понял списание | «зачем сняли деньги?» | прозрачное уведомление до списания, понятная выписка |
| Невольный churn | карта истекла, не хватило средств | dunning: повторные списания, уведомления, альтернативные способы оплаты |
| Цена vs ценность | «дорого за то, как пользуюсь» | downgrade-путь на дешёвый тариф вместо отмены ([[M-cannibalization]] — считать эффект) |
| Сезонность | нужен был на месяц | пауза подписки вместо отмены |
| Событие жизни | сменил работу/город | win-back сегмент с отложенным оффером |

Правила работы с метриками:
- считать по когортам подписок (месяц первой оплаты), не «средний churn по базе»;
- разделять **logo churn** (отмен) и **вырученный churn** (деньги): downgrade и пауза снижают выручку, но сохраняют платящего;
- gross retention (удержание базы) и net revenue retention (с учётом upgrade) — разные метрики; рост NRR при падении GR — «выжимание» базы;
- payback когорты ([[M-unit-economics]]): удержание платящих — главный рычаг payback, иногда дешевле привлечения.

Win-back: ушедшие сегментируются по причине ухода и давности; оффер строится от причины («верните карту» ≠
«вот скидка»); каннибализация — часть win-back аудитории вернулась бы и без оффера, эффект считается только
против контрольной группы.

## Процедура
1. Разложить отток последних 3 месяцев по причинам (опрос при отмене + данные платежей + интервью ушедших).
2. Оценить вклад каждой причины в churn (доля отмен и доля выручки) — приоритизировать по выручке, не по числу отмен.
3. Для невольного churn: аудит dunning-цепочки (повторы списания, интервалы, тексты уведомлений, способы оплаты).
4. Для добровольного: карточка интервенции на каждую причину (механика, ожидаемый эффект на churn, риск каннибализации).
5. Win-back: определить сегменты (причина × давность), оффер и контрольную группу; считать инкремент, не «возвраты».
6. Проверить интервенции A/B ([[M-ab-testing]]): метрика — выживание когорты и NRR, горизонт — минимум 1–2 цикла списания.
7. Закрепить: дашборд churn по причинам, когортные кривые, алерты на аномалии продлений ([[M-loyalty-metrics]]).

## Шаблон / чек-лист
| Причина | Доля отмен | Доля выручки | Инструмент | Ожидаемый эффект | Проверка |
|---|---|---|---|---|---|
| нет ценности | | | | | A/B |
| не понял списание | | | | | A/B |
| платежи (dunning) | | | | | A/B |
| цена | | | downgrade/пауза | | A/B |
| прочее | | | | | |

- [ ] churn считается по когортам и в деньгах, не только по числу отмен;
- [ ] dunning-цепочка описана и проверяется;
- [ ] у каждого тарифа есть downgrade-путь и пауза;
- [ ] win-back считается против контрольной группы (инкремент);
- [ ] горизонт проверки ≥ 1–2 платёжных цикла.

## Типичные ошибки
- Скидка всем уходящим как «удержание»: каннибализация лояльной базы, обучаем отменяться ради скидки.
- churn «по базе», а не по когортам: эффект интервенций не виден.
- только logo churn: downgrade и паузы выглядят «успехом», хотя выручка падает.
- dunning как один повтор списания «в конце месяца»: большая часть невольного churn невосполнима после.
- win-back без контрольной группы: «возвраты» включают тех, кто вернулся бы сам.
- Оффер от давности, а не от причины ухода: скидка «дорого» не помогает «не понял ценность».

## Вопросы, которые могут изменить решение
- Какая причина оттока даёт основную потерю выручки (не числа отмен)?
- Сколько денег приносит +1 п.п. удержания за год — и сравнима ли работа с этим с привлечением?
- Какая часть win-back вернулась бы без оффера?
- Не размывает ли пауза/даунгрейд базу платящих так, что NRR падает при снижении logo churn?
