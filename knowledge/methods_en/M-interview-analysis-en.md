# In-Depth Interview Analysis (EN summary)

**When:** a series of interviews (or other qualitative data: open survey answers, diaries, support tickets) must become an explanatory model, insights and recommendations — without losing information and without promising the team what qualitative data cannot prove.

**Core:** analysis is not a formality — unanalyzed interviews are just stories whose conclusions are easily dismissed; analysis builds the explanatory model the product moves on and guards against lost insights and expectation-fitting. Inputs: recording, transcript, notes (protocol) — work with all three. Stages: immersion (re-read notes and transcripts, re-listen, per-respondent highlights) → coding (short labels reflecting meaning — "distrust of small banks", not retelling — so similar thoughts across respondents can be compared) → categories (codes grouped into themes explaining behavior or values, e.g. seller codes → "different seller attitudes toward credit buyers", "transaction fears"; keep opposing categories too — praise for simplicity alongside complaints about complexity) → interpretation (link categories, explain why users behave so; formulate insights). Evidence strength principles: qualitative data describes variety and mechanisms, not frequencies; sample homogeneity matters more than size; a conclusion strengthens with an independent source. What N interviews allow: 1–4 → individual stories, barrier examples, hypotheses (never "pattern" or "typical"); 5–9 of one segment → first recurring themes, behavior variants, client language (no shares, rankings, cross-segment comparison); ~10–15 homogeneous → stable themes until saturation (new interviews stop adding themes) — sufficient for a qualitative goal, never population prevalence; + behavioral data/support tickets → a triangulated hypothesis (not effect size); interview → survey/A/B with a pre-set threshold → prevalence, segment size, significance. Insight grades: L0 single observation; L1 recurring within a segment series; L2 confirmed by an independent source; L3 quantitatively confirmed — high-stakes decisions need L2–L3. Wording: never present interview results in percentages ("80% said…") — the team gets a false sense of statistics; write "almost all…", "some…", "two distinct approaches: … and …", "not encountered in this series"; counts only as "x of n" to show breadth, with a non-prevalence caveat. Good insight: about a cause or mechanism, specific (segment, situation, barrier), non-obvious, actionable, with explicit evidence strength. Template: *[Segment] in [context] does/avoids [behavior] because [motive/barrier], expecting [outcome]. Product implication: [solution hypothesis]. Strength: L1, 8 interviews (one audience); needs check: [survey / A/B / analytics].* AI and synthetic respondents: transcription, draft grouping, contradiction search and code suggestions are allowed with human verification — every category checked against source quotes; synthetic respondents are only for hypothesis generation and guide prep: their answers are not client data, not coded with real interviews, not counted in n, never proof of demand — labeled "synthetic" and graded L0 until verified on real respondents.

**How:** (1) return to goals, hypotheses and the planned use of results; write out research questions and what would confirm/refute them; (2) run the transcription pipeline within 24 hours: export recordings → auto-transcribe → clean (filler words, PII masking) → sync timecodes (quote ↔ time) → shared storage; keep notes and recordings, label respondents without PII; dual recording (local + cloud) checked right after the session — a lost file is a lost insight; (3) immerse: go through all interviews, mark bright and controversial moments, write "hot" summaries per respondent (what surprised; what matched/diverged from hypotheses; what to clarify in tomorrow's guide); (4) code: assign codes to meaningful fragments (same meaning = same code); maintain a codebook (code, definition, example quote, usage conditions) in a table quote–code–respondent–time; code odd answers too (sometimes an unexpected segment); start with 6–8 top categories; (5) group into categories, name them, keep competing ones, save 2–3 strong quotes per category (density guideline: 3–5 quotes per code — fewer = an "orphan code", more = oversaturation); check coding reliability: dual-code part of the material and compare — below ≈0.7 Cohen's kappa, rewrite code definitions and re-code disagreements; solo coding without verification is a common source of subjectivity; (6) interpret: link categories ("fear of X explains behavior Y at stage Z"), map to segments and journey stages, check against original hypotheses (confirmed/refuted/no data), list unplanned finds; (7) grade every conclusion L0–L3 and name what would strengthen it; (8) formulate insights and recommendations via the template; (9) assemble the artifact: introduction (goal, tasks, hypotheses, sample, method, limitations) → body (behavior, stories, quotes, answers) → conclusions (main points, briefly) — as a board, deck or framework (JTBD, CJM, personas, service blueprint); (10) socialize: shared base, live walkthrough, workshop on embedding into work; revisit conclusions in 2–4 weeks; (11) hand off: hypotheses for quantitative checks, segments and personas, inputs for JTBD and CJM. Health metrics: 100% of planned interviews transcribed; 3–5 quotes per code; session→transcript ≤24h; PII masked at cleaning.

**Pitfalls:** skipping analysis ("it's all obvious anyway") — only bright quotes and memories remain; percentages and statistics from interviews; a dump of quotes without structure; confirming your own hypothesis (taking only fitting fragments, ignoring opposites); forgotten goals (conclusions that don't answer the research question); subjective interpretation or fitting stakeholder expectations; leaning on bright statements instead of recurring patterns; mixed segments (professionals and consumers blended); an unsocialized, unpreserved report forgotten in two weeks; analysis for analysis' sake — balance detail against the task and time to market.
