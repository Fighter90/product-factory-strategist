# Model Validation: Backtest, Benchmarks, Sensitivity (EN summary)

**When:** before presenting the model to stakeholders; when the model becomes the budget/plan (a commitment); after major assumption changes; when fact deviates from plan by >10–15%. Validation is not "checking formulas" — it is a buy-in process: an error in a model that became the plan is very expensive.

**Core:** the validation pyramid, bottom-up, no level skipped: 1 **mechanical errors** (formulas, references, rounding — the most common layer); 2 **logical consistency** (assumptions vs common sense); 3 **assumptions and benchmarks** (each with a source); 4 **backtest** (does the model work on past data); 5 **conceptual check** (is the modeling logic itself right). Mechanical layer: period balance `End = Start + inflows − outflows` (tolerance ≈0.01); the product of step conversions equals the total conversion (adding instead of multiplying is a classic: 50%×30%×20%×10% = 0.3%, not 110%); retention ≤ 100%, conversions ∈ [0;1], users and revenue non-negative; a metric computed "two ways" (demand vs supply) must reconcile; no #REF! after row deletions; dragged formulas checked at range extremes (a shifted relative reference is the classic cause of retention = 120%); retro/fact separated from forecast. Logical layer: metric values must match the business stage — guideline bands: Month-1 retention 10–30% (startup) / 25–50% (scaling) / 40–70% (mature); payment conversion 1–5 / 5–15 / 10–30%; MoM MAU growth 10–30 / 5–15 / 1–5%; monthly churn 5–15 / 3–8 / 1–5%; LTV/CAC 0.5–1.5 / 1.5–3 / 3–5+. Red flags: startup retention >50%, a funnel step at 90% ("doesn't happen"), 3+ metrics in the red zone = revisit assumptions; the "reverse reading" trick: start from final revenue and walk up the chain asking which assumptions were required and whether they're realistic. **Benchmarks:** every benchmark = a source recorded in the model; no source — admit it honestly. Relevance check 2-of-4: industry, segment, stage, business model (usable with a caveat). When sources diverge: consistent → mean, moderately → median, strongly → the conservative value (10–80% dispersion is noise, not information). Healthy proportion: most assumptions within market range; only a few above benchmark, each explained; >40–50% above benchmark = an unrealistic model. **Backtest:** feed past data, compare model forecast vs fact, compute MAPE (mean absolute percentage error): <5% excellent (plan confidently); 5–15% good (budget a deviation buffer); 15–30% satisfactory (revisit key assumptions); >30% weak (unfit for budgeting). Rolling backtest: each month new fact → re-forecast → error should decline; instability = overfitting or a fragile assumption. Traps: future leakage (data unavailable at forecast time), overfitting (split train/test), instability. **Sensitivity:** ±10/20/30% scenarios for 2–3 key drivers; three questions — which parameter moves the result most, which is known worst, at which value the project becomes unviable (**threshold** — below it you must not fall; every investor understands it). Scenarios bull/base/bear: three assumption sets → three outcomes; with high dispersion show a range, not a "precise" forecast. **Review without "one pot"** — the same-team feast shares the same biases: business peer (logic, feel for numbers; 30 min), finance/FP&A (formulas, discounting; 1–2 h), data analyst (data quality, benchmarks vs fact; 1–2 days), external auditor (major assumptions, market; 3–5 days, optional). **Bias control:** confirmation bias, anchoring (attachment to the first draft or an authority's opinion), reluctance to break the tidy picture; antidotes: a challenger (drills one driver to the bottom), three arguments AGAINST the model, sensitivity analysis, an external reviewer. When no data exists at all (new business/market): proxy metrics (`target = proxy1 × proxy2 × adjustment`, expected error 30–60%), expert estimates, a cheap MVP test, an adjacent-market analogy — and scenario planning instead of a "precise" forecast.

**How:** (1) run auto-checks: a Checks tab with binary formulas and a global `=IF(SUM(checks)>0;"ERROR";"OK")` happy checker (period balance, non-negativity, retention ≤1, funnel non-increasing, not above market cap, demand/supply reconciliation, broken references) — 0 means clean and removes cognitive load from the reviewer; (2) sanity-check totals (Revenue/MAU/Profit realistic for the market and stage; reverse reading); (3) benchmark check: every assumption sourced and graded A–D, each deviation explained in one line; (4) fact-vs-plan reconciliation: decompose the deviation into market / product / operational / model factors; update the model with fact; (5) backtest if history exists: MAPE over 6+ months, rolling backtest, future-leakage check; (6) sensitivity analysis; (7) bull/base/bear scenarios with a threshold row (Profit < 0 → red flag); (8) review by diverse perspectives; (9) control cognitive biases; (10) document the validation report — happy checker, issues found and resolved, who reviewed, buy-in of all participants; only then does the model become the plan.

**Pitfalls:** eyeball validation without a Checks tab (the reviewer hunts mechanics instead of logic); a beautiful model without external review (the author's eye misses retention 120%); benchmarks from an irrelevant industry or stage (apparel conversion 2–3% applied to grocery delivery with its 15–25%); an ignored demand/supply divergence (revenue from demand ≠ revenue from supply — always find the cause); fitting assumptions to the desired outcome ("the economics don't converge — let's raise conversion" instead of an honest conclusion); judging by one backtest month; a single reviewer or reviewers all from one team; using the first months as the base (early adopters, unrepresentative — wait 2–3 months of data).
