# Communication strategy: message house

## When to apply
When you need to decide **what to say** to the audience: positioning is ready ([[M-positioning-dunford]],
[[M-usp]]) but the messages for segments, channels, and campaigns are not assembled; when preparing a launch
([[M-gtm-launch]]), a landing page, a pitch, and any document where the product promises benefit.

## Core: the message house
A message house is a "house": roof, pillars, foundation. It is assembled bottom-up and read top-down.

- **The foundation — proof.** Facts, numbers, cases, demonstrations. The consistency rule: **every promise
  has its proof**, otherwise it is not a message but a slogan. Proof is registered as sourced claims
  ([[M-source-criticism]]): "cuts response time by 40% [C###]" is stronger than "significantly speeds up work".
- **The pillars — three supporting theses.** Not features but values for the audience: what the customer
  gets, how it differs from alternatives, why we can be believed. Three — because more is not remembered;
  each pillar rests on its own set of proof and unfolds into messages for specific segments.
- **The roof — the key message.** One phrase the audience must take away and retell in their own words.
  Roof test: if a person repeats it inaccurately but keeps the meaning — the message worked.

**The comprehension barrier.** Between the message and the action stands what the audience does not know,
does not believe, or fears: "online banking is risky", "it already works for us", "a data migration takes
months". The message is designed against a specific barrier: name it in the audience's words (from interviews
and CJM, [[M-jtbd]]) and remove it with a direct answer (a guarantee, a case of a similar company, the number
"the migration took 2 weeks for 12 customers"). A message that does not remove the barrier will not convert
at any channel volume.

**Hierarchy and discipline.** One idea — one message. Segments get the same roof but different pillars:
the CFO gets the economics, the user gets convenience, the lawyer gets compliance. Channels do not invent
their own messages — they unfold the pillars.

## Procedure (agent)
1. Fix the audience and the message's job: whom we persuade, what action we expect, how we measure.
2. List comprehension barriers per segment — from interviews, support, reviews; pick the main one.
3. Assemble proof for each thesis: sourced facts, cases, numbers; weak proof — either strengthen it or drop
   the promise.
4. Assemble the house: roof (1 phrase) → 3 pillars (thesis + proof) → expansions per segment and channel.
5. Check consistency with the product: every promise is backed in the product (the gate of the `strategy`
   step).
6. Message test ("five seconds — in your own words — what was missing"): 3–5 respondents from the segment;
   an A/B test on the channel for the lead formulation.

## Template / checklist
- [ ] the roof is one phrase, retellable in one's own words without distorting the meaning;
- [ ] three pillars, each an audience value, not a feature;
- [ ] every promise has sourced proof (or the promise is dropped);
- [ ] the main comprehension barrier is named in the audience's words and answered with a direct response;
- [ ] segment expansions use one roof and their own pillars;
- [ ] there is a message validation plan (a qualitative test + an A/B on the channel).

## Typical mistakes
- A house without a foundation: loud promises without proof — distrust spills onto the other messages too.
- Feature pillars: "24/7 support, API, dark mode" — the customer's value is not named.
- Three messages in one: no roof, because everything is "important" at once.
- Ignoring the barrier: the message answers something other than what the audience does not believe.
- Bureaucratese and anglicisms instead of the audience's speech — see [[M-committee-doc-style]].

## Questions that could change the decision
- Which barrier is stronger: lack of understanding ("what is this") or lack of trust ("will it work for us")?
- Do we have proof at the level of "a case of a similar company", or do we need to gather it first?
- Does the message contradict how the product actually works?
