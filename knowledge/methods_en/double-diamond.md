# Double Diamond (EN summary)

**When:** explaining and controlling which thinking stage the work is in: diverging (ideas, data) or converging (solutions, choice). In the agent it maps onto the 11 process steps and the question blocks.

**Core:** Two diamond phases, each "diverge, then converge": (1) Discover — gather as much as possible about the problem: data, interviews, context; no solution proposals. (2) Define — narrow to a correctly posed problem / point of view (insight). (3) Develop — generate many meaningfully different solutions and attack them. (4) Deliver — choose, verify at small scale, fix the decision and metrics. The classic process failure is "collapsing the diamond": starting a solution before understanding the problem, or iterating solutions without choice criteria. Mapping to the agent process: Discover = intake → sources → research → discovery (gate: a plan built from decision-changing questions; personas/JTBD); Define = situation → options → choice (gate: contradictions named; ≥3 options; the human chooses); Develop = strategy → validation (gate: promises ↔ product; metric + base + timeframe); Deliver = review → decision → monitoring (gate: check/rubric; decision recorded; commitments).

**How:** (1) at every step announce the phase ("we're in Define — narrowing") so the lead sees the thinking mode; (2) in Discover/Develop phases explicitly accumulate options (C### hypotheses, variants A–D) instead of pruning early; (3) in Define/Deliver apply the criteria from the question blocks (options-criteria, choice-reversibility); (4) never enter the next diamond without the gate: Define closes with a human choice, Deliver with a recorded decision. Gate table: Discover→Define — claim registry with sources; a plan from decision-changing questions; every key question answered with a C### or a named gap. Define→Develop — situation document with contradictions; ≥3 meaningfully different options; red team answered; the human picked a variant. Develop→Deliver — product and communication strategies; validation plan (metric, base, timeframe, counter-metrics); every promise backed by the product map. Deliver→next cycle — decision in decisions.jsonl; commitments with owners and dates; decision due empty; monitoring set up.

**Pitfalls:** deciding in Discover ("let's just do X" before situation/options); endless Define (data collected without the question "what will change the decision"); Deliver without metrics ("launched" = "done"); one diamond instead of two — no separate work on the problem and on the solution.
