# AI in Research (EN summary)

**When:** speeding up research routine (transcription, first-pass coding, draft guides and hypotheses, search across the interview base) without losing the quality of conclusions; choosing a model and mode; building an assistant over your own data. The course places AI after session-design and data-storage topics deliberately: without understanding the method you cannot judge the model's output. AI answers must be checked against your own data, otherwise it is just plausible text.

**Core:** LLMs show "intelligence" (pattern-finding, prediction, modeling) but without facts in the context window they fill gaps with plausible fiction — hence the key practice, **context engineering**. Base prompt: `[Role] + [Task] + [Context/details] + [Format/constraints]`; seven rules: clarity and brevity, role, context (goal, constraints, audience), output format, step-by-step instructions for complex tasks, examples, delimiters/structure. Reasoning models "think" internally and can browse and show sources: prompt them shorter and more precisely — long role instructions and "first do this, then that" hurt; the reasoning chain and source list reveal why an answer went wrong. Three context layers: System (role and rules, read first), Session (task and clarifications), Extended (extracts from the interview base, tickets, metrics). RAG: retrieve relevant chunks → pass into the prompt → generate from them; course parameters: chunks ≈800 tokens, embeddings, similarity threshold ≈0.75, top-5 chunks; a chunk >2000 tokens gets truncated; without metadata search pulls irrelevant content; scanned PDFs without a text layer yield nothing — "context is worth more than tokens": an hour cleaning data beats dumping pages. Assistant = model + system prompt + knowledge base (+ tools); for analyzing your own interviews switch web access off (it injects "outliers"), for market scans switch it on; never load internal company data into external services without security approval. Delegation boundaries: yes with checks — transcription (spot-check against audio, verify names/terms), open-answer coding (closed tag list, "no fitting tag" allowed, human spot-check), interview summarization (every thesis with a quote + timecode/file link), draft guides/hypotheses (researcher edits, check for leading questions), vague-request→research-questions conversion (draft only), pattern search (a claim must be supported in ≥N quotes, verified manually), clustering (human approves groups), market/competitor scans (web + source criticism). Never delegate: final insight and recommendation (human owns the decision), estimating prevalence, demand, willingness to pay, segment size (real respondents and statistics only), synthetic respondents (only under that method's rules, labeled, never proof), emotions "from text" (hypothesis until video/voice/observation), personal data (internal perimeter only, consent, anonymization).

**How:** (1) decide what to delegate using the table; (2) pick model and mode — short precise task → reasoning model with a simple prompt; to compare quality run the same task on both; toggle web access deliberately; check context limits (tokens, file size) in the service docs; in assistant builders distinguish the UI wrapper (fast to share) from API access (versioning, logs, control) — the latter when the assistant is part of a process; (3) assemble context: clean texts (not scans), metadata (date, segment, method, respondent without PII), split large files, minimum three heterogeneous sources, system prompt fixing role, a ban on leaving the CONTEXT, answer format, and a requirement to cite the file name; (4) request evidence-formatted output: thesis → verbatim quote → file/position → confidence level; "say so if data is insufficient"; separate "fact from source" and "model interpretation"; (5) validate — mandatory: every quote exists verbatim (search the source); human re-check 10–20% of theses (more for critical conclusions); rerun with another phrasing/model and reconcile differences; double-code part of the answers; inspect the reasoning and source list, remove irrelevant sources; conclusions the model made without quotes are downgraded to hypotheses; (6) save with provenance: model, date, prompt version, source files, who verified.

**Pitfalls:** accepting output without sources (fiction in the report); dumping 50 pages into the window (costly, truncated); oversized chunks and missing metadata; indexing scans (empty text); web access on while analyzing your own interviews; long role prompts for reasoning models; open tag lists instead of closed ones (impossible to aggregate); AI as an unlabeled "respondent" (evidence substitution); internal data in external services (leak); presenting a model's conclusion as the research result (lost responsibility) — a human signs the conclusion.
