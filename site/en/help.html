Key points — the whole gist in one minute

Evidence, not eloquenceEvery number and conclusion: a type (fact/hypothesis/forecast/assumption/inference), grade A–D, and a source. The chain S### → C### → D### is traceable from link to decision.
12 steps, 3 human pausesThe agent drives: brief → sources → research → discovery → situation → options → choice → strategies → validation → review → decision → monitoring.
Honest optionsAt least three substantively distinct ones, including "do nothing" and "shut it down". A dedicated red-team subagent attacks each.
State lives in filesprojects/<slug>/ stores everything. New chat, another environment, a break — work resumes where it stopped, no repeats.
Formula Excel4 workbooks (unit economics, growth, cohorts, market) build in the background; the Input sheet holds parameters, the rest are formulas.
Transparency and costAn action log, grounds behind conclusions, cost in tokens and money — pfs cost, pfs next, pfs check --strict.

Talking to the agent

Write in plain language as to a colleague. The agent understands three kinds of messages: a task ("why is in-app retention dropping"), answers to its questions (pick an option or reply freely) and control phrases (see below). It never asks more than three questions at once and always explains what it is missing and why it matters for the next step.

A good first request names the decision to make: "Help me decide whether to launch antispam as a paid subscription; here is the brief and six months of data." A weak one ("make me a strategy") also works — the agent clarifies the decision, audience and constraints via pfs ask before spending your tokens.

Control phrases

PhraseWhat happens
"stop"Pause: state saved, the agent stays quiet until a new command
"clarify: …"Adjust the task; only the affected part is redone, sources are not duplicated
"redo section X"Targeted rework of a single document section
"what should I decide now"pfs next: current step, overdue decisions, stale grounds, open questions
"what's due"pfs decision due: decisions and commitments whose review date arrived
"what will this new source affect"pfs impact: which conclusions, document lines and decisions go stale
"build the six-pager"pfs calc all + pfs export --six-pager: FAQ-1…6 report and 4 Excel workbooks
"recalculate Excel"pfs calc all — workbooks rebuilt from current calcs.json
"build the report" / "build the deck"pfs export → REPORT.md; pfs export --deck → 16:9 HTML deck
"make it a doc"pfs docx file.md — Markdown to Word, dependency-free
"check the project"pfs check --strict — numbers, links, options
"how much did it cost"pfs cost — tokens and money per model

Quick start — 5 minutes

$ git clone https://github.com/Fighter90/product-factory-strategist.git
$ cd product-factory-strategist
$ python3 -m tools.pfs doctor      # environment check
$ python3 -m unittest discover -s tests   # 115 tests, optional
$ pfs new "Why is retention dropping" "the request verbatim"

Requirements: Python 3.9+ and any supported environment. No packages to install — standard library only. Secrets (Linear and other MCP keys) go to .env — it is git-ignored and not required for the basic loop.

First project — what happens

pfs new "<name>" "<the request verbatim>" creates projects/<slug>/ (sources, interviews, analysis, outputs, state.json, log.jsonl) and activates it. The agent then: classifies the scenario via routing (pfs route), asks the intake question block — up to 3 questions — writes outputs/00_brief.md and stops for your approval. That is the first of three human pauses.

Switch projects with pfs use <slug>, list them with pfs list, inspect state with pfs status.

CVStart demo: how it was made and what to look at

A full end-to-end run on a live open-source product — cvstart.org (AI resume builder + job search: 129 job boards, AI scoring, 19 languages): 12 steps, 5 options, 20 red-team objections, both strategies, a six-pager in 6 formats (RU/EN × MD/PDF/DOCX, each with its language's screenshots), 4 Excel workbooks, decision D001, check --strict 100/100. Project: projects/демо/; interactive walkthrough: demo.html.

What to look at (in order): 00_brief → 01_research_plan → 02_situation → 03_options (5 options + 20 red-team objections) → 04/05 (strategies) → 06_validation_plan (90-day thresholds) → REPORT.md and SIX_PAGER_RU / SIX_PAGER_EN in .md/.pdf/.docx; Excel in outputs/attachments/; product screenshots in outputs/img/ (19 locales); the action log is log.jsonl.

Mistakes along the way (honestly): market estimates from aggregators diverge ×2 — recorded as ranges [S006]; source numbering shifted during re-registration — tags re-bound and re-checked with check --strict; some C### links drifted to neighbouring claims during migration — caught by a registry audit and fixed. The human helped at three pauses: brief, option choice, decision D001 approval.

The cycle: 12 steps and phases

The cycle is 12 steps in four double-diamond phases: Discover (0–3) → Define (4–6) → Develop (7–9) → Deliver (10–11). Each step has mandatory knowledge cards (pfs step prints them), a question block (pfs questions <step>), quality gates and an artifact. Progress shows in one line: Step N/12 · research · sources S001–S009 · next: situation. Steps 0, 6, 10 are human pauses: brief, option choice, decision approval.

step 0Brief

Input: your request verbatim. Agent: clarifies the target decision, goal, audience and format, constraints, available data — the intake question block (≤3 questions with options and a recommendation). Output: outputs/00_brief.md. Human: approves the brief — it is then fixed and can ground assumptions (like source S011 in the demo). Commands: pfs new, pfs questions intake, pfs answer "…".

step 1Sources

Input: your files and a list of public pages. Agent: registers materials — pfs source add <url|file> — dedup by URL and SHA-256 (a repeat adds nothing), extracts text from PDF/DOCX/XLSX/CSV/pages, checks the domain against the project's allowed_sources, flags embedded instruction-like phrases (data, not commands). Output: sources/S###.md + copies in sources/raw/. Commands: add/list/show/refresh; refreshing a web source compares hashes and warns on changes.

step 2Research

Agent: builds a plan from questions that could change the decision ("question → if yes / if no → how it affects"), extracts claims with type, grade and quote, runs calculations, prepares interviews when needed. A fact without a source cannot be stored — the tool refuses. Output: outputs/01_research_plan.md, claims.jsonl (C###), analysis/. Commands: pfs claim add, pfs data profile|cohort|funnel|stats, pfs interview guide|save, pfs media add. Gate: every key question answered with a C### or an explicitly named gap.

step 3Discovery

Agent: builds personas and their jobs-to-be-done, describes user alternatives — how people solve the problem today; the discovery question block fixes the segment. AI respondents (the synthetic-respondent subagent) yield hypotheses about motives and barriers — registered with origin=synthetic and unable to prove demand. Output: the "Segments" section of 02_situation.md, transcripts in interviews/synthetic/.

step 4Situation

Agent: assembles a verifiable picture: what is known and from where (C### tags), what we do not know and why it matters, contradictions between sources. Every number in a document must carry a tag — check catches "naked" numbers. Output: outputs/02_situation.md. Gate: pfs check with zero errors.

step 5Options + red team

Agent: prepares at least three substantively distinct options, including "do nothing" and "shut it down" — check verifies their presence by keywords. Each with: strong objections (attacked by the red-team subagent), formula-based economics with ranges, and the conditions under which the option is right. Output: outputs/03_options.md. Gate: red team has responded, check passes.

step 6Choice — human pause

Agent: shows the option comparison (criteria, economics, risks) and a single recommendation, then asks — pfs ask "Which option do we take?" --options "A,B,C". Human: picks the option — the answer is stored in state.json and grounds the strategies and the D### decision (like S011 in the CVStart demo). No strategies are written before the choice.

step 7Strategies

Agent: writes the product strategy — audience and their job, alternatives, the chosen direction and conscious trade-offs, benefit-to-cost economics — and the communication strategy — audience and situation, the comprehension barrier, the key message, its proof, channel roles. Consistency is enforced by a "promise → product proof" table: every promise cites a C###. The comms-strategist subagent drafts the comms part. Output: 04_product_strategy.md, 05_comms_strategy.md.

step 8Validation plan

Agent: states the expected change (which metric, by how much), the comparison baseline (prior period, control group), the observation window, unwanted side effects (counter-metrics), and continue / adjust / stop criteria. All five sections are mandatory — check enforces them. Output: outputs/06_validation_plan.md.

step 9Review

Agent: runs pfs check --strict, requests an independent rubric review (the evidence-auditor subagent) and assembles the committee pack: pfs calc all (4 Excel workbooks) and pfs export --six-pager (FAQ-1…6 + attachments). On a borderline score the model escalates and the step repeats. Output: outputs/07_quality_review.md, SIX_PAGER.md, attachments/*.xlsx.

step 10Decision — human pause

Agent: records the decision via pfs decision add: title, statement, owner, grounds (C###), metric with target and date, review date, trigger ("if X — revisit"), commitments ("what | who | when"). Human: approves the decision. Output: a record in decisions.jsonl (D###). From now on pfs next and pfs decision due watch the deadlines.

step 11Monitoring

Agent: keeps the step open: pfs decision due lists overdue reviews; when new data arrives — pfs source refresh + pfs impact C### locate affected conclusions; stale ones are superseded via pfs claim supersede, conclusions redirected by pfs claim rebase, decisions by pfs decision rebase. Gate: pfs decision due is empty or fully handled.

Sources S### — registration and hygiene

A source is the minimal unit of trust. pfs source add <url> downloads the page and extracts text; pfs source add <file> accepts PDF, DOCX, XLSX, CSV, images (your description of what is visible). For a JS-rendered page: save the text manually and add pfs source add --text-file saved.md --url <url> --title "…". For screenshots/audio descriptions: pfs media add (see Media & UX).

Hygiene: dedup by URL and SHA-256; the domain is checked against projects/<slug>/project.json → allowed_sources (a hook blocks foreign domains before the request); pfs source list — the registry, pfs source show S### — text and metadata; pfs source refresh S### — reload: hash changed → warning and a reminder to run pfs impact S###.

Source types: public, own, interview, synthetic

OriginWhat it isConstraint
public/webPublic pages and publications (default)Project-allowed domains
ownYour materials: briefs, data dumps, internal docsNo closed or personal data
interviewReal interviews — with participant consentNo personal data in the repository
syntheticAI respondents, model-generated dataHypotheses only: facts on synthetic data are blocked by the checker

Claims C### — five types

A claim is the atom of knowledge. The registry is claims.jsonl; written only via pfs claim add:

TypeWhen to useRequirement
factA verified statementSource required; never on synthetic data; grade D forbidden
hypothesisAn assumption we intend to testGrounds: a source or other claims
forecastA model-based predictionGrounds + visible assumptions in the model
assumptionAccepted without testing (demo frame, model scenario)Grounds: where it came from (checker warns otherwise)
inferenceYour conclusion from other claims--from required; never stronger than its weakest input

Evidence grades A–D

An inference is never stronger than its weakest critical input: two C grounds and one B give at most C. Set via claim add --grade; supersede preserves the grade automatically.

Supersede, retract, rebase — history is kept

After supersede, documents referencing the old ID get a check error with the replacement hint (replacement: C058) — re-tag the lines and rebuild exports. This is a guard, not a bug: documents cannot silently rely on stale claims. The history (who, when, why) stays in the registry.

Change impact: pfs impact

pfs impact C005 / pfs impact S002 shows transitively: which claims rely on it, which document lines cite it, which decisions are grounded in it. Practice: impact before an edit, impact after, then pfs check --strict as the final filter.

Decisions D### — grounds, commitments, review

Track: pfs decision due — overdue items, due reviews, decisions with stale grounds; pfs decision done --id D001 --commitment K1 — close a commitment; pfs decision list — registry. New data changed the grounds? — run impact, supersede, then pfs decision rebase --id D001 --note "…".

Project documents 00–07

Same structure in English: brief → research plan → situation → options (≥3 incl. status quo) → product strategy → comms strategy → validation plan (5 mandatory sections) → quality review. Check enforces sections, tagged numbers and option counts.

REPORT.md — the final document with all attachments

pfs export assembles REPORT.md: summary, brief, situation, options and choice, both strategies, the validation plan, appendices (claim registry with grades and sources, cost log, Excel links). Edit only outputs/*.md by hand — REPORT rebuilds so nothing drifts. pfs export --six-pager — the committee format.

Six-pager: FAQ-1…FAQ-6 structure

FAQ-1 status (market, competitors) · FAQ-2 segments & personas · FAQ-3 initiatives + red-team objections · FAQ-4 tactics (need → mechanics → effect) · FAQ-5 delivery & validation plan · FAQ-6 success metrics with formulas. Numbers come from the claim registry, assumptions visible in calcs.json.

calcs.json — full parameter reference

The file is projects/<slug>/calcs.json. The agent fills values from claims and records grounds in note; missing keys fall back to examples marked "EXAMPLE", visible in Excel.

Excel workbooks: structure and editing

pfs calc all|unit-econ|growth|cohort|market writes workbooks to outputs/attachments/. The Input sheet holds editable parameters (with source notes); all other sheets are live formulas: CM, LTV, LTV/CAC, payback, sensitivity (unit economics); MAU → orders → GMV → margin over 12 months (growth); cohorts and M1–M12 retention; PAM→TAM→SAM→SOM.

Editing: change the Input values — Excel recalculates. If you edit calcs.json — rerun pfs calc all and pfs export --six-pager so the text and workbooks match. A file preview may look "empty" — that is a cached render; formulas compute on open.

Deck and docx

pfs export --deck builds a 16:9 HTML deck from SIX_PAGER.md — section slides in the site's gradient theme, printable to PDF from the browser. pfs docx <file.md> converts Markdown to Word (headings, tables, lists, inline code), dependency-free — for handing documents to the committee.

CLI: all command groups

Same groups in English: projects (new/list/use/status) · steps (step/next/questions) · ask/answer · sources (S###, dedup, domains, refresh) · claims (C###, 5 types, grades, history) · quality (check/impact) · decisions (D###) · data (profile/cohort/funnel/stats) · interviews · media & UX · knowledge (BM25 over 89 cards) · models (profiles, escalation) · calc (4 formula workbooks) · export (REPORT/six-pager/deck/docx) · log & cost · doctor.

MCP server: 18 tools

The pfs-strategist server (stdio, stdlib only) plugs into any environment's .mcp.json — the agent gets the same operations as the CLI. Tools:

Skills (120): structure and three ways to invoke

Structure: base per-step skills (13) · product-skills, method procedures (27) · a personal library of ~59 (design, marketing, science, documents & media, thinking modes, meta) · integrations. Each folder .claude/skills/<name>/SKILL.md holds instructions + scripts + references.

Invocation: 1) automatic — description triggers; 2) explicit — "use skill <name>: <task>"; 3) per step — pfs step prints mandatory cards. Priority rule: project methodology (KB maps) outranks generic skills. Integration examples: hallmark (anti-slop page gates), board-of-directors (5-perspective council + Red Team at options), premortem (failure pre-mortem before approval), rea (reverse-engineering JS pages and closed formats), sdd (development discipline), deck (six-pager presentation), deep-research (literature review via Feynman). Full registry: docs/SKILLS.md.

Subagents (8)

router (request scenario), researcher (source extraction), data-analyst (tables, cohorts, funnels), synthetic-respondent (AI persona, hypotheses only), ux-analyst (interface review, evidence-bound), red-team (attacks each option), comms-strategist (comms draft), evidence-auditor (rubric review).

Hooks (4): events and actions

SessionStart feeds project context on a new chat; PreToolUse enforces allowed domains before fetch; PostToolUse logs actions, scans external text for embedded instructions (flags, never executes), auto-checks changed docs; Stop recomputes session cost from the transcript.

Models and routing

The model profile lives in config/models.json: cheap models for classification, extraction, rubric scoring, AI respondents; strong ones for synthesis, options, red team, strategy. pfs models — table; pick — per task; use — switch profile; pfs route --economy downgrades deep→balanced except red team. Escalation: two consecutive check failures or a borderline rubric score → pfs models escalate <task> and retry with a stronger model. Subagents inherit the profile; pfs models sync after changes.

Cost: tokens, money, human time

The Stop hook recomputes cost from the session transcript (prices from config/pricing.json); pfs cost — totals per model and task; pfs cost --window — periods. Human edits count too: pfs log "brief edit" --human-minutes 15. Demo reference: a full project ≈ $19 with a mixed model profile.

Data analysis: profile, cohort, funnel, stats

Before computing, the agent checks metrics, units, periods and gaps (table profile). --save makes a run reproducible. Results go to analysis/ and are anchored as C### claims with the file as source.

Interviews and model respondents

pfs interview guide --persona "Parent, kids 7–12" builds the guide; pfs interview save transcript.md registers it with origin=synthetic. The synthetic-respondent subagent plays the persona. Honesty rule: synthetic answers yield hypotheses only; the checker refuses facts on them; documents mark them as model-generated. Real interviews require consent and no personal data.

Media and UX analysis

pfs media add shot.png --desc "what is visible" --title "…" copies the media to sources/raw/ and turns the description into a text source: the agent analyzes exactly what is described. pfs ux scaffold S003 --focus "onboarding" builds a heuristics + journey scaffold bound to the material; the ux-analyst subagent fills it without inventing beyond the screenshots.

Environment: Claude Code — the full experience

Open the repo folder in Claude Code — everything auto-loads: 121 skills, 8 subagents, 4 hooks, the CLI (pfs …) and MCP tools. Just state the task — the agent takes it from there.

Environments: Cursor, Codex, OpenCode, Windsurf, Copilot

All environments read AGENTS.md. Cursor — .cursor/rules + MCP from .mcp.json. Codex / OpenCode / Windsurf / Copilot — no hooks: start with "read AGENTS.md and run pfs status" — the agent restores context and continues. The pfs-strategist MCP works everywhere (path-independent launcher).

Integration: Linear

MCP server npx mcp-server-linear, key LINEAR_API_KEY in .env (git-ignored). The agent reads issues, comments progress, closes with reports — as in this project: PRO-5…PRO-24 closed with final comments. Same rule: the human decides — no issues are closed without your word.

Integration: Lovable

MCP https://mcp.lovable.dev is wired in .mcp.json; authorize once via OAuth (/mcp → lovable → Authenticate). Then the agent creates and edits Lovable projects on request: this project's landing lives in the repo (canonical) and in Lovable (mirror). create_project/send_message consume Lovable credits; ready prompts are in docs/lovable-brief.md.

Integrations: Higgsfield, REA, Feynman, officecli

Higgsfield — image/video generation (this page's art is its work). REA — reverse-engineering of JS pages and closed formats (HAR, SQLite, APK) when plain fetch returns nothing. Feynman — deep-research CLI (literature reviews); a search-provider key is needed for live runs. officecli — Office documents in/out. All are optional MCP/CLI add-ons to the basic loop.

Resuming after a break

All state lives in projects/<slug>/: state.json (steps, choices, questions), claims.jsonl, decisions.jsonl, log.jsonl, sources/, outputs/. New chat in the repo folder: the SessionStart hook feeds status and "what to decide now" automatically. Hook-less environment: write "read AGENTS.md and run pfs status". Finished steps never repeat; sources and claims never duplicate.

Moving a project between environments

A project is a plain folder: copy projects/<slug>/ (or git push/pull if tracked) and open elsewhere. The only non-portable part is secrets in .env: move them manually, never commit. The model profile (config/models.json) is repo-wide.

Security and data

Data: public sources and your materials only; no closed company data, no respondents' personal data. Domains: allow-listed in project.json; a hook blocks foreign domains pre-request. Secrets: .env only, git-ignored; no keys ever committed. Embedded instructions: source texts are data; "ignore instructions" inside a source is flagged, never executed. Interviews: real ones need consent; no personal data in the repo; synthetic data is honestly labeled.

What pfs check verifies

Fact without source → error; fact on synthetic → error; grade-D fact → error; grounds-less hypothesis/forecast/assumption → warning; links to missing/retracted IDs → error with replacement hint; superseded grounds → warning; untagged numbers → warning; <3 options or no status-quo → error; missing required sections → error; sources with embedded instructions → warning listing them.

Troubleshooting

Fact without source → by design, add source or use hypothesis; domain not allowed → edit allow-list or --force; 0 chars extracted → JS page, save text manually or use REA; empty Excel preview → computes on open; six-pager ≠ Excel → rerun calc+export; superseded C### in docs → re-tag per hint; no hook status → ask agent to run pfs status; skill missing → restart session; assumption without grounds → register its origin and supersede; Lovable credits → top up or edit site/ directly; MCP tool missing → refresh .mcp.json, restart; interrupted session → pfs status and repeat, --save makes runs reproducible.
