Как общаться с агентом

Talking to the agent

Пишите обычным языком, как коллеге. Агент понимает три вида сообщений: задачу («почему падает удержание в приложении»), ответы на его вопросы (выбирайте вариант или отвечайте свободно) и команды-фразы (см. ниже). Больше трёх вопросов за раз агент не задаст — и всегда объяснит, чего ему не хватает и почему это важно для следующего шага.

Write in plain language as to a colleague. The agent understands three kinds of messages: a task ("why is in-app retention dropping"), answers to its questions (pick an option or reply freely) and control phrases (see below). It never asks more than three questions at once and always explains what it is missing and why it matters for the next step.

Хороший первый запрос называет решение, которое предстоит принять: «Помоги решить, выводить ли антиспам в платную подписку; вот бриф и выгрузка за полгода». Слабый запрос («сделай стратегию») тоже сработает — агент уточнит целевое решение, получателя и ограничения через pfs ask, прежде чем тратить ваши токены.

A good first request names the decision to make: "Help me decide whether to launch antispam as a paid subscription; here is the brief and six months of data." A weak one ("make me a strategy") also works — the agent clarifies the decision, audience and constraints via pfs ask before spending your tokens.

Requirements: Python 3.9+ and any supported environment. No packages to install — standard library only. Secrets (Linear and other MCP keys) go to .env — it is git-ignored and not required for the basic loop.

Первый проект — что произойдёт

First project — what happens

pfs new "<название>" "<запрос дословно>" создаёт папку projects/<slug>/ со структурой (sources, interviews, analysis, outputs, state.json, log.jsonl) и делает активной. Дальше агент: определит сценарий маршрутизацией (pfs route), задаст вопросный блок intake — до 3 вопросов, — запишет бриф в outputs/00_brief.md и остановится до вашего подтверждения. Это первая из трёх пауз человека.

pfs new "<name>" "<the request verbatim>" creates projects/<slug>/ (sources, interviews, analysis, outputs, state.json, log.jsonl) and activates it. The agent then: classifies the scenario via routing (pfs route), asks the intake question block — up to 3 questions — writes outputs/00_brief.md and stops for your approval. That is the first of three human pauses.

Переключение между проектами — pfs use <slug>, список — pfs list, состояние — pfs status.

Switch projects with pfs use <slug>, list them with pfs list, inspect state with pfs status.

Устройство цикла: 12 шагов и фазы

The cycle: 12 steps and phases

Цикл = 12 шагов в четырёх фазах двойного романа: Discover (0–3) → Define (4–6) → Develop (7–9) → Deliver (10–11). У каждого шага: обязательные карты знаний (pfs step печатает какие), вопросный блок (pfs questions <шаг>), ворота качества и артефакт на выходе. Прогресс виден одной строкой: Шаг N/12 · research · источники S001–S009 · дальше: ситуация. Шаги 0, 6 и 10 — паузы человека: бриф, выбор варианта, утверждение решения.

The cycle is 12 steps in four double-diamond phases: Discover (0–3) → Define (4–6) → Develop (7–9) → Deliver (10–11). Each step has mandatory knowledge cards (pfs step prints them), a question block (pfs questions <step>), quality gates and an artifact. Progress shows in one line: Step N/12 · research · sources S001–S009 · next: situation. Steps 0, 6, 10 are human pauses: brief, option choice, decision approval.

шаг 0БрифBrief

Вход: ваш запрос дословно. Агент: уточняет целевое решение, цель, получателя и формат результата, ограничения, доступные данные — вопросным блоком intake (≤3 вопроса с вариантами и рекомендацией). Выход: outputs/00_brief.md. Человек: подтверждает бриф — после этого он фиксируется и служит основанием допущений (как источник S020 в демо). Команды: pfs new, pfs questions intake, pfs answer "…".

Input: your request verbatim. Agent: clarifies the target decision, goal, audience and format, constraints, available data — the intake question block (≤3 questions with options and a recommendation). Output: outputs/00_brief.md. Human: approves the brief — it is then fixed and can ground assumptions (like source S020 in the demo). Commands: pfs new, pfs questions intake, pfs answer "…".

шаг 1ИсточникиSources

Вход: ваши файлы и список открытых сайтов. Агент: регистрирует материалы — pfs source add <url|файл> — с дедупликацией по URL и SHA-256 (повтор не создаёт дубль), извлекает текст из PDF/DOCX/XLSX/CSV/страниц, проверяет домен по allowed_sources проекта, помечает найденные фразы-инструкции (это данные, не команды). Выход: sources/S###.md + копии в sources/raw/. Команды: add/list/show/refresh; обновление web-источника сравнивает хеш и предупреждает о изменениях.

Input: your files and a list of public pages. Agent: registers materials — pfs source add <url|file> — dedup by URL and SHA-256 (a repeat adds nothing), extracts text from PDF/DOCX/XLSX/CSV/pages, checks the domain against the project's allowed_sources, flags embedded instruction-like phrases (data, not commands). Output: sources/S###.md + copies in sources/raw/. Commands: add/list/show/refresh; refreshing a web source compares hashes and warns on changes.

шаг 2ИсследованиеResearch

Агент: строит план от вопросов, которые могут изменить решение («вопрос → если да / если нет → как влияет»), ведёт выписки утверждений с типом, силой и цитатой, считает расчёты по данным, при необходимости готовит интервью. Факт без источника записать невозможно — инструмент откажет. Выход: outputs/01_research_plan.md, claims.jsonl (C###), analysis/. Команды: pfs claim add, pfs data profile|cohort|funnel|stats, pfs interview guide|save, pfs media add. Ворота: каждый ключевой вопрос — с ответом и C### или названным пробелом.

Agent: builds a plan from questions that could change the decision ("question → if yes / if no → how it affects"), extracts claims with type, grade and quote, runs calculations, prepares interviews when needed. A fact without a source cannot be stored — the tool refuses. Output: outputs/01_research_plan.md, claims.jsonl (C###), analysis/. Commands: pfs claim add, pfs data profile|cohort|funnel|stats, pfs interview guide|save, pfs media add. Gate: every key question answered with a C### or an explicitly named gap.

шаг 3ДискавериDiscovery

Агент: формирует персоны и их задачи (JTBD), описывает альтернативы пользователя — чем люди решают проблему сегодня; вопросный блок discovery фиксирует сегмент. ИИ-респонденты (субагент synthetic-respondent) дают гипотезы о мотивах и барьерах — они регистрируются с origin=synthetic и не могут доказывать спрос. Выход: раздел «Сегменты» в 02_situation.md, транскрипты в interviews/synthetic/.

Agent: builds personas and their jobs-to-be-done, describes user alternatives — how people solve the problem today; the discovery question block fixes the segment. AI respondents (the synthetic-respondent subagent) yield hypotheses about motives and barriers — registered with origin=synthetic and unable to prove demand. Output: the "Segments" section of 02_situation.md, transcripts in interviews/synthetic/.

шаг 4СитуацияSituation

Агент: собирает проверяемую картину: что известно и откуда (теги C###), чего не знаем и почему это важно, противоречия между источниками. Каждое число в документе должно нести тег — check ловит «голые» числа. Выход: outputs/02_situation.md. Ворота: pfs check без ошибок.

Agent: assembles a verifiable picture: what is known and from where (C### tags), what we do not know and why it matters, contradictions between sources. Every number in a document must carry a tag — check catches "naked" numbers. Output: outputs/02_situation.md. Gate: pfs check with zero errors.

шаг 5Варианты + red teamOptions + red team

Агент: готовит минимум три содержательно разных варианта, включая «оставить как есть» и «закрыть направление» — check проверяет их наличие по ключевым словам. Для каждого: сильные возражения (их атакует субагент red-team), экономика формулами и диапазонами, условия, при которых вариант верен. Выход: outputs/03_options.md. Ворота: red-team ответил, check без ошибок.

Agent: prepares at least three substantively distinct options, including "do nothing" and "shut it down" — check verifies their presence by keywords. Each with: strong objections (attacked by the red-team subagent), formula-based economics with ranges, and the conditions under which the option is right. Output: outputs/03_options.md. Gate: red team has responded, check passes.

шаг 6Выбор — пауза человекаChoice — human pause

Агент: показывает сравнение вариантов (критерии, экономика, риски) и одну рекомендацию, затем спрашивает — pfs ask "Какой вариант принимаем?" --options "A,B,C". Человек: выбирает вариант — ответ сохраняется в state.json и становится основанием стратегий и решения D### (как S021 в демо-antispam). Никакие стратегии не пишутся до выбора.

Agent: shows the option comparison (criteria, economics, risks) and a single recommendation, then asks — pfs ask "Which option do we take?" --options "A,B,C". Human: picks the option — the answer is stored in state.json and grounds the strategies and the D### decision (like S021 in the antispam demo). No strategies are written before the choice.

шаг 7СтратегииStrategies

Агент: пишет продуктовую стратегию — аудитория и её задача, альтернативы, выбранное направление и осознанные отказы, связь пользы с затратами и доходами — и коммуникационную — аудитория и ситуация, барьер понимания, ключевое сообщение, его подтверждение, роль каналов. Согласованность проверяется таблицей «обещание → подтверждение в продукте»: каждый промис ссылается на C###. Субагент comms-strategist готовит черновик коммуникационной части. Выход: 04_product_strategy.md, 05_comms_strategy.md.

Agent: writes the product strategy — audience and their job, alternatives, the chosen direction and conscious trade-offs, benefit-to-cost economics — and the communication strategy — audience and situation, the comprehension barrier, the key message, its proof, channel roles. Consistency is enforced by a "promise → product proof" table: every promise cites a C###. The comms-strategist subagent drafts the comms part. Output: 04_product_strategy.md, 05_comms_strategy.md.

шаг 8План проверкиValidation plan

Агент: формулирует ожидаемое изменение (какая метрика, насколько), с чем сравниваем (база: период до, контрольная группа), срок наблюдения, нежелательные последствия (контрметрики) и критерии «продолжить / изменить / остановить». Все пять разделов обязательны — check их требует. Выход: outputs/06_validation_plan.md.

Agent: states the expected change (which metric, by how much), the comparison baseline (prior period, control group), the observation window, unwanted side effects (counter-metrics), and continue / adjust / stop criteria. All five sections are mandatory — check enforces them. Output: outputs/06_validation_plan.md.

шаг 9ReviewReview

Агент: гонит автопроверку pfs check --strict, запускает независимую оценку по рубрике (субагент evidence-auditor) и собирает пакет для комитета: pfs calc all (4 книги Excel) и pfs export --six-pager (FAQ-1…6 + приложения). При пограничной оценке — эскалация модели и повтор шага. Выход: outputs/07_quality_review.md, SIX_PAGER.md, attachments/*.xlsx.

Agent: runs pfs check --strict, requests an independent rubric review (the evidence-auditor subagent) and assembles the committee pack: pfs calc all (4 Excel workbooks) and pfs export --six-pager (FAQ-1…6 + attachments). On a borderline score the model escalates and the step repeats. Output: outputs/07_quality_review.md, SIX_PAGER.md, attachments/*.xlsx.

шаг 10Решение — пауза человекаDecision — human pause

Агент: фиксирует решение через pfs decision add: заголовок, суть, ответственный, основания (C###), метрика с целью и датой, дата пересмотра, триггер («если X — пересмотреть»), обязательства («что | кто | когда»). Человек: утверждает решение. Выход: запись в decisions.jsonl (D###). С этого момента pfs next и pfs decision due следят за сроками.

Agent: records the decision via pfs decision add: title, statement, owner, grounds (C###), metric with target and date, review date, trigger ("if X — revisit"), commitments ("what | who | when"). Human: approves the decision. Output: a record in decisions.jsonl (D###). From now on pfs next and pfs decision due watch the deadlines.

шаг 11МониторингMonitoring

Агент: держит шаг открытым: pfs decision due показывает просрочки и наступившие пересмотры; когда появляются новые данные — pfs source refresh + pfs impact C### находят затронутые выводы; устаревшие замещаются через pfs claim supersede, выводы перенаправляются pfs claim rebase, решения — pfs decision rebase. Ворота: pfs decision due пуст или всё обработано.

Agent: keeps the step open: pfs decision due lists overdue reviews; when new data arrives — pfs source refresh + pfs impact C### locate affected conclusions; stale ones are superseded via pfs claim supersede, conclusions redirected by pfs claim rebase, decisions by pfs decision rebase. Gate: pfs decision due is empty or fully handled.

Источники S### — регистрация и гигиена

Sources S### — registration and hygiene

Источник — минимальная единица доверия. pfs source add <url> скачивает страницу и извлекает текст; pfs source add <файл> принимает PDF, DOCX, XLSX, CSV, изображения (текст распознаётся, для картинок — ваше описание: «что видно»). Для сайта с JS-рендерингом: сохраните текст вручную и добавьте pfs source add --text-file saved.md --url <url> --title "…". Для описания скриншота/аудио: pfs media add (см. «Медиа и UX»).

A source is the minimal unit of trust. pfs source add <url> downloads the page and extracts text; pfs source add <file> accepts PDF, DOCX, XLSX, CSV, images (your description of what is visible). For a JS-rendered page: save the text manually and add pfs source add --text-file saved.md --url <url> --title "…". For screenshots/audio descriptions: pfs media add (see Media & UX).

Гигиена: дедупликация по URL и SHA-256; домен проверяется по projects/<slug>/project.json → allowed_sources (хук блокирует чужой домен до запроса); pfs source list — реестр, pfs source show S### — текст и метаданные; pfs source refresh S### — перезагрузка: изменился хеш — предупреждение и напоминание проверить pfs impact S###.

Сила доказательства A–D

Evidence grades A–D

СилаЧто означаетПример
AНесколько независимых надёжных источников сходятсяДве официальные статистики + отраслевой отчёт об одном объёме рынка

Вывод (inference) не бывает сильнее самого слабого критичного основания: вывод из двух C и одного B — не выше C. Проставляется при claim add --grade; при supersede сила сохраняется автоматически.

An inference is never stronger than its weakest critical input: two C grounds and one B give at most C. Set via claim add --grade; supersede preserves the grade automatically.

Замена, отзыв, перенаправление — история не теряется

Supersede, retract, rebase — history is kept

# данные обновились: старое остаётся в истории со статусом superseded
pfs claim supersede --id C005 "рынок 320 млрд ₽" --reason "свежая оценка ЦБ" --source S012
# утверждение неверно целиком
pfs claim retract --id C006 --reason "методология выборки неверна"
# выводы, опиравшиеся на заменённое, перенаправить на замену
pfs claim rebase --id C005
pfs decision rebase --id D001 --note "основания обновлены"

После supersede документы, ссылающиеся на старый ID, получат ошибку check с подсказкой замены (замена: C058) — перетагируйте строки и пересоберите экспорт. Это не баг, а защита: документы не могут молча опираться на устаревшее. История (кто, когда, почему заменил) хранится в реестре.

After supersede, documents referencing the old ID get a check error with the replacement hint (replacement: C058) — re-tag the lines and rebuild exports. This is a guard, not a bug: documents cannot silently rely on stale claims. The history (who, when, why) stays in the registry.

Влияние изменений: pfs impact

Change impact: pfs impact

pfs impact C005 / pfs impact S002 показывает транзитивно: какие утверждения на это опираются, какие строки документов ссылаются, какие решения основаны на этом. Практика: перед правкой — impact, после правки — impact повторно, затем pfs check --strict как финальный фильтр.

pfs impact C005 / pfs impact S002 shows transitively: which claims rely on it, which document lines cite it, which decisions are grounded in it. Practice: impact before an edit, impact after, then pfs check --strict as the final filter.

Модели и маршрутизация

Models and routing

Профиль моделей живёт в config/models.json: дешёвые — классификация, выписки, оценка по рубрике, ИИ-респонденты; сильные — синтез, варианты, red team, стратегии. pfs models — таблица, pfs models pick <задача> — конкретная модель, pfs models use <профиль> — переключение среды (например, экономный профиль), pfs route --economy — понижение deep→balanced кроме red team. Эскалация: если check дважды нашёл ошибки в результате шага или оценка пограничная — pfs models escalate <задача> --reason "…" и повтор моделью выше. Субагенты наследуют профиль из frontmatter; после смены профиля — pfs models sync.

The model profile lives in config/models.json: cheap models for classification, extraction, rubric scoring, AI respondents; strong ones for synthesis, options, red team, strategy. pfs models — table; pick — per task; use — switch profile; pfs route --economy downgrades deep→balanced except red team. Escalation: two consecutive check failures or a borderline rubric score → pfs models escalate <task> and retry with a stronger model. Subagents inherit the profile; pfs models sync after changes.

Стоимость: токены, деньги, ручное время

Cost: tokens, money, human time

Хук Stop пересчитывает стоимость по транскрипту сессии (цены из config/pricing.json); pfs cost — сводка по моделям и задачам, pfs cost --window — по периодам. Ручные правки человека не теряются: pfs log "правка брифа" --human-minutes 15 входит в полную стоимость результата. Ориентиры демо: сквозной проект ≈ $19 при смешанном профиле моделей.

The Stop hook recomputes cost from the session transcript (prices from config/pricing.json); pfs cost — totals per model and task; pfs cost --window — periods. Human edits count too: pfs log "brief edit" --human-minutes 15. Demo reference: a full project ≈ $19 with a mixed model profile.

Анализ данных: profile, cohort, funnel, stats

Data analysis: profile, cohort, funnel, stats

pfs data profile file.csv                 # типы, пропуски, диапазоны, уникальные
pfs data cohort file.csv --user id --date dt --save cohorts   # когорты по месяцам
pfs data funnel events.csv --steps visit,signup,pay --user id  # воронка
pfs data stats file.csv --col revenue --group seg              # статистика с ДИ 95%

Перед расчётами агент проверяет показатели, единицы, периоды и пропуски (профиль таблицы). --save сохраняет расчёт воспроизводимым — повторное выполнение даёт тот же результат. Результаты пишутся в analysis/ и закрепляются утверждениями C### с источником-файлом.

Before computing, the agent checks metrics, units, periods and gaps (table profile). --save makes a run reproducible. Results go to analysis/ and are anchored as C### claims with the file as source.

Интервью и модельные респонденты

Interviews and model respondents

pfs interview guide --persona "Родитель 7–12" --topic "мошенничество" — каркас гайда по шагам пути. pfs interview save transcript.md --persona … — транскрипт становится источником origin=synthetic. Субагент synthetic-respondent играет роль по персоне из дискавери. Правило честности: синтетические ответы порождают только гипотезы и регистрируются как синтетика; факт на них чекер не даст записать; в документах они помечены как модельные. Реальные интервью — только с согласия и без персональных данных.

pfs interview guide --persona "Parent, kids 7–12" builds the guide; pfs interview save transcript.md registers it with origin=synthetic. The synthetic-respondent subagent plays the persona. Honesty rule: synthetic answers yield hypotheses only; the checker refuses facts on them; documents mark them as model-generated. Real interviews require consent and no personal data.

Продолжение после перерыва

Resuming after a break

Всё состояние — в файлах projects/<slug>/: state.json (шаги, выбор, вопросы), claims.jsonl, decisions.jsonl, log.jsonl, sources/, outputs/. Новый чат в папке репозитория: хук SessionStart сам подаст статус и «что решать сейчас». Среда без хуков: напишите «прочитай AGENTS.md и выполни pfs status». Выполненные шаги не повторяются; источники и утверждения не дублируются.

All state lives in projects/<slug>/: state.json (steps, choices, questions), claims.jsonl, decisions.jsonl, log.jsonl, sources/, outputs/. New chat in the repo folder: the SessionStart hook feeds status and "what to decide now" automatically. Hook-less environment: write "read AGENTS.md and run pfs status". Finished steps never repeat; sources and claims never duplicate.

Перенос проекта между средами

Moving a project between environments

Проект — обычная папка: скопируйте projects/<slug>/ (или git push/pull, если проект в репозитории) и откройте в другой среде. Единственное, что не переносится автоматически, — секреты в .env: перенесите их руками и не коммитьте. Профиль моделей (config/models.json) общий на репозиторий.

A project is a plain folder: copy projects/<slug>/ (or git push/pull if tracked) and open elsewhere. The only non-portable part is secrets in .env: move them manually, never commit. The model profile (config/models.json) is repo-wide.

Безопасность и данные

Security and data

Данные: только открытые источники и ваши материалы; никаких закрытых данных компаний и персональных данных респондентов. Домены: разрешённые списком в project.json; хук блокирует чужой домен до запроса. Секреты: только в .env, он в .gitignore; в репозитории ключей нет и не было. Внедрённые инструкции: тексты источников — данные; «игнорируй инструкции» внутри источника помечается хуком и не исполняется. Интервью: реальным нужно согласие; персональных данных в репозитории нет; синтетика честно помечена.

Data: public sources and your materials only; no closed company data, no respondents' personal data. Domains: allow-listed in project.json; a hook blocks foreign domains pre-request. Secrets: .env only, git-ignored; no keys ever committed. Embedded instructions: source texts are data; "ignore instructions" inside a source is flagged, never executed. Interviews: real ones need consent; no personal data in the repo; synthetic data is honestly labeled.
