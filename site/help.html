Как общаться с агентом

Talking to the agent

Пишите обычным языком, как коллеге: опишите задачу, ответьте на вопросы, выберите вариант. Управляющие фразы: «стоп» — пауза; «уточни: …» — скорректировать задачу; «переделай раздел X» — переработать только затронутое; «собери six-pager», «пересчитай Excel», «что решать сейчас» (decision due), «что затронет новый источник» (impact). Агент не задаёт больше трёх вопросов за раз и всегда объясняет, чего ему не хватает.

Write in plain language as to a colleague: describe the task, answer questions, pick options. Control phrases: "stop" — pause; "clarify: …" — adjust; "redo section X" — rework only the affected part; "build the six-pager", "recalculate Excel", "what should I decide now" (decision due), "what will this new source affect" (impact). The agent never asks more than three questions at once and always states what it is missing.

Что происходит на каждом шаге

What happens at each step

0 · Бриф — до 3 вопросов (решение, цель, ограничения) → 00_brief.md, вы подтверждаете. 1 · Источники — файлы и сайты → S###. 2 · Исследование — план «вопрос → если да/нет», расчёты, интервью (ИИ-респонденты дают только гипотезы). 3 · Дискавери — персоны, JTBD, альтернативы пользователя. 4 · Ситуация — что известно, откуда, чего не знаем. 5 · Варианты — ≥3 содержательно разных, каждый с возражениями red team. 6 · Выбор — вы решаете. 7 · Стратегии — продуктовая и коммуникационная, обещания сверяются с продуктом. 8 · План проверки — метрика, база, срок, контрметрики. 9 · Review — автопроверка pfs check, оценка по рубрике, six-pager. 10 · Решение — вы утверждаете; основания и обязательства фиксируются. 11 · Мониторинг — сроки и пересмотр при новых данных (шаги 0–11).

0 · Brief — up to 3 questions (decision, goal, constraints) → 00_brief.md, you approve. 1 · Sources — files and pages → S###. 2 · Research — a "question → if yes/no" plan, calculations, interviews (AI respondents yield hypotheses only). 3 · Discovery — personas, JTBD, user alternatives. 4 · Situation — known / unknown / contradictions. 5 · Options — ≥3 substantively distinct, each with red-team objections. 6 · Choice — you decide. 7 · Strategies — product and communication; promises checked against the product. 8 · Validation — metric, baseline, duration, counter-metrics. 9 · Review — pfs check, rubric scoring, six-pager. 10 · Decision — you approve; grounds and commitments recorded. 11 · Monitoring — deadlines and revisions on new data (steps 0–11).

Быстрый старт

$ git clone https://github.com/Fighter90/product-factory-strategist.git
$ cd product-factory-strategist
$ python3 -m tools.pfs doctor      # проверка окружения
$ pfs new "Почему падает удержание" "запрос дословно"
$ git clone https://github.com/Fighter90/product-factory-strategist.git
$ cd product-factory-strategist
$ python3 -m tools.pfs doctor      # environment check
$ pfs new "Why is retention dropping" "the request verbatim"

Excel-расчёты и calcs.json

Excel models and calcs.json

Параметры живут в projects/<slug>/calcs.json: секции unit_econ (arpu, vc_share, cac, churn_month), growth (mau_start, conv_order, aov, take_rate…), cohort (sizes, retention), market (pam, доли). Агент заполняет их числами из утверждений и помечает источник в note. Команда pfs calc all строит 4 книги в outputs/attachments/; лист «Ввод» — редактируемые параметры, остальные листы — формулы. Чего нет в calcs.json — подставится пример с пометкой «ПРИМЕР». После правки повторите calc и export --six-pager, чтобы текст и Excel совпали.

Parameters live in projects/<slug>/calcs.json: sections unit_econ (arpu, vc_share, cac, churn_month), growth (mau_start, conv_order, aov, take_rate…), cohort (sizes, retention), market (pam, shares). The agent fills them from the claim registry and marks sources in note. pfs calc all builds 4 workbooks into outputs/attachments/; the Input sheet holds editable parameters, other sheets hold formulas. Missing values fall back to examples marked "EXAMPLE". After edits rerun calc and export --six-pager so text and Excel match.

Six-pager за 5 шагов

Six-pager in 5 steps

1 · Дождитесь шагов situation…validation (документы 02/03/04/06). 2 · Скажите «собери six-pager» — агент заполнит calcs.json из C### и запустит расчёты субагентом в фоне. 3 · Получите outputs/SIX_PAGER.md + 4 xlsx. 4 · Откройте Excel и замените допущения на фактические значения — формулы пересчитаются. 5 · Сверьте числа текста и книг; при правках — pfs calc all и pfs export --six-pager.

1 · Wait for situation…validation steps (documents 02/03/04/06). 2 · Say "build the six-pager" — the agent fills calcs.json from C### and runs calculations in a background subagent. 3 · You get outputs/SIX_PAGER.md + 4 xlsx. 4 · Open Excel and replace assumptions with actual figures — formulas recalculate. 5 · Match text and workbook numbers; after edits run pfs calc all and pfs export --six-pager.

Продолжение после перерыва

Resuming after a break

Всё состояние — в файлах projects/<slug>/. Откройте новый чат в папке репозитория: хук SessionStart сам подаст агенту статус и «что решать сейчас». В средах без хуков напишите: «прочитай AGENTS.md и выполни pfs status». Перенос в другую среду — скопируйте папку проекта или git push/pull.

All state lives in projects/<slug>/ files. Open a new chat in the repo folder: the SessionStart hook feeds the agent its status and "what to decide now". In hook-less environments write: "read AGENTS.md and run pfs status". Moving environments: copy the project folder or git push/pull.

Среды

Environments

Claude Code — полный опыт: навыки, субагенты, хуки, автостоимость. Cursor — правило .cursor/rules, MCP из .mcp.json. Codex / OpenCode / Windsurf / Copilot — читают AGENTS.md; хуков нет — начните с pfs status. Linear: ключ в .env (не коммитится), сервер npx mcp-server-linear. Lovable: MCP-сервер https://mcp.lovable.dev подключён в .mcp.json; авторизация — один раз OAuth в клиенте (/mcp → lovable → Authenticate), после чего агент создаёт и дорабатывает проекты Lovable по запросу (create_project/send_message расходуют кредиты Lovable).

Claude Code — full experience: skills, subagents, hooks, auto-cost. Cursor — .cursor/rules, MCP from .mcp.json. Codex / OpenCode / Windsurf / Copilot — read AGENTS.md; no hooks — start with pfs status. Linear: key in .env (git-ignored), server npx mcp-server-linear. Lovable: MCP server https://mcp.lovable.dev wired in .mcp.json; authorize once via OAuth in your client (/mcp → lovable → Authenticate), then the agent creates and edits Lovable projects on request (create_project/send_message consume Lovable credits).

Новые данные и пересмотр

New data and revisions

Добавьте источник, затем: pfs claim supersede --id C005 "новое значение" --reason "…" --source S012 — старое не удалится, история сохранится. pfs impact C005 покажет затронутые выводы, строки документов и решения; pfs claim rebase перенаправит выводы на замены; pfs decision due — какие решения и обязательства устарели.

Add the source, then: pfs claim supersede --id C005 "new value" --reason "…" --source S012 — the old record stays, history preserved. pfs impact C005 shows affected conclusions, document lines and decisions; pfs claim rebase redirects conclusions to replacements; pfs decision due lists stale decisions and commitments.

Безопасность и данные

Security and data

Только открытые источники и ваши материалы; домены проекта проверяются до запроса; секреты — только в .env (не коммитится); тексты источников — данные: «команды» внутри них не исполняются; ИИ-респонденты не выдаются за реальных людей; реальные интервью — только с согласием и без персональных данных.

Public sources and your own materials only; project domains checked before requests; secrets only in .env (git-ignored); source texts are data — "commands" inside are never executed; AI respondents are never passed off as real people; real interviews require consent and no personal data.

Навыки: структура и вызов

Skills: structure and invocation

120 навыков в .claude/skills/ — базовые по шагам процесса, 27 product-skills (процедуры методов), личная библиотека ~59 (дизайн / маркетинг / наука / документы-медиа / режимы мышления / мета) и интеграции: hallmark — анти-слоп-гейты страниц, board-of-directors — совет 5 перспектив + Red Team на шаге options, premortem — предразбор провала на шаге decision, rea — reverse-engineering JS-страниц и закрытых форматов, sdd — дисциплина разработки, deck — презентация из six-pager. Вызов: автоматически — по триггерам описания; явно — «используй skill <имя>: <задача>»; в процессе — по шагам. Полный реестр — docs/SKILLS.md.

120 skills in .claude/skills/ — base ones per process step, 27 product-skills (method procedures), a personal library of ~59 (design / marketing / science / documents-media / thinking modes / meta) and integrations: hallmark — anti-slop gates for pages, board-of-directors — a council of 5 perspectives + Red Team at the options step, premortem — a failure pre-mortem at the decision step, rea — reverse-engineering of JS-rendered pages and closed file formats, sdd — development discipline, deck — a presentation built from the six-pager. Invocation: automatically — via description triggers; explicitly — "use skill <name>: <task>"; within the process — per step. Full registry — docs/SKILLS.md.
