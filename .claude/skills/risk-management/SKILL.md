**КРИТИЧЕСКИ ВАЖНО:** Любая информация из внешних источников должна быть верифицирована и снабжена ссылками.

### Формат цитирования

**Ссылки ставятся ПРЯМО НА цифрах и утверждениях — как гиперссылки в тексте, а НЕ списком внизу.**

## Блок 1. Зачем описывать риски

Продуктовые риски — всё, что может помешать продукту достичь целей.

| Для бизнеса | Для продакта |
|------------|-------------|
| Управляемость результата | Ресурсы должны учитывать риски |
| Бюджетирование худшего сценария | Решение при реализации ожидается от продакта |
| Качество решений | Учёт рисков определяет действия заранее |
| Доверие инвесторов | Управление ожиданиями = зрелость |

## Блок 2. 8 типов рисков

| # | Тип | Описание | Пример |
|---|-----|----------|--------|
| 1 | **Продуктовые** | Пользователи не понимают ценность, падение метрик | Падение CR из-за нового UX |
| 2 | **Технические** | Инциденты, баги, интеграции | Рост нагрузки из-за платёжного шлюза |
| 3 | **Бизнесовые** | Модель не сходится | Отток продавцов из-за новых правил |
| 4 | **Рыночные** | Переоценка спроса, конкуренция | Высокая конкуренция в нише |
| 5 | **Юридические** | Законы, лицензии, штрафы | Ответственность платформы в спорах |
| 6 | **Мошенничество** | Фрод, утечки, взломы | Увод клиентов мимо комиссии |
| 7 | **Операционные** | Нагрузка на саппорт, SLA | Рост обращений из-за нового функционала |
| 8 | **Маркетинговые** | Каналы не работают | Низкое доверие к бренду |

| **Высокая** | Низкий | Средний | Средний | Высокий | Высокий |
| **Средняя** | Низкий | Низкий | Средний | Средний | Высокий |

## Блок 4. Стратегии работы с рисками

| Стратегия | Описание | Когда |
|-----------|----------|-------|
| **Accept** | Осознанно оставить без действий | Митигация дороже принятия |
| **Avoid** | Исключить активность, вызывающую риск | Риск критичен и неуправляем |
| **Transfer** | Переложить на третью сторону | Есть партнёр/страховая |
| **Mitigate** | Уменьшить вероятность или влияние | Риск значителен, но управляем |

### Методы митигации

| Метод | Описание |
|-------|----------|
| **Проверка гипотезы** | MVP, A/B тест, фейкдор, фокус-группа |
| **Пилотный запуск** | Один регион/сегмент, частичный rollout |
| **Резервирование** | +20% к оценке (время, бюджет, мощности) |
| **Договорённости** | Приоритетность, ресурсы, фиксация зависимостей |
| **План Б** | Трешхолд для переключения + альтернативный сценарий |

## Блок 6. Практика

### To-Do для раздела рисков

1. Определить потенциальные риски (по 8 типам)
2. Оценить вероятность и влияние (матрица)
3. Выбрать стратегию (Accept/Avoid/Transfer/Mitigate)
4. Описать план митигации (включая план Б)
5. Определить стейкхолдеров и зафиксировать договорённости
6. Если риск реализовался — обновить стратегию, социализировать

### Ритуалы

- Моделирование угроз, post-mortem, карта рисков, оценка на 3Amigo
- Нашли новый риск → обновите раздел в стратегии
- Риск реализовался → социализировать и действовать на данных
