# Масштабирование и коммуникация

## Обязательные правила работы с внешними данными

**КРИТИЧЕСКИ ВАЖНО:** Любая информация из внешних источников должна быть верифицирована и снабжена ссылками.

### Когда искать в интернете

Используй веб-поиск (WebSearch/WebFetch) **обязательно** в следующих случаях:
- Оценка размеров рынка (TAM/SAM/SOM) — ищи актуальные отчёты аналитических агентств
- Данные о конкурентах — выручка, доли рынка, количество пользователей
- Бенчмарки метрик — средние значения Retention, Conversion Rate, NPS для конкретной индустрии и типа продукта
- Статистика рынка — темпы роста, тренды, прогнозы
- Примеры реальных кейсов — как конкретные компании решали аналогичные задачи

### Как верифицировать данные

1. **Ищи первоисточники** — отчёты Statista, McKinsey, CB Insights, SimilarWeb, Crunchbase, а не пересказы в блогах
2. **Проверяй дату** — данные должны быть не старше 2 лет. Если свежих данных нет, укажи дату источника
3. **Сравнивай минимум 2 источника** для ключевых цифр (размер рынка, доли)
4. **Если данных нет** — честно напиши «данные не найдены в открытых источниках» и дай свою оценку с пометкой «экспертная оценка»

### Формат цитирования

**Ссылки ставятся ПРЯМО НА цифрах и утверждениях — как гиперссылки в тексте, а НЕ списком внизу.**

Правильно:
- «Компании с PMF растут в среднем на [20% MoM](https://example.com/pmf-study)»
- «[Только 12% продуктов](https://example.com/research) успешно масштабируются после первого года»

Неправильно:
- Текст без ссылок с пометкой «Источник: ...» без URL
- Просто список ссылок в конце документа без привязки к конкретным утверждениям

Каждое число, факт или заявление из внешнего источника = гиперссылка на этом числе/факте.

### Что искать для конкретного типа продукта

Перед анализом сделай поисковые запросы по шаблонам:
- `"[тип продукта] market size [год]"` — для TAM/SAM/SOM
- `"[тип продукта] benchmark metrics"` — для бенчмарков метрик
- `"[тип продукта] retention rate benchmark"` — для retention
- `"[тип продукта] conversion rate industry average"` — для конверсий
- `"[конкурент] revenue users funding"` — для данных о конкурентах

Этот навык помогает масштабировать продукт, достичь PMF, управлять портфелем и выстроить коммуникацию со стейкхолдерами.

## Блок 1. Масштабирование продукта

### Что такое масштабирование

Процесс увеличения масштабов бизнеса для обслуживания большего количества клиентов и операций **без пропорционального увеличения расходов**. Измеряется в терминах роста выручки, количества пользователей и инфраструктурной поддержки.

### Стратегии масштабирования

| Стратегия | Описание | Пример |
|-----------|---------|--------|
| **Географическое расширение** | Новые рынки и регионы | Запуск в новых городах/странах |
| **Выход на новые сегменты** | Новые типы пользователей / закрытие новых болей | B2B → B2C или наоборот |
| **Платформенные модели** | Экосистемы | Превращение продукта в платформу |

### 4 условия готовности к масштабированию

1. **Достигнут PMF** — чёткое понимание потребностей, подтверждённое метриками и обратной связью
2. **Подтверждённый спрос** — позитивная динамика на качественных и количественных данных ≥ 2 кварталов
3. **Юнит-экономика** — расчёт LTV и CAC, понимание, как выйти в плюс
4. **Готовность команды и инфраструктуры** — масштабируемая система, план развития ресурсов

### План масштабирования

- **Расширение каналов:** интеграция с новыми платформами, партнёрские программы
- **Масштабирование маркетинга:** увеличение бюджета, персонализация, таргетинг
- **Техническое масштабирование:** масштабируемая архитектура, облако, автоматизация
- **Расширение команды:** наём специалистов, укрепление культуры

### Метрики масштабирования

| Метрика | Что отслеживать |
|---------|----------------|
| **CAC** | Изменения в стоимости привлечения |
| **LTV** | Рост продолжительности и ценности клиента |
| **Retention Rate** | Способность удержания |
| **ROMI** | Рентабельность маркетинговых инвестиций |
| **NPS / CSAT** | Лояльность и удовлетворённость |
| **Contact Rate** | Доля обращений в поддержку |
| **Доля платящих** | Изменение конверсии в оплату |

### 4 красных флага преждевременного масштабирования

1. **Отсутствие роста** — продажи и пользователи не увеличиваются
2. **CAC растёт выше LTV** — экономика не сходится
3. **Падение retention** — рост оттока клиентов
4. **Команда не справляется** — организационная несостоятельность

### 2 типичные ошибки

1. Запуск масштабирования без подтверждённого PMF
2. Недооценка затрат на маркетинг и техническую поддержку

## Блок 2. Достижение PMF (Product-Market Fit)

### 7 критериев PMF

1. **Обратная связь** — отзывы, NPS показывают удовлетворённость
2. **Метрики использования** — Retention Rate, DAU/MAU стабильны или растут
3. **Финансовые показатели** — стабильный рост выручки, положительная юнит-экономика
4. **Рыночная динамика** — рынок тянет продукт, высокая скорость продаж
5. **Процент удовлетворённости** — опросы клиентов подтверждают ценность
6. **Показатели роста** — вирусный эффект, органический рост
7. **Качественные факторы** — комбинация количественных данных с качественными исследованиями

**Важно:** PMF можно утратить. Условия рынка меняются, продукт должен адаптироваться.

**Исключение:** инновационные продукты можно масштабировать без достижения PMF, если занимаешся инновациями.

## Блок 3. Продуктовый портфель (модель Авито)

### 6 типов инициатив

| Тип | Описание |
|-----|---------|
| **New Big Bet** | Высокий риск, потенциал 1 млрд доп. выручки или снижения затрат на 5-й год |
| **Business as Usual** | Поддержка органического развития, низкий риск |
| **Продукт** | Целостный функционал, закрывающий новую потребность |
| **Стрим** | Ряд взаимосвязанных небольших инициатив (совокупность мини-продуктов) |
| **Энейблер** | «Фундамент» для других продуктов, сам не продукт |
| **Прочее** | Непродуктовые инициативы (тех.проекты, внутренние инструменты) |

### Этапы создания продукта

| Этап | Цель | Ключевые outputs | Критерий перехода |
|------|------|-----------------|-------------------|
| **New Idea** | Выбрать идею | Идея выбрана, определён фронтмен, даты | Начаты работы Discovery |
| **Opportunity Discovery** | Обосновать идею | Потребности, трекшн на 3 года, способы проверки | Пройден Gate 1 |
| **Solution Discovery** | Обосновать решение | Проверены гипотезы, определён MLP, пройден TDR | Пройден Gate 2 |
| **Development** | Вывести MLP, достичь PMF | Запущен MLP, достигнут PMF, маркетинг-план | Пройден Gate 3 |
| **Scaling** | Достичь целей | Цели достигнуты, решение о будущем | Пройден Gate 4 |
| **Baseline** | Поддержка | Живёт / пивот / закрывается | Продукт закрыт |

### Traction-диаграмма (TTM)

- **Touch time:** New → Kickoff
- **Discovery TTM:** Kickoff → Gate 2 (~4–5 мес)
- **T2PMF:** Kickoff → Gate 3 (~10 мес)
- **T2Scale:** Kickoff → Gate 4 (1+ год)

TTM включает «полезные» (активная работа, эксперименты) и «неполезные» (ожидание, нехватка ресурсов) фрагменты.

## Блок 4. MECE-структуризация

### Принцип MECE

**MECE** (Mutually Exclusive, Collectively Exhaustive) — «взаимно исключающее, совместно исчерпывающее».

Принцип позволяет:
- **Всё объять и структурировать** — не упустить решения и не дублировать
- **Фокусировать и аргументировать** — найти критичные точки, прозрачно донести решение

Смысл: «нарезать» общую задачу на части так, чтобы каждая была уникальной и вместе они покрывали всё пространство решений.

## Блок 5. Коммуникация со стейкхолдерами

### 10 типов стейкхолдеров

| Тип | Как работать |
|-----|-------------|
| **Согласующие** | Вовлекать в процесс, давать право голоса |
| **Тревожные** | Снимать неопределённость, давать факты и данные |
| **Доминирующие** | Управлять ожиданиями, ставить рамки |
| **Требующие** | Фиксировать требования, приоритизировать |
| **Пофигистичные** | Минимально информировать, не перегружать |
| **Инициаторы** | Канализировать энергию, направлять в нужное русло |
| **Эксперты-молчуны** | Активно запрашивать мнение, создавать пространство для высказывания |
| **Политики** | Учитывать интересы, искать win-win |
| **Оптимисты** | Заземлять ожидания, просить обосновать |
| **Скептики** | Давать данные, привлекать к обсуждению рисков |

### Каналы коммуникации

- Чаты (оперативная связь)
- Встречи (глубокое обсуждение)
- Отчёты (фиксация результатов)
- Внутренние рассылки (информирование)

## Блок 6. Защита продукта

### Майлстоуны до защиты

1. Начинай подготовку с предыдущей защиты
2. Заранее бронируй дату, не зови всех подряд
3. Перманентно погружай команду в решения
4. Согласуй решения с ключевыми функциями по ходу квартала
5. Проведи 2–3 вычитки с расширением круга
6. До защиты обсуди спорные моменты с критичными участниками

### Советы по документам

- Обозначь цель документа и дай вводную
- Не пиши о том, в чём не уверен
- Давай ответы, а не задавай вопросы
- Делись результатами, а не процессами
- Будь конкретным, объясни почему именно это
- Убирай лишнее, проверяй что не потерялся смысл

### Чек-лист самовычитки

- Пиши на простом языке, сокращай предложения
- Одна идея — одно предложение
- Подкрепляй утверждения цифрами

5 вопросов к каждому предложению:
1. Почему я об этом пишу? Актуально ли?
2. Что упущу, если удалю?
3. Достаточно ли деталей?
4. Какой вывод можно сделать?
5. Поясняет ли предыдущее? Если да — предыдущего достаточно?

> **Хороший документ не тот, в который нечего добавить, а тот, из которого нечего убрать.**

## Блок 7. Трекшн-модель

### Принципы

- Основывайся на данных из LTM (самый достоверный долгосрочный прогноз)
- Выдели несколько ключевых input-метрик и покажи связь с output-метриками
- Из трекшна должно быть понятно, за счёт каких драйверов будет достигнут результат

### Что показывать

- Ключевые аутпуты и ауткамы (не весь беклог, только результаты, приближающие к трекшну)
- Какие новые гипотезы будем проверять
- Когда следующий review и какие критерии успеха

## Выходной артефакт

На выходе пользователь получает:
1. **Диагностика готовности** — по 4 условиям масштабирования
2. **Оценка PMF** — по 7 критериям
3. **Классификация инициативы** — тип в портфеле, текущий gate
4. **Карта стейкхолдеров** — типы + стратегия коммуникации
5. **Защитный документ** — проверенный по чек-листу
6. **Трекшн-модель** — связь input/output метрик
