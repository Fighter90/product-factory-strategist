# Метрики и аналитика продукта

## Обязательные правила работы с внешними данными

**КРИТИЧЕСКИ ВАЖНО:** Любая информация из внешних источников должна быть верифицирована и снабжена ссылками.

### Когда искать в интернете

Используй веб-поиск (WebSearch/WebFetch) **обязательно** в следующих случаях:
- Бенчмарки метрик — средние значения Retention, Conversion Rate, NPS для конкретной индустрии и типа продукта
- Примеры NSM реальных компаний — актуальные данные о North Star Metrics
- Кейсы построения деревьев метрик — как конкретные компании структурируют аналитику
- Статистика по воронкам — типичные конверсии по этапам для разных типов продуктов

### Как верифицировать данные

1. **Ищи первоисточники** — отчёты Statista, McKinsey, CB Insights, SimilarWeb, Crunchbase, а не пересказы в блогах
2. **Проверяй дату** — данные должны быть не старше 2 лет. Если свежих данных нет, укажи дату источника
3. **Сравнивай минимум 2 источника** для ключевых цифр
4. **Если данных нет** — честно напиши «данные не найдены в открытых источниках» и дай свою оценку с пометкой «экспертная оценка»

### Формат цитирования

**Ссылки ставятся ПРЯМО НА цифрах и утверждениях — как гиперссылки в тексте, а НЕ списком внизу.**

Правильно:
- «Средний D30 Retention для EdTech приложений — [25%](https://example.com/benchmark)»
- «Spotify использует [Time Spent Listening](https://example.com/spotify-nsm) как свою NSM»

Неправильно:
- Текст без ссылок с пометкой «Источник: ...» без URL
- Просто список ссылок в конце документа без привязки к конкретным утверждениям

Каждое число, факт или заявление из внешнего источника = гиперссылка на этом числе/факте.

### Что искать для конкретного типа продукта

Перед анализом сделай поисковые запросы по шаблонам:
- `"[тип продукта] benchmark metrics"` — для бенчмарков метрик
- `"[тип продукта] retention rate benchmark"` — для retention
- `"[тип продукта] conversion rate industry average"` — для конверсий
- `"[компания] north star metric"` — для примеров NSM

Этот навык помогает выбрать правильные метрики, построить их в систему и связать с бизнес-целями.

## Блок 1. Классификация метрик

### Продуктовые метрики

Оценивают вовлечённость, качество и пользу для пользователя.

| Метрика | Что показывает | Стадия |
|---------|---------------|--------|
| DAU / MAU | Активность пользователей | Growth / Scale |
| Retention (D1, D7, D30) | Возвращаемость — есть ли реальная ценность | MVP → Growth |
| Stickiness (DAU/MAU) | Привычность и частота использования | Growth |
| Activation rate | Понимает ли пользователь ценность | MVP |
| Task Success Rate | Удаётся ли решить свою задачу | Discovery / MVP |
| NPS / CSAT | Удовлетворённость и лояльность | Growth / Maintenance |

### Бизнес-метрики

Оценивают деньги, рост, экономику.

| Метрика | Что показывает | Стадия |
|---------|---------------|--------|
| Выручка / GMV | Масштаб бизнеса | Scale |
| LTV (Lifetime Value) | Пожизненная ценность клиента | Growth / Scale |
| CAC (Customer Acquisition Cost) | Стоимость привлечения | Growth / Scale |
| LTV / CAC | Устойчивость экономики (должно быть > 3) | Growth / Scale |
| ARPU / ARPPU | Средний доход на пользователя | Scale |
| Churn Rate | Проблемы с удержанием | Growth / Maintenance |
| ROMI | Эффективность маркетинга | Growth |

### Операционные метрики

| Метрика | Что показывает | Стадия |
|---------|---------------|--------|
| Скорость роста базы | Есть ли приток | Growth |
| Источник трафика / % органики | Зависимость от платного канала | MVP / Growth |
| Количество багов / скорость релизов | Зрелость разработки | MVP / Maintenance |

## Блок 2. North Star Metric (NSM)

NSM — это главная метрика продукта, отражающая ценность для пользователя и долгосрочный рост. Она должна быть одна и вести за собой все остальные метрики. NSM — стратегический ориентир, а не операционная метрика.

### 8 вопросов для определения NSM

Проверь кандидата на NSM по каждому критерию:

| # | Вопрос | Пояснение |
|---|--------|-----------|
| 1 | **Отражает ценность для пользователя?** | NSM должна показывать момент получения ценности, а не бизнес-результат |
| 2 | **Коррелирует с долгосрочным ростом?** | Если NSM растёт — бизнес растёт в перспективе |
| 3 | **Можно ли влиять на неё продуктом?** | Команда должна иметь рычаги воздействия |
| 4 | **Понятна ли всей команде?** | Одно число, которое все понимают одинаково |
| 5 | **Измерима ли регулярно?** | Можно считать ежедневно/еженедельно |
| 6 | **Ведёт ли за собой другие метрики?** | Рост NSM должен тянуть за собой revenue, retention и др. |
| 7 | **Не является ли vanity metric?** | Не MAU ради MAU, а отражение реального поведения |
| 8 | **Масштабируется ли с бизнесом?** | При росте бизнеса NSM тоже должна расти |

### Примеры NSM реальных компаний

| Компания | NSM | Почему именно она |
|----------|-----|-------------------|
| **Facebook** | Daily Active Users (DAU) | Отражает вовлечённость в социальную сеть |
| **Spotify** | Time Spent Listening | Показывает реальное потребление ценности |
| **Amazon** | Количество покупок в месяц | Отражает повторное использование и доверие |
| **Airbnb** | Забронированные ночи | Ценность для обеих сторон маркетплейса |
| **WhatsApp** | Количество отправленных сообщений | Показывает использование основной функции |
| **Netflix** | Часы просмотра контента | Вовлечённость и ценность подписки |
| **Slack** | Messages sent within an org | Показывает adoption внутри организации |
| **Uber** | Количество поездок в неделю | Отражает привычку и ценность транспорта |

### Примеры NSM по типам продуктов

| Тип продукта | NSM | Почему |
|-------------|-----|--------|
| Маркетплейс | Количество завершённых сделок | Отражает ценность для обеих сторон |
| SaaS | Количество активных пользователей в неделю | Показывает реальное использование |
| Контент-платформа | Время просмотра контента | Отражает вовлечённость |
| E-commerce | Количество повторных покупок | Показывает лояльность и ценность |
| EdTech | Количество завершённых уроков | Отражает прогресс пользователя |
| FinTech | Количество транзакций | Отражает доверие и полезность |

## Блок 3. Пирамида метрик (4 уровня)

Пирамида метрик — структура, показывающая как действия команды влияют на стратегические цели. Продуктовая команда управляет системой **снизу вверх**: через input и output, влияя на outcome, а в долгосрочной перспективе — на NSM.

### 4 уровня пирамиды

```
NSM (North Star Metric) — стратегический ориентир
    ↑
Outcome metrics — метрики результата периода (квартал/полугодие)
    ↑
Output metrics — промежуточные продуктовые результаты
    ↑
Input metrics — метрики, на которые команда влияет напрямую
```

### Описание уровней

| Уровень | Описание | Горизонт | Примеры |
|---------|----------|----------|---------|
| **NSM** | Главная метрика продукта, отражающая ценность для пользователя | Стратегический | Завершённые заказы, время использования |
| **Outcome** | Метрики результата, напрямую отражающие изменение ключевой ценности. Формулируются как цели периода | Квартал / полугодие | Количество сделок, активные платящие, Retention |
| **Output** | Промежуточные результаты, влияющие на outcome | Спринт / месяц | Конверсия в покупку, доля повторных заказов, скорость ответа |
| **Input** | Метрики, на которые команда влияет напрямую | Ежедневно / еженедельно | Конверсия шага, adoption функции, количество пушей |

### Пример пирамиды: маркетплейс услуг

- **NSM:** завершённые заказы (стратегический ориентир)
- **Outcome (цель квартала):** рост числа завершённых заказов на 20%
- **Output:** рост конверсии в заказ, доля повторных заказов
- **Input:** конверсия активации, скорость ответа исполнителя, заполнение профиля

### Пример пирамиды: LLM-ассистент в чатах

- **Outcome:** Revenue, Daily target buyers
- **Output:** CR to target chat, Share of answers in 1 hour
- **Input:** Share of answered first messages with Assistant

### Пример пирамиды: SaaS-продукт

- **NSM:** Weekly Active Users
- **Outcome (цель квартала):** рост WAU на 30%
- **Output:** Activation rate, D7 Retention
- **Input:** % прошедших онбординг, время до первого результата, конверсия приглашения коллег

### Как использовать пирамиду

1. Определи NSM
2. Выбери 1–2 outcome-метрики на период (квартал)
3. Разложи на output-метрики (что нужно изменить)
4. Найди input-метрики (на что можно влиять напрямую)
5. Для каждой input-метрики — определи инициативы и эксперименты

## Блок 4. Дерево метрик (Metrics Tree)

Дерево метрик — это структура, показывающая, как локальные действия влияют на основные метрики.

### Подход 1: От денег (Revenue Tree)

```
Выручка
├── Количество пользователей
│   ├── Новые пользователи (Acquisition)
│   │   ├── Трафик
│   │   └── Конверсия в регистрацию
│   └── Возвращающиеся (Retention)
│       ├── Retention D7
│       └── Retention D30
├── Конверсия в оплату
│   ├── Activation rate
│   └── Конверсия воронки
└── Средний чек (ARPU)
    ├── Частота покупок
    └── AOV (средний чек заказа)
```

### Подход 2: От NSM

```
NSM (например, завершённые сделки)
├── Input-метрика 1: Количество просмотров объявлений
│   ├── Трафик
│   └── Качество выдачи
├── Input-метрика 2: Конверсия просмотр → контакт
│   ├── Качество контента
│   └── Цена
└── Input-метрика 3: Конверсия контакт → сделка
    ├── Удобство коммуникации
    └── Доверие к продавцу
```

### Как строить дерево

1. Определи NSM или ключевую output-метрику
2. Разложи на составляющие (input-метрики)
3. Для каждой input-метрики определи драйверы
4. Проверь: если изменить любой драйвер — изменится ли output?
5. Свяжи с конкретными продуктовыми действиями

## Блок 5. AARRR (Pirate Metrics)

Фреймворк для структурирования аналитики воронки:

| Этап | Что измеряем | Ключевые метрики |
|------|-------------|-----------------|
| **Acquisition** (привлечение) | Откуда приходят пользователи | Трафик, CAC, источники |
| **Activation** (активация) | Получил ли пользователь первую ценность | Activation rate, Time to Value |
| **Retention** (удержание) | Возвращается ли пользователь | Retention D1/D7/D30, Churn |
| **Revenue** (монетизация) | Платит ли пользователь | ARPU, LTV, конверсия в оплату |
| **Referral** (рекомендации) | Приводит ли новых пользователей | NPS, вирусный коэффициент, реферальный трафик |

### Когортный анализ

Когортный анализ — это разбивка пользователей по группам (когортам), обычно по дате регистрации, и отслеживание их поведения во времени.

Зачем:
- Увидеть реальный retention без искажения новыми пользователями
- Сравнить когорты до и после изменений
- Оценить долгосрочную ценность разных сегментов

## Блок 7. Контр-метрики

Контр-метрика — это метрика, которая показывает, не ломаем ли мы что-то другое, улучшая целевую метрику.

**Примеры:**
- Растим конверсию → смотрим, не падает ли retention
- Увеличиваем частоту push-уведомлений → смотрим, не растёт ли отписка
- Снижаем цену → смотрим, не падает ли маржа

**Правило:** для каждого эксперимента определи минимум 1 контр-метрику.

## Выходной артефакт

На выходе пользователь получает:
1. **Набор метрик** — классифицированный по типам, привязанный к стадии
2. **NSM** — с обоснованием выбора (проверка по 8 вопросам)
3. **Пирамида метрик** — NSM → Outcome → Output → Input
4. **Дерево метрик** — от NSM или от выручки к input-метрикам
5. **Контр-метрики** — для каждого ключевого направления
