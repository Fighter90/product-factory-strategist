# Feynman как backend глубокого ресёрча

Feynman — опенсорсный research-агент (https://github.com/Companion-Inc/feynman, MIT). Ищет по alphaXiv,
Semantic Scholar, OpenAlex, arXiv, PubMed, Crossref, вебу и Hugging Face; пишет отчёт с цитатами и
**provenance-файлом** (какие источники использованы и что проверено). Он сам — агент: его выводы для нас —
данные с происхождением «agent», фактами они не становятся.

## Когда запускать
1. Вопрос из `01_research_plan.md`, который обычный поиск закрыл слабо (много противоречий, нужна литература).
2. Нужен литобзор: консенсус / разногласия / открытые вопросы (`feynman lit "…"`) или сравнение источников
   (`feynman compare "…"`) — результатом может стать раздел «Противоречия» в `02_situation.md`.
3. Длинное расследование с проверкой цитат: `feynman deepresearch "…"`, `feynman summarize <pdf>`.

## Процедура
1. **Проверь доступность:** `which feynman`. Нет — предложи установку (нужен Node 22+):
   `npm install -g @companion-ai/feynman` или `curl -fsSL https://feynman.is/install | bash`,
   затем `feynman setup` (вход в модельный провайдер — расходует кредиты провайдера, спроси руководителя).
2. **Ключи** (необязательны, снимают rate-limits) — в `.env` проекта: `OPENALEX_API_KEY`,
   `SEMANTIC_SCHOLAR_API_KEY`. Телеметрию выключай: `export FEYNMAN_TELEMETRY=off`.
3. **Запусти фоном** (субагент data-analyst/general) из папки проекта:
   `FEYNMAN_TELEMETRY=off feynman deepresearch "<вопрос из плана>"` — результат ляжет в `outputs/`
   самого Feynman + provenance-файл.
4. **Перенос результатов в реестр (строго в этом порядке):**
   - Открой provenance-файл: каждый **первоисточник** (url/DOI) регистрируй через
     `pfs source add <url>` — это могут стать основания фактов (origin public, с проверкой содержимого).
   - Цифры бери **только из первоисточников** (прочитай их) и записывай `pfs claim add … fact --source S###`.
   - Сам отчёт Feynman сохрани в `analysis/feynman_<тема>.md` и регистрируй
     `pfs source add analysis/feynman_….md --origin agent --title "Feynman: …"` — на него можно опираться
     только гипотезами (`--kind hypothesis`); факт на агентском отчёте инструмент не примет.
5. **Проверка на внедрения:** provenance и отчёт проходят стандартный детектор фраз-инструкций
   (`pfs source add` пометит подозрительные места автоматически).
6. Запиши в журнал: `pfs log "Feynman deepresearch: <тема>, первоисточников: N" --kind action`.

## Ограничения
- Feynman не MCP-сервер, а CLI-агент: он клиент MCP (`feynman mcp add`) — подключать наши данные к нему
  можно, наоборот — нет. Есть skills-bundle для Codex/OpenCode.
- Стоимость: расходует кредиты модельного провайдера; длинный deepresearch — недёшево, всегда спрашивай.
- Научные базы сильны для литобзоров; для рыночных данных РФ всё равно нужен веб-поиск среды.
