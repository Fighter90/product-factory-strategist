## Что такое юнит-экономика

Юнит-экономика — оценка прибыльности бизнеса в расчёте на одну базовую единицу, генерирующую доход, через сравнение доходов и расходов на неё. Цель — понять, приносит ли каждая отдельная «продажа» прибыль.

**Юнит** — это базовая единица: заказ, товар, сделка, событие, клиент, поездка и т.д.

### Зачем считать юнит-экономику

- **Оценить целесообразность масштабирования** — если юнит убыточен, масштабирование только увеличит убытки
- **Проверить устойчивость бизнес-модели** — сходится ли экономика на единице
- **Принимать решения о развитии** — приоритизировать гипотезы на основе влияния на UE
- **Корректировать ценообразование** — понять дельту между ценой и себестоимостью
- **Управлять затратами** — увидеть, где деньги утекают

### Базовая формула

```
UE = (Доход с юнита − Себестоимость юнита) × Кол-во периодов жизни − CAC
```

Где:
- Доход с юнита = ARPU или Revenue per Order
- Себестоимость = переменные затраты на единицу (variable costs)
- Периоды жизни = lifetime
- CAC = стоимость привлечения пользователя

**Положительная юнит-экономика ещё не означает, что продукт прибылен в целом** — она не учитывает непрямые и постоянные затраты. Но если UE отрицательная, продукт точно убыточен.

### Как улучшать юнит-экономику

Четыре рычага:
1. **Повышать средний чек** — upsell, кросс-продажи, премиум-тарифы
2. **Снижать себестоимость** — оптимизация операций, автоматизация
3. **Увеличивать число покупок на клиента** — retention, повторные покупки, привычка
4. **Развивать эффективные каналы привлечения** — снижение CAC, органический рост

## Блок 1. Главное правило: LTV > CAC

Юнит-экономика сходится, когда LTV > CAC.

```
UE = LTV − CAC
```

- **LTV (Lifetime Value)** — сколько денег приносит пользователь за всё время
- **CAC (Customer Acquisition Cost)** — сколько стоит привлечение одного пользователя

Юнит-экономику правильно считать с учётом когорт — разные когорты ведут себя по-разному.

---

## Блок 2. Семь методов расчёта LTV

Выбор метода зависит от типа бизнеса, доступных данных и модели монетизации. Ниже — каждый метод с формулой, условиями применения и типичными продуктами.

### Метод 1. Классический расчёт LTV

```
LTV = ARPU × Lifetime × GM%
```

- **ARPU** — средний доход на пользователя за период
- **Lifetime** — срок жизни клиента (в месяцах или периодах)
- **GM%** — маржа первого уровня (GM1 / Revenue): прибыль после вычета переменных затрат, но до учёта фиксированных расходов

```
UE = (ARPU × Lifetime × GM%) − CAC
```

**Когда подходит:**
- Подписочная модель со стабильным ARPU
- Предсказуемый отток → легко считать Lifetime
- Стабильная маржинальность
- Нет значимых переменных затрат на каждый юнит

**Типичные продукты:** SaaS-подписки (Notion, Miro), стриминг (IVI, Кинопоиск), фитнес-приложения

---

### Метод 2. LTV через Retention и когорты

```
LTV = Σ (ARPU_t × GM% × Retention_t)
```

LTV = сумма за все периоды жизни клиента, где:
- **ARPU_t** — доход от пользователя в период t
- **Retention_t** — доля пользователей, доживших до периода t

```
UE = LTV − CAC
```

**Когда подходит:**
- Есть хорошие когортные данные
- ARPU и маржа меняются по месяцам
- Retention «проседает» неоднородно (не плавная кривая)
- Классическая модель даёт искажения

**Типичные продукты:** мобильные игры, e-commerce с непредсказуемым поведением, EdTech

---

### Метод 3. LTV через отток (Churn)

```
Lifetime = 1 / Churn Rate
LTV = ARPU × (1 / Churn) × GM%
```

- **Churn Rate** — доля пользователей, прекративших использование за период

```
UE = ARPU × (1 / Churn) × GM% − CAC
```

**Когда подходит:**
- Стабильный ARPU
- Ровный GM%
- Предсказуемый churn
- Долгий retention-tail (кривая удержания выходит на плато)

**Типичные продукты:** телеком-операторы, банковские продукты, B2B SaaS со стабильной базой

---

### Метод 4. LTV на основе гросс-маржи на заказ

```
GM1_per_order = Revenue_per_order − Variable_cost_per_order
LTV = GM1_per_order × Orders_per_user × Lifetime
```

- **Revenue_per_order** — выручка с одного заказа
- **Variable_cost_per_order** — переменные затраты на исполнение (упаковка, доставка и т.д.)

```
UE = GM1_per_order × Orders_per_user × Lifetime − CAC
```

**Когда подходит:**
- Высокая доля переменных расходов на каждый заказ
- Важно оценивать реальную прибыль, а не просто доход
- Логистически нагруженные бизнесы

**Типичные продукты:** e-grocery (Самокат, Яндекс Лавка), доставка еды, DTC-бренды

---

### Метод 5. LTV через ARPPU (выручка с платящего)

```
ARPPU = Revenue / Paying Users
Conversion_to_paid = Paying Users / All Users
ARPU = ARPPU × Conversion_to_paid
LTV = ARPU × Lifetime × GM%
```

```
UE = LTV − CAC
```

**Когда подходит:**
- Маленькая доля платящих (freemium-модель)
- Подписочный сервис с фиксированной суммой
- Важна окупаемость маркетинга и планирование CAC

**Типичные продукты:** Telegram Premium, VK Музыка, мобильные игры с IAP, Duolingo

---

### Метод 6. LTV через GMV

```
GMV_per_user = GMV / Active Users
Commission% = Revenue / GMV
Revenue_per_user = GMV_per_user × Commission%
GM1_per_user = Revenue_per_user − Variable_costs_per_user
LTV = GM1_per_user × Lifetime
```

- **GMV** — валовая стоимость товаров/услуг, проданных через платформу
- **Commission%** — стоимость услуг платформы за транзакцию

```
UE = LTV − CAC
```

**Когда подходит:**
- Маркетплейсы и платформы с комиссионной моделью
- Доход = процент от GMV
- Freemium-модели с маленькой долей платящих

**Типичные продукты:** Авито, Ozon Marketplace, Airbnb, Uber

---

### Метод 7. LTV через «средний чек × частоту»

```
ARPU = AOV × F
LTV = (AOV × F × Lifetime) × GM%
```

- **AOV** — средний чек (Average Order Value)
- **F** — число транзакций на пользователя за период

```
UE = (AOV × F × Lifetime × GM%) − CAC
```

**Когда подходит:**
- Транзакционные модели с повторными покупками
- Важно управлять и чеком, и частотой отдельно
- Есть данные по обоим параметрам

**Типичные продукты:** e-commerce (Wildberries, Ozon), food delivery, ритейл, маркетплейсы услуг

## Блок 3. Как выбрать метод расчёта

Выбор метода определяется тремя факторами: тип монетизации, доступные данные и что именно нужно оптимизировать.

### Матрица выбора

| Если у вас... | Используйте метод |
|---------------|-------------------|
| Подписка, стабильный ARPU, предсказуемый churn | **Метод 1** (классический) или **Метод 3** (через churn) |
| Когортные данные, ARPU меняется по месяцам | **Метод 2** (через retention и когорты) |
| Высокие переменные затраты на заказ (логистика) | **Метод 4** (гросс-маржа на заказ) |
| Freemium, маленькая доля платящих | **Метод 5** (через ARPPU) |
| Маркетплейс, доход = комиссия от GMV | **Метод 6** (через GMV) |
| E-commerce, повторные покупки, нужно управлять чеком и частотой | **Метод 7** (AOV × частота) |

### Практические рекомендации

**Начинайте с простого.** Если у вас подписка — метод 1 или 3. Усложняйте только если простой метод даёт явные искажения.

**Считайте по когортам.** Какой бы метод вы ни выбрали, правильный расчёт — когортный. Усреднение по всей базе скрывает реальную картину: ранние когорты могут быть прибыльными, а новые — убыточными.

**Сравнивайте методы.** Если два метода дают сильно разные LTV — это сигнал, что один из них неточен. Разберитесь почему.

## Блок 4. Практический пример: CPA-модель

Пример расчёта юнит-экономики для сервиса «на все руки ассистент» (чатбот с вызовом мастеров):

**Модель монетизации:** CPA (мастер платит за запись клиента)

```
CPA = AVO × TR × CRap
```
- AVO (Average Value of Order) — средний чек заказа
- TR (Take Rate) — комиссия платформы
- CRap (Conversion Rate, action to payment) — конверсия из записи в оплату

```
Revenue = 365 × DAU × OrderRate × CPA
clientLTV = LifetimeSessions × OrderRate × CPA
```

**Расчёт Lifetime Sessions:**
```
LifetimeSessions ≈ (1 + MRR + MRR² + MRR³ + …) × Stickiness
```
- MRR = Monthly Retention Rate (доля вернувшихся из месяца X в месяц X+1)
- Stickiness = MAU / DAU

**Точки сверки:**
1. Сравниваем Revenue и Expenses — прибылен ли бизнес в целом
2. Сравниваем clientLTV и CAC — окупается ли привлечение

## Выходной артефакт

При расчёте юнит-экономики результат включает:

1. **Определение юнита** — что именно является базовой единицей
2. **Выбор метода расчёта LTV** — с обоснованием, почему именно этот
3. **Расчёт LTV** — с формулами и подставленными значениями
4. **Расчёт CAC** — по каналам привлечения, если есть данные
5. **UE = LTV − CAC** — итоговая оценка сходимости
6. **Когортная разбивка** — если есть данные по когортам
7. **Рекомендации по улучшению** — какие рычаги дадут наибольший эффект
